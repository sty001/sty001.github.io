## 命令的分类与识别

Linux 中的一条命令可以是四种身份之一：shell 内部命令（内建）、外部命令、别名、shell 函数。区分它们用 `type` 命令。

### 四种命令类型

| 类型 | 说明 | 常见例子 |
| --- | --- | --- |
| shell 内部命令（builtin） | 由 shell 自身实现，随 shell 启动加载，磁盘上没有对应的可执行文件 | `cd`、`echo`、`pwd`、`exit`、`alias`、`umask`、`export`、`source`、`type`、`read`、`test`/`[`、`jobs`、`fg`/`bg`、`history` |
| 外部命令 | 磁盘上的可执行文件，位于 `/bin`、`/usr/bin`、`/sbin` 等 PATH 目录中 | `ls`、`cp`、`mv`、`rm`、`cat`、`grep`、`find`、`tar` |
| 别名（alias） | 给一条命令起的绰号，shell 会先把它展开成原命令再执行 | `ll`、`rm`（CentOS 默认 `rm -i`） |
| 函数（function） | 用户自定义的一段 shell 代码，可以像命令一样调用 | 自定义的 `mkcd` 等 |

用 `type` 区分四种身份：

```bash
[root@web01 ~]# type cd
cd is a shell builtin
[root@web01 ~]# type rm
rm is aliased to `rm -i'
[root@web01 ~]# type grep
grep is /usr/bin/grep
[root@web01 ~]# type -a grep          # -a 显示所有匹配（含 PATH 中的其他副本）
grep is /usr/bin/grep
grep is /bin/grep
[root@web01 ~]# type -t rm             # -t 只输出类型关键字
alias
```

区分命令身份有实际意义：

1. 内建命令没有创建进程的开销，执行更快；
2. `which` 只能查外部命令（它只看 PATH 里的可执行文件），所以 `which cd` 没有任何输出；
3. 自己定义的函数和别名会"遮蔽"同名外部命令，排错时如果命令行为不符合预期，先用 `type` 确认它到底是什么；
4. 少数命令两种身份并存（如 `pwd`、`kill`、`test`），`type` 会同时给出两条结果。

上面示例里还有个细节：`type cat` 输出的是 `cat is hashed (/usr/bin/cat)`。说白了，bash 为了省去每次翻 PATH 的开销，第一次找到外部命令后会把路径缓存进一张哈希表，之后直接走缓存。这个缓存偶尔会坑人——命令挪了位置或升级了版本，shell 还在用旧路径，敲 `hash -r`（或 `hash -d 命令名`）清掉即可。实际敲一遍就明白：先执行一次 `cat`，再 `type cat`，输出里就会多出 hashed 字样。

### 原理解析：shell 如何执行一条命令 {: .sec-know}

1. 读取用户输入的命令行，先做别名展开和变量替换；
2. 检查命令名是否为 shell 内建命令或函数，是则直接由当前 shell 进程执行（不创建新进程）；
3. 如果是外部命令，shell 在 PATH 环境变量列出的目录中按顺序查找同名可执行文件；
4. 找到后通过 `fork` 创建子进程、`exec` 加载可执行文件执行，父进程（当前 shell）等待其结束；
5. 执行完毕后 shell 读取退出码 `$?`（0 表示成功，非 0 表示失败）。

顺带一个安全提醒：PATH 里的目录按顺序查找，如果有人能往 PATH 前面的目录（比如当前目录 `.`）放一个与系统命令同名的脚本，就能劫持命令。生产环境永远不要把 `.` 放进 PATH；排查可疑命令时用 `type -a` 看全部同名副本。

### man 手册章节结构

man 手册按主题分为 9 个章节，同一名词在不同章节含义不同，用 `man 章节号 名称` 精确指定：

| 章节 | 内容 | 示例 |
| --- | --- | --- |
| 1 | 用户命令（可执行程序和 shell 命令） | `man 1 ls` |
| 2 | 系统调用（内核提供的函数） | `man 2 open` |
| 3 | 库函数（C 程序库中的函数） | `man 3 printf` |
| 4 | 设备文件（`/dev` 下的特殊文件） | `man 4 tty` |
| 5 | 文件格式与约定（各类配置文件） | `man 5 passwd` |
| 6 | 游戏 | `man 6 fortune` |
| 7 | 杂项（协议、宏包、字符集等） | `man 7 ascii` |
| 8 | 系统管理命令 | `man 8 useradd` |
| 9 | 内核例程（Linux 特有，非标准章节） | `man 9 intro` |

最典型的例子是 `passwd`：`man passwd` 查的是 1 章节的修改密码命令，`man 5 passwd` 查的是 `/etc/passwd` 文件的格式说明。查不到时用 `man -k passwd` 搜索所有相关手册页。

顺带说一句，`whatis` 和 `apropos` 查询的是手册页的摘要数据库。刚装完的软件包 `whatis` 查不到，多半是数据库还没生成，执行 `mandb`（老系统是 `makewhatis`）重建即可。

记忆窍门：1 是人敲的命令，5 是文件格式，8 是管理员用的——日常九成查询落在这三个章节，`man man` 本身就有完整列表。

| 按键 | 作用 |
| --- | --- |
| 空格 / `f` | 向下翻一页 |
| `b` | 向上翻一页 |
| `/关键词` | 向下搜索 |
| `n` / `N` | 跳到下一个 / 上一个匹配 |
| `g` / `G` | 跳到开头 / 结尾 |
| `q` | 退出手册 |

### 辨析：type、which、command -v

三者都在找命令，层次不同。`type` 是 shell 内建，能识别别名、函数、内建、外部命令四种身份，排错首选；`which` 是外部工具，只在 PATH 里搜可执行文件，看不到别名和内建；`command -v` 兼具可移植性与准确性——同样是 shell 内建、能识别别名与函数，POSIX 标准保证它在任何 shell 里可用。脚本里判断"命令存不存在"，写 `command -v 命令 >/dev/null 2>&1` 比 `which 命令` 可靠：不同发行版的 `which` 退出码行为并不一致，有的找不到时返回 1，有的返回 2。

熟练使用快捷键可以大幅减少敲命令的时间，以下是最常用的一组（适用于 bash 及多数终端）：

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl + A` | 光标跳到行首 |
| `Ctrl + E` | 光标跳到行尾 |
| `Ctrl + U` | 剪切光标位置到行首的内容（清空已输入部分） |
| `Ctrl + K` | 剪切光标位置到行尾的内容 |
| `Ctrl + W` | 剪切光标前的一个单词 |
| `Ctrl + Y` | 粘贴最近一次被 `Ctrl + U/K/W` 剪切走的内容 |
| `Ctrl + R` | 反向搜索历史命令（输入关键字，再按 `Ctrl + R` 继续向前翻） |
| `Ctrl + L` | 清屏，效果等同 `clear` |
| `Ctrl + C` | 中断当前正在执行的命令 |
| `Ctrl + D` | 发送 EOF，结束输入或退出当前 shell |
| `Ctrl + Z` | 把当前命令挂起到后台（可用 `fg` 恢复、`bg` 继续） |
| `Tab` | 命令名、路径、参数自动补全（连按两次列出候选） |
| `↑` / `↓` | 翻阅历史命令 |
| `!!` | 重复执行上一条命令 |
| `!n` | 执行历史记录中第 n 条命令（配合 `history` 使用） |
| `Ctrl + Shift + C` / `Ctrl + Shift + V` | 在图形终端中复制 / 粘贴 |

这里有个坑：终端卡住、敲什么都没反应，多数情况不是死机，而是误按了 `Ctrl + S`——它不是"保存"，是终端流控（XOFF），会把输出冻结，按 `Ctrl + Q` 恢复即可。`Ctrl + D` 也常被误解：它发送的是 EOF，等于告诉 shell"输入结束了"，只有空行上按下才退出当前 shell，拿它当删除键用的人经常莫名其妙被登出。`Ctrl + R` 搜历史是高频动作：输入关键字实时回显匹配命令，再按继续向前翻，回车执行、方向键可修改。配合 `history | tail` 定位编号再用 `!n`，是重复长命令的两种省力姿势。

## 标准输入输出与重定向 {: .sec-best}

Linux 给每个进程预开了三个文件描述符（fd）：

| fd | 名称 | 默认去向 | 设备文件 |
| --- | --- | --- | --- |
| 0 | 标准输入 stdin | 键盘 | `/dev/stdin` |
| 1 | 标准输出 stdout | 终端屏幕 | `/dev/stdout` |
| 2 | 标准错误 stderr | 终端屏幕 | `/dev/stderr` |

fd 的编号 0/1/2 来自 C 语言标准库的约定，进程一启动内核就替它打开。想亲眼看某个进程开了哪些 fd，`ls -l /proc/进程PID/fd`，每一项都是指向实际打开文件的链接——排查"日志写去哪了""句柄泄漏"这类问题时这个目录非常直观，配合 `lsof -p PID` 使用。

重定向就是改变这三个流的去向，常用写法及语义如下：

| 写法 | 含义 |
| --- | --- |
| `> 文件` | 标准输出覆盖写入文件（原内容被清空） |
| `>> 文件` | 标准输出追加写入文件（原内容保留） |
| `< 文件` | 标准输入改为从文件读取 |
| `<< EOF` | here document：把多行文本作为标准输入，直到遇到 EOF 结束 |
| `<<< "字符串"` | here string：把一个字符串作为标准输入（bash 支持） |
| `2> 文件` | 标准错误覆盖写入文件 |
| `2>> 文件` | 标准错误追加写入文件 |
| `2>&1` | 把 fd 2 指向 fd 1 当前指向的位置（错误与输出合并） |
| `&> 文件` | 标准输出与标准错误都写入文件（覆盖，bash 扩展写法） |
| `&>> 文件` | 标准输出与标准错误都追加写入文件（bash 扩展写法） |
| `> 文件 2>&1` | 与 `&> 文件` 等价的 POSIX 兼容写法 |
| `>> 文件 2>&1` | 与 `&>> 文件` 等价的 POSIX 兼容写法 |
| `> /dev/null 2>&1` | 输出与错误都丢弃（静默执行） |

最容易踩的坑是重定向的顺序。`2>&1` 的含义是"让 fd 2 指向 fd 1 现在指向的地方"，因此：

```bash
find / -name "*.log" > /tmp/all.log 2>&1     # 正确：先让 fd 1 指向文件，再把 fd 2 也指向该文件
find / -name "*.log" 2>&1 > /tmp/all.log     # 错误：fd 2 先指向终端，之后 fd 1 改指文件，错误信息仍然打印在屏幕上
```

再配合 `/dev/null` 这个"黑洞设备"（写入即被丢弃），就得到了运维中最常见的静默写法：

```bash
find / -name "*.log" > /tmp/all.log 2>/dev/null    # 只存结果，丢弃 Permission denied 之类的报错
find / -name "*.log" > /dev/null 2>&1              # 完全不关心任何输出
```

另外两个值得知道的点。其一，`>` 打开文件的瞬间就会清空内容，哪怕后面的命令因路径写错没执行成功，原文件也已经没了——对重要文件做重定向，先备份再动手。其二，`> file` 遇到同名文件会直接覆盖，bash 提供 `set -C`（noclobber）开关，开启后覆盖已存在文件会被拒绝，需要强制时写 `>| file`。

## 管道与 tee

### 管道原理 {: .sec-know}

管道符 `|` 把前一个命令的标准输出连接到后一个命令的标准输入，其工作方式有以下几个要点：

1. 管道由内核维护一块内存缓冲区，左侧进程写、右侧进程读，数据不落盘，因此效率高；
2. 管道两侧的命令是同时启动的并行进程，数据边产生边消费，不需要等左侧全部跑完；
3. 默认只有标准输出（fd 1）会进入管道，标准错误（fd 2）仍打印到终端；要把错误也送进管道，需要写 `命令 2>&1 | 下一级`；
4. 当右侧命令提前退出、管道无人读取时，左侧命令会收到 `SIGPIPE` 信号而终止；
5. 管道只能串联命令，不能"分流"保存——分流要用 `tee`。

内核为管道分配的缓冲区默认 64KB，写满后左侧进程阻塞，直到右侧读走数据——这就是"流式"处理的含义。

脚本期权一提：管道默认只关心最后一个命令的退出码，`命令1 | 命令2` 即使命令1 中途失败，`$?` 也只反映命令2。要让失败"穿透"管道，脚本开头加 `set -o pipefail`；配合 `set -e` 使用，任何一环出错都能及时中断。生产脚本里这两行几乎是标配。

### tee：一份输出两处使用

`tee` 从标准输入读数据，一边原样输出到屏幕，一边写入文件，像水路中的三通：

```bash
make 2>&1 | tee build.log                    # 编译过程边看边存档
make 2>&1 | tee -a build.log                 # -a 追加而非覆盖
find /etc -name "*.conf" | tee /tmp/all.txt | wc -l   # 既存档又统计条数
```

实际排查中"既看实时输出又留档"就是 tee 的本职。进阶一点还有进程替换写法 `命令 | tee >(wc -l)`，把 tee 的另一路直接喂给另一个命令而不落盘，多路消费时很省事。

## 命令执行顺序

| 符号 | 作用 | 行为特点 |
| --- | --- | --- |
| `;` | 顺序执行多条命令 | 互不影响，前一条成败都执行后一条 |
| `&&` | 逻辑与 | 前一条成功（退出码 0）才执行后一条 |
| `||` | 逻辑或 | 前一条失败（退出码非 0）才执行后一条 |
| `&` | 放到后台执行 | 不阻塞当前终端 |
| `(命令1; 命令2)` | 在子 shell 中执行一组命令 | 不改变当前 shell 的环境变量 |
| `{ 命令1; 命令2; }` | 在当前 shell 中执行一组命令 | 会改变当前 shell 的环境 |

经典组合用法：

```bash
cd /data && tar zcf backup.tar.gz app && echo "备份成功" || echo "备份失败"
```

判断逻辑是：`cd` 失败则不打包并输出"备份失败"；`cd` 成功但打包失败也输出"备份失败"；全部成功才输出"备份成功"。每条命令的退出码可以用 `$?` 读取：

补充两点：退出码取值范围是 0-255，0 约定俗成为成功，非 0 的具体含义由各命令自己定义（比如 grep 用 1 表示"没匹配到"）；`$?` 只保留最后执行的那条命令的退出码，前面的成败信息不及时取走就丢了。另外这个 `&&`/`||` 组合有个坑：cmd2 失败时也会触发 cmd3，它并不是 if/else 的等价物，想要真正的二选一，老老实实写 if。

```bash
[root@web01 ~]# ls /nonexistent; echo $?
ls: cannot access /nonexistent: No such file or directory
2
```

{: .sec-pit}

常用工具的新旧对照：

| 旧命令（CentOS 7 及以前） | 新命令（Rocky/Alma 9） | 说明 |
| --- | --- | --- |
| `yum install` | `dnf install` | `yum` 仍可用但已废弃，建议迁移 |
| `netstat -lntup` | `ss -lntup` | `netstat` 属于 net-tools 包，已废弃 |
| `ifconfig` | `ip addr` | `ifconfig` 同属 net-tools，已废弃 |
| `service 服务 start` | `systemctl start 服务` | `service` 仅剩兼容壳，最终都转给 systemd |
| `/etc/init.d/服务 start` | `systemctl start 服务` | SysV 脚本方式已被 systemd unit 取代 |
| `iptables -L` | `firewall-cmd --list-all` / `nft list ruleset` | 后端已全面转向 nftables |
| `ntpdate 时间服务器` | `chronyd`（chrony） | `ntpdate` 已从新版源中移除 |

### 远程连接异常排错 {: .sec-ts}

**第一步：检查链路是否通畅**

```bash
ping 10.0.0.200
```

不通的原因：

1. 物理线路有问题；
2. 检查网卡配置（IP 地址、掩码、网关、DNS）；
3. 网络安全策略阻止；
4. 虚拟网卡是否配置正确（可重新初始化虚拟网络配置）。

> **注意：** 现代系统查看网卡地址用 `ip addr`（或简写 `ip a`），不再使用已废弃的 `ifconfig`。
{: .sec-pit}

**第二步：远程连接请求被阻止**

在客户端进行测试：

```bash
telnet 10.0.0.200 22
```

如果被拒绝，通常是防火墙策略阻止了连接。

> **注意：** 新版最小化安装可能没有 telnet 客户端，可用 `nc -zv 10.0.0.200 22`（nmap-ncat 包）或 `curl -v telnet://10.0.0.200:22` 达到同样的探测效果。
{: .sec-pit}

**第三步：远程服务没有开启**

在服务端进行测试：

```bash
systemctl status sshd
ss -lntup          # ss 是 netstat 的替代工具
```

```console
[root@linux-node1 ~]# ss -lntup
Netid State      Recv-Q Send-Q Local Address:Port    Peer Address:Port
udp   UNCONN     0      0          127.0.0.1:323               *:*      users:(("chronyd",pid=908,fd=1))
udp   UNCONN     0      0                ::1:323              :::*      users:(("chronyd",pid=908,fd=2))
tcp   LISTEN     0      128                *:22                *:*      users:(("sshd",pid=2540,fd=3))
tcp   LISTEN     0      100        127.0.0.1:25                 *:*      users:(("master",pid=1433,fd=13))
tcp   LISTEN     0      128               :::22               *:*
```

> **注意：** 原文表述"`ss` 等同于 `netstat`"并不准确：`netstat` 属于已废弃的 net-tools 包，`ss` 属于 iproute2 包，是新一代的 socket 查看工具，输出更快、信息更全。生产环境应优先使用 `ss`，只有在没有 `ss` 的老系统上才需要 `yum install -y net-tools` 装回 `netstat`。
{: .sec-pit}

`ss` 常用参数：

| 参数 | 作用 |
| --- | --- |
| `-l` | list，列表显示网络服务信息 |
| `-n` | number，以数字方式显示（不反解服务名） |
| `-t` | tcp 网络协议 |
| `-u` | udp 网络协议 |
| `-p` | process，显示服务进程信息 |

### 常见错误与排错 {: .sec-ts}

| 现象 | 可能原因 | 排查命令 | 解决方式 |
| --- | --- | --- | --- |
| `ping` 不通目标 IP | IP/掩码/网关配置错误；虚拟网络服务未启动 | `ip addr`、`services.msc` 检查 vmware 服务 | 修正网卡配置，重新初始化虚拟网络编辑器 |
| `telnet IP 22` 被拒绝或超时 | 防火墙拦截；安全组策略 | `systemctl status firewalld`、`firewall-cmd --list-ports` | 放行 22 端口（`firewall-cmd --permanent --add-port=22/tcp` 后 `--reload`） |
| SSH 提示 `Connection refused` | sshd 服务未启动 | `systemctl status sshd`、`ss -lntup | grep 22` | `systemctl start sshd && systemctl enable sshd` |
| 输入 `ll` 提示 command not found | 当前 shell 未定义该别名 | `type ll`、`alias` | 执行 `alias ll='ls -l --color=auto'`，或写入 `/etc/profile.d/` 持久化 |
| 删除文件时反复要求确认 | 默认定义了 `rm -i` 别名 | `type rm` | 确认后输入 `y`，或用 `\rm 文件` 临时绕过别名 |
| 中文在终端显示乱码 | 客户端与服务端字符集不一致 | `locale`、Xshell 会话字符集设置 | 两端统一为 UTF-8 |

## 自测题 {: .sec-prac}

1. `find / -name "*.log" > /tmp/all.log 2>&1` 与 `find / -name "*.log" 2>&1 > /tmp/all.log` 的区别是什么？后者错在哪里？
2. `type cd` 与 `which cd` 的输出有什么不同？为什么 `which` 查不到内建命令？
3. 执行 `cmd1 && cmd2 || cmd3`，`cmd3` 在什么情况下会执行？`$?` 的值由谁决定？
4. `命令1 | tee /tmp/a.log | 命令2` 这条链路上，数据流是如何分流的？`命令1` 的报错信息会进入 `a.log` 吗？
5. 想查 `/etc/passwd` 这个文件的格式说明（而非 `passwd` 命令的用法），man 应该怎么写？
6. 脚本里想判断 `grep` 是否匹配，为什么推荐 `if grep -q ...` 而不是先执行 grep 再看 `$?`？

> **答案：** 1. 前者先把 fd 1 指向文件、再把 fd 2 指向同一文件，结果与错误都进文件；后者先让 fd 2 指向终端，之后 fd 1 才改指文件，错误信息仍然打印在屏幕上。2. `type cd` 输出 `cd is a shell builtin`；`which` 只在 PATH 目录中找可执行文件，内建命令没有对应文件，所以无输出。3. `cmd2` 失败时执行 `cmd3`；`$?` 的最终值取决于最后执行的命令。4. `tee` 把 stdin 复制成两路：一路写文件、一路继续向下游传递，屏幕与文件都能看到 `命令1` 的标准输出；默认 stderr 不过管道，报错不会进入 `a.log`，需要写 `命令1 2>&1 | tee /tmp/a.log`。5. `man 5 passwd`，5 章节是文件格式与约定。6. 直接执行 grep 会把匹配行打印到屏幕，污染脚本输出；`-q` 静默且命中即停，大文件更快，`if` 结构还天然兼容 `set -e`。

## 小结 {: .sec-sum}

1. 命令分四种身份：shell 内建、外部命令、别名、函数，用 `type`（配合 `-a`、`-t`）区分；`which` 只能查 PATH 中的外部命令。
2. 查帮助有完整体系：`man` 最权威且分 9 个章节（`man 5 passwd` 查配置文件格式），`--help` 速查，`help` 查内建命令，`info` 看 GNU 详细文档，`apropos` 按关键字搜索。
3. 记住高频快捷键：`Ctrl + A/E` 行首行尾、`Ctrl + U/K/W` 剪切、`Ctrl + R` 搜索历史、`Ctrl + L` 清屏、`Tab` 补全；误按 `Ctrl + S` 卡屏用 `Ctrl + Q` 解。
4. 重定向的核心是三个文件描述符 0/1/2；`> 文件 2>&1` 顺序不能颠倒，`2>&1 > 文件` 是错误的经典写法。
5. 管道只传标准输出且两侧进程并行；`tee`（含 `-a`）实现一份输出两处使用。
6. 命令执行顺序：`;` 无条件顺序执行，`&&` 成功才继续，`||` 失败才执行，退出码用 `$?` 读取。
7. 远程排错三段式：先 `ping` 看链路、再 `telnet IP 22` 看是否被策略拦、最后在服务端 `systemctl status sshd` + `ss -lntup` 确认服务与端口；判断端口通不通，`nc -zv` 比 telnet 更通用。
8. CentOS 7 已 EOL，新环境用 Rocky Linux / AlmaLinux；`netstat` 已被 `ss` 取代，`ifconfig` 被 `ip` 取代，`yum` 演进为 `dnf`。
