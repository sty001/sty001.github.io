VMware 装好只是第一步：先搞清快照、克隆与三种网络模式，再掌握远程连接的排错套路（路通不通 → 有没有人拦 → 服务开没开），最后过一遍命令提示符、命令语法与 `shutdown`、`ls`、`mkdir`、`cd`、`pwd` 这批最基础的命令。刚装好虚拟机，就跟着敲。

## 虚拟软件使用方法

### 1. 软件启动注意事项

系统中有些软件可以多次启动（多实例），但 **VMware 不具有多实例功能**，重复启动会报错。

> **注意：** 报错的原因是 VMware 通过后台服务管理所有虚拟机，重复启动时新的进程无法获得服务控制权，而不是软件本身的 bug。

### 2. 软件关闭注意事项

尽量选择**挂起虚拟主机**的方式关闭软件，下次开机可以直接恢复到上次的工作状态。

> **注意：** "挂起"是把虚拟机的内存状态完整保存成一个文件，恢复时直接读回内存，接近秒开；代价是挂起期间会持续占用宿主机的内存和磁盘空间。长时间不使用虚拟机时，更推荐正常关机释放资源。

### 3. 快照功能

虚拟主机可以拍摄快照，相当于"后悔药"——在做危险操作（如改配置、装软件）之前先拍快照，出问题一键回滚。

### 4. 虚拟主机删除方法

右键点击虚拟主机 → `管理` → `从磁盘中删除`。

> **注意：** 建议在主机关机状态下进行删除，避免文件被占用导致删除不干净。

## 快照与克隆的区别与用途

快照和克隆是虚拟化里最容易混淆的两个功能。一句话概括：**快照是"时间轴上的存档点"，克隆是"复制出一台新机器"**。

### 快照（Snapshot）

- 记录虚拟机在某一时刻的完整状态：磁盘内容、内存数据、设备配置；
- 一台虚拟机可以保存多个快照，形成快照链，回滚时任选其一；
- 典型场景：改配置、装软件、系统升级、做破坏性实验之前的"保险"。

> **注意：** 快照不是备份。快照文件与源磁盘强耦合，磁盘文件损坏会连带影响整条快照链；重要数据仍需要独立的备份机制（如 rsync、专业备份系统）。另外，这里有个坑——快照长期不清理会让磁盘持续膨胀、性能下降，实验结束记得删掉旧快照。

### 克隆（Clone）

- 以当前虚拟机为模板，完整复制出一台**新的、独立的虚拟机**：新的磁盘文件、新的 MAC 地址，可重新指定主机名与 IP；
- 分为**完整克隆**（复制全部数据，不依赖源虚拟机）与**链接克隆**（只存差异数据，依赖源虚拟机磁盘，省空间但源被删除后副本不可用）；
- 完整克隆耗时与磁盘大小成正比，链接克隆秒出但依赖母盘——给同事分发用完整克隆，自用省磁盘可选链接克隆；
- 典型场景：批量搭建测试环境、给同事分发配置统一的机器、制作"黄金镜像"。

### 对比表

| 对比项 | 快照 | 克隆 |
| --- | --- | --- |
| 产出物 | 原机器的一个存档点 | 一台全新的虚拟机 |
| 数量关系 | 一台机器可存多个快照 | 一个模板可克隆多个副本 |
| 独立性 | 依赖原磁盘文件 | 完整克隆完全独立 |
| 能否回滚 | 可恢复到拍摄时刻 | 不能反向恢复 |
| 资源占用 | 增量存储差异数据 | 完整克隆占整份磁盘空间 |
| 典型用途 | 操作前的保险 | 批量复制一致环境 |

## 原理解析：三种网络模式的数据是怎么流动的

VMware Workstation 通过宿主机上的**虚拟交换机**（VMnet0、VMnet1、VMnet8）把虚拟机网卡与宿主机、物理网络连接起来。三种网络模式的本质区别，就是虚拟机网卡接在哪个虚拟交换机上，以及这台交换机有没有"出门"的通道。

三种模式的数据流，顺着网线走一遍：

1. **桥接模式**：虚拟机网卡 → VMnet0 虚拟交换机 → 直接桥接到宿主机的物理网卡 → 物理局域网。虚拟机相当于局域网里的一台独立主机，与宿主机平级，需要网段内有空闲 IP 或 DHCP 服务；
2. **NAT 模式**：虚拟机网卡 → VMnet8 虚拟交换机 → VMware NAT 服务 → 借用宿主机 IP 做地址转换后访问外网。虚拟机位于一个私有网段，说白了就是躲在宿主机后面上网，外部设备无法主动访问虚拟机内部，除非手动做端口映射；
3. **仅主机模式**：虚拟机网卡 → VMnet1 虚拟交换机 → 只连通宿主机和其他接在 VMnet1 上的虚拟机。这条链路没有任何"出门"的组件，因此完全隔离外网。

> **补充：** VMware Workstation 其实还有第四种模式——**自定义 / LAN 区段**。它把若干虚拟机划到一个与外界完全隔离的私有二层网络中，常用于搭建集群实验（如多机数据库、Kubernetes 学习环境）。

### 三种模式详细对比

| 模式 | 特点 | 优点 | 缺点 |
| --- | --- | --- | --- |
| NAT 模式 | 虚拟主机和宿主机网络信息可以不一致（如宿主机 10.0.3.x，虚拟主机 10.0.0.x） | 不容易出现局域网中 IP 地址冲突 | 其他宿主机不能直接访问虚拟主机 |
| 桥接模式 | 虚拟主机和宿主机网络信息一致（如都是 10.0.3.x） | 其他宿主机可以直接访问虚拟主机 | 容易出现局域网中 IP 地址冲突 |
| 仅主机模式 | 虚拟主机只能和宿主机或其他虚拟主机建立通讯 | 更加安全 | 不能连接外网 |
| 自定义 / LAN 区段 | 仅多台虚拟机之间互联，宿主机也不在网段内 | 环境隔离最彻底，适合集群实验 | 无法访问宿主机与外网，需配合其他模式使用 |

### 选型建议

| 使用场景 | 推荐模式 | 理由 |
| --- | --- | --- |
| 学习练机、需要虚拟机上网 | NAT | 不与局域网抢 IP，不容易冲突 |
| 虚拟机要被同事或其他机器访问（如部署网站） | 桥接 | 虚拟机有独立局域网身份，可直接互访 |
| 对隔离性要求高、只在本机操作 | 仅主机 | 外网完全不可达，最安全 |
| 多机组集群实验 | 自定义 / LAN 区段 | 多机互联且与外界隔离 |

> **注意：** 企业办公电脑常接入有准入控制的办公网，桥接后虚拟机可能因未注册而被网络准入系统拦截，导致虚拟机上不了网。新手容易栽在这——网络模式明明选对了，就是死活不通。遇到这种情况优先改用 NAT 模式。笔记本连 Wi-Fi 时桥接也可能失败：部分无线网卡驱动不支持桥接，改 NAT 是最省事的出路。

## 远程连接工具：Xshell 与 Xftp

在企业中，管理员通常不在机房本地操作服务器，而是通过远程工具连接。最常用的组合是 Xshell（远程终端）+ Xftp（文件传输）。

为什么远程比机房里敲键盘高效？一是不用跑机房——服务器在另一个城市甚至另一个大洲，远程连接一条命令等价；二是可以开多个会话并行管理几十上百台机器；三是操作全程留痕（终端日志、sshd 记录），事后可审计。机房控制台只留作网络断开时的最后手段。

| 工具 | 定位 | 常用功能 |
| --- | --- | --- |
| Xshell | SSH 远程终端 | 新建会话（IP + 端口 + 用户名密码或密钥）、多标签管理、会话导出导入、字体与配色、断线自动重连、日志录制 |
| Xftp | 图形化 SFTP / FTP 文件传输 | 拖拽上传下载、目录浏览、批量传输、权限修改、与 Xshell 会话联动（在 Xshell 里直接打开当前目录） |

> **注意：** Xshell 默认使用 SSH 协议，连接时如果服务器改了 SSH 端口，需要在会话属性里把端口从 22 改成对应端口。Xftp 与 Xshell 共用会话列表，配置一次两边都能用。

顺带一提：SSH 是加密协议，telnet、FTP 这类明文协议在生产环境一律禁用——账号密码在链路上裸奔，抓个包就全漏了。

### 辨析：密码登录与密钥登录

密码认证简单，但可被暴力猜解，且每次连接都要输一遍。密钥认证用一对非对称密钥：公钥放服务器 `~/.ssh/authorized_keys`，私钥留本机，认证过程不传输任何秘密；配合"禁用密码认证"后，自动化爆破直接失效。生产服务器的标准做法是密钥登录 + 关闭密码认证，完整配置见《远程管理服务 SSH》。

几个值得改的 Xshell 默认设置：打开"日志录制"（会话属性 → 终端 → 日志），每次连接自动把操作记录存成本地文件，出问题能回放；"保持连接状态"设成间隔发心跳，防止 NAT 空闲把连接掐了；字体调大、配色选顺眼的主题，一天看八小时的东西值得花两分钟调。

## 远程连接排错方法

把远程连接想象成"出门去一家店"：路通不通、有没有人拦你、店有没有开门。按这三步依次排查，顺序别乱——跳步排查只会来回折腾。

### 01. 链路是否通畅

检查链路通畅的方法：

```bash
ping 10.0.0.200
```

不通畅的常见原因：

- a. 物理线路有问题，或物理主机被人关闭；
- b. 网络安全设备阻止了 ping 的功能；
- c. 虚拟主机网卡地址是否设置正确；
- d. 虚拟网卡（VMnet8）有没有开启并且配置正确；
- e. 虚拟主机网络服务是否关闭。

排错先 ping 网关：网关是虚拟机出门的第一跳。网关通而外网不通，问题在 NAT 或 DNS；网关不通，问题在链路本身——这样一分为二，排查范围砍一半。

### 02. 是否有安全策略阻止访问

- a. 防火墙没有关闭；
- b. SSH 服务配置中也可以阻止用户远程连接。

### 03. 远程服务是否开启

检查远程服务是否开启：

```bash
telnet 10.0.0.200 22
```

Windows 默认没启用 telnet 客户端，在"启用或关闭 Windows 功能"里勾上才能用——排错时敲 telnet 提示"不是内部或外部命令"，就是这个原因。

网络中会给每个网络服务设置一个数字编号，称为**网络服务端口**，SSH 服务的端口号是 **22**。

连接失败的原因：

- a. 远程服务关闭了，启动即可：

```bash
systemctl start sshd
```

- b. 虚拟网络编辑器中网卡设置错误，进行默认还原即可；
- c. 虚拟软件程序运行不正常：
  - 检查虚拟软件服务是否开启：`Win + R` → `services.msc`
  - 将所有相关服务进行开启或重启。

### 远程连接失败标准排错表

| 现象 | 可能原因 | 排查命令 / 手段 | 解决方式 |
| --- | --- | --- | --- |
| ping 不通 | 网卡未启用、IP 配错、线路故障 | `ip addr`、`ping 网关` | 修正 IP / 启用网卡 / 检查线路 |
| ping 通但 ssh 连不上 | sshd 服务未启动 | `systemctl status sshd` | `systemctl start sshd` 并 `enable` |
| ping 通但 ssh 连不上 | 防火墙拦截 22 端口 | `systemctl status firewalld`、`firewall-cmd --list-ports` | 关闭防火墙或放行 22 端口 |
| ping 通但 ssh 连不上 | 22 端口被修改 | `ss -lnt` 看实际监听端口 | 用新端口连接 |
| 连接超时 | 安全设备（安全组 / 交换机 ACL）拦截 | 从跳板机 `telnet IP 22` 或 `nc -zv IP 22` | 调整安全组 / 网络策略 |
| 提示 connection refused | 目标端口没有服务监听 | `ss -lnt` | 启动对应服务 |
| 提示 permission denied | 用户名或密码错误、禁止 root 登录 | `cat /var/log/secure` 看失败记录 | 核对账号；检查 `PermitRootLogin` 配置 |
| 连接很慢才进去 | GSSAPI 认证与 DNS 反解耗时 | 观察连接等待时长 | 关闭 `GSSAPIAuthentication` 与 `UseDNS`（详见系统优化篇） |

> **注意：** `telnet` 在 CentOS 7 中默认并不安装，现代环境更推荐用 `nc -zv 10.0.0.200 22`（探测端口是否开放）或在服务器本机用 `ss -lnt`（查看监听端口）。两者的作用与 `telnet IP 22` 等价，且 nc 可以只发探测包不断开连接。

### 辨析：ping 通与端口通

`ping` 走的是 ICMP 协议，测的是"这台机器在网络里活没活"；`telnet IP 22`、`nc -zv IP 22` 走的是 TCP，测的是"这个端口上有没有服务在听"。ping 得通只代表链路 OK，sshd 挂了照样连不上——排错的第三步不能省。反过来，有些服务器禁 ping 但 SSH 正常，别被"ping 不通"骗了。

## 现代环境补充

| 旧做法 | 现代做法 | 说明 |
| --- | --- | --- |
| `telnet IP 22` 测端口 | `nc -zv IP 22` | nc 更轻，且不做完整会话 |
| `ifconfig` 看网卡 | `ip addr` | ifconfig 属于 net-tools，已停止维护 |
| `netstat -lnt` 看监听 | `ss -lnt` | ss 直接读内核 netlink，速度更快 |
| VMware Workstation 单机练机 | VirtualBox、KVM（`virt-manager`） | 开箱即用选 VirtualBox，服务器原生虚拟化选 KVM |

> **注意：** CentOS 7 已于 2024 年 6 月停止维护，新系统建议使用 Rocky Linux、AlmaLinux 或 CentOS Stream；本文中的 `systemctl`、`sshd` 等操作在这些系统上同样适用。若使用 KVM 作为虚拟化平台，网络模式的概念（桥接 / NAT / 隔离）与 VMware 完全一致，只是配置入口不同——快照与克隆也都有对应物（`qemu-img snapshot`、`virt-clone`），概念可以直接平移。

## 系统管理的预备知识

### 命令提示符的组成

```bash
[root@linux-node1 ~]#
```

**作用**：只有在命令提示符后面输入命令才有效果。

| 组成部分 | 示例 | 说明 |
| --- | --- | --- |
| 登录用户的信息 | `root` | 当前登录的用户 |
| 分隔符 | `@` | 分隔用户与主机 |
| 主机名信息 | `linux-node1` | 当前主机的名称 |
| 当前所在目录路径信息 | `~` | `~` 表示当前用户的家目录 |

提示符里带上用户和主机名不是装饰：多台机器来回切换时，一眼确认"我是谁、在哪台机器上"，能拦下大量误操作。主机名规范命名（如 linux-node1）也是这个目的。

### 系统命令的语法规范

```text
命令       参数            文件/路径
干的事情   做事情的条件    做事情结果
```

例如：

```bash
systemctl start network
systemctl stop   network
```

> **注意：** 命令、参数、文件之间必须有空格分隔，`ls-l` 和 `ls -l` 是两回事，实际敲一遍就明白。

### 系统目录结构简介

Linux 目录结构一切从根（`/`）开始。

绝对路径像快递单上的完整地址，写到哪都对；相对路径像"我家隔壁"——离开当前目录就失效。两者怎么选，写脚本时见分晓：脚本里一律绝对路径。

| 路径类型 | 定义 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 绝对路径 | 从根开始进行查找数据 | 准确性高 | 寻找数据更慢（写得长） |
| 相对路径 | 从当前路径位置查找数据 | 寻找数据更快（写得短） | 准确性低 |

## 系统的操作命令

### 1. 系统运行命令

> **说明：** Linux 是多用户的系统；Windows 也支持多用户，但按用户数收费——这也是 Linux 服务器并发登录几十个会话不稀奇的原因。

**系统关机：**

```bash
shutdown
```

```bash
[root@linux-node1 test04]# shutdown
Shutdown scheduled for Fri 2019-03-29 11:36:45 CST, use 'shutdown -c' to cancel.
```

定义一个关机方案 = 定义什么时间进行关机，使用 `shutdown -c` 取消关机计划。

```bash
[root@linux-node1 test04]#
Broadcast message from root@linux-node1 (Fri 2019-03-29 11:35:45 CST):

The system is going down for power-off at Fri 2019-03-29 11:36:45 CST!
```

关机信息会广播给所有登录到该主机的用户，并提示真正关机的时刻。这是多用户系统的基本礼节——别人可能还登着呢，直接拔电源等于把人家的工作全毁了。`wall` 命令也能随时给所有在线用户发广播。

指定 5 分钟后关机：

```bash
shutdown -h 5
```

**系统重启：**

```bash
[root@linux-node1 ~]# shutdown -r 5
Shutdown scheduled for Fri 2019-03-29 12:02:41 CST, use 'shutdown -c' to cancel.
[root@linux-node1 ~]#
Broadcast message from root@linux-node1 (Fri 2019-03-29 11:57:41 CST):

The system is going down for reboot at Fri 2019-03-29 12:02:41 CST!
```

也可以直接重启：

```bash
reboot
```

> **知识卡片：shutdown 常用参数**

| 命令 | 作用 |
| --- | --- |
| `shutdown -h now` | 立即关机 |
| `shutdown -h 5` | 5 分钟后关机 |
| `shutdown -r now` | 立即重启 |
| `shutdown -r 12:30` | 在 12:30 重启 |
| `shutdown -c` | 取消待执行的关机 / 重启计划 |
| `shutdown -k time` | 只发送警告信息，并不真正关机 |

### shutdown 与 halt / poweroff 的差别

`shutdown` 是"有礼貌的关机"：先广播通知所有登录用户、拒绝新登录，再按计划停止服务、同步磁盘、断电；`poweroff`、`halt` 是"立即执行"，不打任何招呼。多用户服务器上永远优先 `shutdown`——给在线的人留出保存工作的时间窗口。

### 2. 目录路径相关命令

#### 检查文件或目录是否存在：`ls`（list，列表）

检查文件是否存在：

```bash
[root@linux-node1 ~]# ls /etc/hosts
/etc/hosts
[root@linux-node1 ~]# ls /etc/hosts01
ls: cannot access /etc/hosts01: No such file or directory
```

检查目录是否存在：

```bash
[root@linux-node1 ~]# ls /etc/
abrt                     environment         krb5.conf.d               pki             shadow
adjtime                  ethertypes          latrace.d                 plymouth        shadow-
aliases                  exports             ld.so.cache               pm              shells
aliases.db               favicon.png         ld.so.conf                polkit-1        skel
alternatives             filesystems         ld.so.conf.d              popt.d         sos.conf
```

只查看目录本身的信息：

```bash
[root@linux-node1 ~]# ls -d /data
/data
```

不加 `-d` 时，`ls /data` 列的是目录里的内容；加 `-d` 才显示目录本身的元信息。想确认目录存在且属性正常，`ls -ld /data` 一条到位。

#### 创建新的目录：`mkdir`（make directory）

```bash
[root@linux-node1 ~]# mkdir /data
[root@linux-node1 ~]# mkdir -p /data/test01/test02/test03/test04    # 创建多级目录
[root@linux-node1 ~]# ls -d /data/test01/test02/test03/test04
/data/test01/test02/test03/test04
```

#### 目录的切换：`cd`（change directory）

绝对路径切换：

```bash
[root@linux-node1 data]# cd /data/test01/test02/test03/test04/
```

相对路径切换（相对于当前路径找它下面的路径信息）：

```bash
[root@linux-node1 test03]# cd test04/
[root@linux-node1 test04]# cd ..          # 返回到上一级目录
[root@linux-node1 test04]# cd ../../      # 返回到上两级目录
[root@linux-node1 test04]# cd ../test05
```

两个目录之间快速切换：

```bash
[root@linux-node1 test05]# cd /tmp/
[root@linux-node1 tmp]# cd -
/data/test01/test02/test03/test05
[root@linux-node1 test05]# cd -
/tmp
```

`cd -` 能来回切换，靠的是环境变量 `OLDPWD`——shell 每次切目录都把旧路径记进去。还有一点容易忽略：`cd` 只改变当前 shell 所在目录，脚本里 cd 了，脚本跑完宿主 shell 还在原地。

快速返回到家目录：

```bash
[root@linux-node1 test05]# cd ~
[root@linux-node1 ~]# cd -
/data/test01/test02/test03/test05
[root@linux-node1 test05]# cd          # 直接 cd 也回到家目录
[root@linux-node1 ~]#
```

#### 查看当前所在路径：`pwd`（print work directory）

```bash
[root@linux-node1 test05]# pwd
/data/test01/test02/test03/test05
[root@linux-node1 test05]# cd /data/test01/
[root@linux-node1 test01]# pwd
/data/test01
[root@linux-node1 test01]# cd /tmp/
[root@linux-node1 tmp]# pwd
/tmp
```

## 系统命令的帮助方法

使用 `man`（manual）查看命令手册：

```bash
man mkdir
```

手册的主要结构：

| 章节 | 含义 | 示例 |
| --- | --- | --- |
| NAME | 命令作用说明 | `mkdir - make directories` |
| SYNOPSIS | 命令使用方法 | `mkdir [OPTION]... DIRECTORY...` |
| DESCRIPTION | 命令的参数解释 | `-p, --parents` → `no error if existing, make parent directories as needed` |

> **补充：** man 手册共 9 个章节（1 用户命令、2 系统调用、3 库函数、5 配置文件格式、8 管理命令等）。不同章节可能有同名条目，例如 `man 5 passwd` 查 `/etc/passwd` 的格式说明，`man 1 passwd` 查改密码的命令。在 man 界面中：`/关键词` 向下搜索，`?关键词` 向上搜索，`n` 跳到下一个匹配，`q` 退出。查不到时还可以用 `命令 --help`、`info 命令`、`help 内置命令`——手册太长时，`--help` 直接看参数示例，速度更快。

## 常见错误与排错

| 现象 | 可能原因 | 排查命令 | 解决方式 |
| --- | --- | --- | --- |
| 第二次打开 VMware 报错 | 不支持多实例 | 检查任务栏 / 托盘图标 | 只保留一个 VMware 窗口 |
| 虚拟机上不了网 | 网络模式选错（如仅主机） | 虚拟机设置 → 网络适配器 | 改为 NAT 或桥接模式 |
| 局域网 IP 冲突 | 桥接模式 IP 与同事机器重复 | `ip addr` 查看当前 IP | 换一个空闲 IP 或改 NAT 模式 |
| 快照占了几十 GB | 长期不清理快照链 | 快照管理器 | 删除确认无用的旧快照 |
| VMware 服务异常 | 后台服务被禁用或未启动 | `services.msc` 查看 VMware 相关服务 | 启动服务并设为自动 |
| 从磁盘删除不干净 | 删除时虚拟机还在运行 | 检查虚拟机电源状态 | 关机后再删除 |

## 自测题

1. 三种网络模式各自适合什么场景？为什么生产部署网站时常用桥接？
2. `ping` 通但 `ssh` 连不上，可能有哪些原因？按什么顺序排查？
3. 快照和克隆有什么区别？为什么说快照不是备份？
4. 挂起和正常关机分别适合什么场景？
5. 绝对路径和相对路径各有什么优缺点？

> **答案：**
> 1. NAT 适合学习练机（不抢 IP、可上网）；桥接适合虚拟机需要被外部访问的场景（虚拟机是局域网独立成员）；仅主机适合高隔离场景。生产部署网站常用桥接，是因为其他主机能直接访问虚拟机，无需端口映射。
> 2. 可能原因：sshd 未启动、防火墙拦截 22 端口、SSH 端口被修改、账号或密码错误、被安全策略拦截。顺序：先确认 sshd 是否运行（`systemctl status sshd`），再确认防火墙与端口（`ss -lnt`），最后核对账号与配置。
> 3. 快照是原机器的存档点、依赖源磁盘、可回滚但不能反向恢复；克隆是复制出一台新虚拟机，完整克隆完全独立。快照文件与源磁盘强耦合，磁盘损坏快照也会丢，所以不能替代备份。
> 4. 挂起适合短时间继续工作（秒恢复但占用内存与磁盘）；正常关机适合长时间不用，释放全部资源。
> 5. 绝对路径从根开始，准确但写得长；相对路径从当前位置开始，快而短但依赖当前所在目录。

## 小结

1. VMware 不支持多实例，关闭时优先挂起虚拟主机；快照是操作前的"后悔药"（但不是备份，需定期清理），删除虚拟主机建议先关机。
2. 克隆是从模板复制出新机器，完整克隆独立、链接克隆省空间，是批量交付一致环境的标准做法。
3. NAT 模式不易 IP 冲突但外部无法直接访问；桥接模式外部可直接访问但易冲突；仅主机模式最安全但无法上外网；LAN 区段适合多机集群实验。
4. 远程连接排错分三步：链路是否通畅（`ping`）、有无安全策略拦截（防火墙 / SSH 配置）、远程服务是否开启（`telnet IP 22`，现代可用 `nc -zv IP 22`）。
5. 命令提示符由"用户 @ 主机名 目录"组成，命令语法为 `命令 参数 文件/路径`，各部分必须用空格分隔。
6. 路径分绝对路径（从根开始，准确但长）和相对路径（从当前位置开始，快但准确性低）。
7. 基础命令：`shutdown` / `reboot` 管理系统运行，`ls`、`mkdir -p`、`cd`、`pwd` 管理目录；忘记用法用 `man` 查手册。
