## 9.1 数组基础
{: .sec-expl}

数组说白了就是"同一类型的对象一个挨一个排在一起"。`int a[5];` 一下造出 5 个紧挨着的 `int`，在 LP64 下正好 20 字节，一分不多一分不少。它有三件事是铁律，记死了能避开一大片坑：

- **维度必须是编译期常量**。`int a[n];` 里 n 是运行期变量，标准 C++ 直接拒绝——数组大小要参与类型计算（`int[5]` 和 `int[6]` 是两个不同类型），类型在编译期就得定下来。
- **下标从 0 开始**，最大合法下标是"维度减一"。
- **不检查越界**。`a[5]` 编译器不拦，运行时是 UB，第 08 章的指针算术规则就是它的底层逻辑。

变长数组（VLA，维度是运行期才定的值）在 C99 进过 C 标准，C++ 从头到尾没收——原因挺硬：数组大小会进类型计算、还会决定栈帧怎么摆，一旦放到运行期，类型系统就背不动了。GCC 和 Clang 都给了 VLA 扩展，可一旦依赖它，代码就锁死在这两家编译器上，MSVC 碰都不碰。还有个更阴的同类叫 `alloca`：在栈上现抠一块内存，出错没救（栈不够直接溢出，崩得没声儿），而且它根本不是标准接口。我自己踩过一次 alloca 的坑——栈爆了连个像样的报错都没有。真要运行期才定尺寸，老老实实用 `std::vector`，堆上分配、自动扩容、异常还安全，没理由不用。

```cpp
#include <cstddef>
#include <iostream>

int main() {
    int a[5] = {1, 2, 3, 4, 5};
    constexpr std::size_t n = sizeof(a) / sizeof(a[0]);   // 编译期算元素个数

    std::cout << "元素个数: " << n << '\n';
    std::cout << "总字节数: " << sizeof(a) << '\n';

    // int m = 10;
    // int b[m];   // GCC 放行，但那是编译器扩展，不是标准 C++

    std::cout << a[0] << ' ' << a[n - 1] << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra arr_basic.cpp -o arr_basic && ./arr_basic
```

```text
元素个数: 5
总字节数: 20
1 5
```

sizeof(a) / sizeof(a[0]) 是 C 时代数元素个数的祖传写法，但它只对"还没退化的数组名"管用——一旦传参退化成指针，这套除法就废了（9.6 节会亲眼看到）。我现在的习惯是直接交给 `std::size(a)`（C++17）或者 `std::array::size()`，少写字符还不容易算错。

> **坑：** 全局数组维度写错这种事，我见过不止一次——以为 `N` 是 1024，结果宏里定义的是 1000，编译期本该炸的没炸，运行时越界悄悄把隔壁变量写花了。给维度起名用 `constexpr`，别用 `#define`：`constexpr` 有类型、有作用域，炸的时候诊断信息里还能看到它，宏名早就面目全非了。
{: .sec-pit}

## 9.2 动态数组
{: .sec-know}

运行期才定下尺寸，就得去堆上要内存。C++ 给的原始手段是 `new T[n]`，返回首元素指针，配对释放是 `delete[]`——方括号别漏，`new[]` 配 `delete[]`，`new` 配 `delete`，错配就是 UB。`delete` 只按单个对象去析构、按单对象的方式释放，`new[]` 底层那段内存布局对不上，硬删就出事。

`new[]` 天生带俩缺陷：忘了 `delete[]` 就漏；异常路径上多一个 `return` 或一次抛出，释放就直接被跳过。所以现代 C++ 的答案毫无悬念是 `std::vector`——构造时拿着、析构时自动还、异常安全，还自己会长大。

vector 怎么长大，值得单独记一笔：容量不够时，它去要一块更大的内存（通常是现在的 1.5 或 2 倍，libstdc++ 是 2 倍），把旧元素搬过去、再把旧的释放掉。单次 `push_back` 最坏 O(n)，但把总开销摊到 n 次插入上，每次就是摊还 O(1)。代价是"搬家"会动元素——指向元素的指针、迭代器全部失效。只要能预估大小，先 `reserve` 把搬家压到最多一次，性能稳不少。

```cpp
#include <iostream>
#include <vector>

int main() {
    int* p = new int[8]{0};    // 值初始化：8 个 0
    p[0] = 42;
    std::cout << p[0] << ' ' << p[7] << '\n';
    delete[] p;                // 必须配对 delete[]，写 delete 是 UB

    std::vector<int> v;
    v.reserve(100);            // 提前要够，后面 100 次插入一次搬家都不用
    for (int i = 0; i < 100; ++i) v.push_back(i);
    std::cout << "容量: " << v.capacity() << "，大小: " << v.size() << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra arr_dynamic.cpp -o arr_dynamic && ./arr_dynamic
```

```text
42 0
容量: 100，大小: 100
```

`new int[8]{0}` 里那对大括号会触发值初始化，八个元素全清零；裸写 `new int[8]` 走的是默认初始化，元素值未定义。对 int 这种标量来说，差别就是"全 0 还是一坨垃圾"——这坑我刚工作时栽过，以为默认值会是 0，结果拿到一堆随机数。

> **坑：** `new[]`/`delete[]` 错配、double free、内存泄漏——这三板斧编译器一个都帮不上忙。凡是手痒想写裸 `new[]`，先问一句"能不能换成 vector"。真要自己管生命周期，用 `std::unique_ptr<T[]>`（C++14 起就有，析构自动 `delete[]`），别裸着写。
{: .sec-pit}

## 9.3 数组存储
{: .sec-ver}

多维数组在内存里到底怎么摆？C++ 把它定义成"数组的数组"——`int grid[2][3]` 是 2 个元素，每个元素又是一个 `int[3]`。第一维的下标是挨着排的，这叫**行主序**（row-major）。地址公式一眼就明白：

```text
&grid[i][j] = 基址 + (i * 3 + j) * sizeof(int)
```

行主序的厉害之处，全在缓存上。CPU 从内存搬数据是按缓存行（通常 64 字节）成块拉的：你刚访问完 `grid[i][j]`，紧接着读 `grid[i][j+1]`，数据多半已经在缓存里了——这就是按行遍历。反过来按列遍历，`3 * 4 = 12` 字节的间隔还勉强，可一旦换成 `2048x2048` 的大数组，`grid[i][j]` 和 `grid[i+1][j]` 中间隔了整整一行 8192 字节，每次访问都逼着缓存换一行，性能直接垮掉。

写个基准实测眼见为实：

```cpp
#include <chrono>
#include <iostream>

constexpr int N = 2048;
static int grid[N][N];                       // 2048 * 2048 * 4 字节 = 16 MB

int main() {
    for (int i = 0; i < N; ++i)              // 先填数据，免得被当全零优化掉
        for (int j = 0; j < N; ++j)
            grid[i][j] = (i + j) % 7;

    volatile long long sink = 0;             // volatile 防止求和循环被整体删除
    auto t0 = std::chrono::steady_clock::now();
    for (int i = 0; i < N; ++i)
        for (int j = 0; j < N; ++j)
            sink += grid[i][j];              // 行优先：顺着内存走
    auto t1 = std::chrono::steady_clock::now();
    for (int j = 0; j < N; ++j)
        for (int i = 0; i < N; ++i)
            sink += grid[i][j];              // 列优先：每步跳 8 KB
    auto t2 = std::chrono::steady_clock::now();

    auto ms = [](std::chrono::steady_clock::time_point a,
                 std::chrono::steady_clock::time_point b) {
        return std::chrono::duration_cast<std::chrono::milliseconds>(b - a).count();
    };
    std::cout << "按行遍历: " << ms(t0, t1) << " ms\n";
    std::cout << "按列遍历: " << ms(t1, t2) << " ms\n";
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra arr_layout.cpp -o arr_layout && ./arr_layout
```

```text
按行遍历: 6 ms
按列遍历: 31 ms
```

（LP64、x86-64、`-O2` 下的示例值，具体数字因机器而异，倍数关系才是重点。）

顺手一个推论：多维数组传参必须把除第一维外的维度全带上——`void f(int g[][3])` 实际是 `int (*)[3]`，因为算下标偏移靠的就是内层维度，信息丢了 `g[i][j]` 在哪儿就再也算不出来了。想甩掉这些枷锁，往下看 9.6 节的 `std::mdspan`。

## 9.4 字符数组
{: .sec-know}

C++ 从 C 那儿原封不动接来了"以 `'\0'` 收尾的字符数组就是字符串"这套约定。字符串字面量 `"abc"` 的类型其实是 `char[4]`——三个字符再垫一个结尾的 `'\0'`。所有 C 字符串函数都指望着这个结尾符过活，它就是字符串的"终点站"。

这套机制的账，得一笔笔算：

- **`strlen` 是 O(n)**。它从头扫描到 `'\0'` 为止，没有捷径。想知道长度，C 字符串只有付出扫描代价这一个选项。
- **`strcpy` 没有边界检查**。目标缓冲区装不下就溢出写坏栈——网络安全史上相当比例的事故从这里来。
- **`'\0'` 缺失全盘皆输**。构造一个没有结尾符的字符数组，`strlen` 会一路读到越界，`cout` 会把后面栈上的垃圾一起打印。
- **`gets` 已经除名**。它无法限制读入长度，缓冲区溢出防不胜防，C11 把它踢出 C 标准，C++17 也移除了 `std::gets`。

```cpp
#include <cstring>
#include <iostream>

int main() {
    char s1[] = "abc";                // 4 个字节：'a' 'b' 'c' '\0'
    char s2[3] = {'a', 'b', 'c'};     // 手动初始化：没有结尾符

    std::cout << sizeof(s1) << ' ' << sizeof(s2) << '\n';

    // std::cout << strlen(s2);       // undefined behavior：找不到 '\0'，一路读出去

    char buf[8];
    std::strcpy(buf, s1);             // s1 需要 4 字节，buf 装得下
    std::cout << buf << '\n';

    // std::strcpy(buf, "this string is far too long");   // 溢出：UB，栈被写坏

    std::string sv = s1;              // 现代写法：交给 std::string 管理
    std::cout << sv.size() << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra char_arr.cpp -o char_arr && ./char_arr
```

```text
4 3
abc
3
```

### 现代替代：std::string 与 std::string_view
{: .sec-ext}

默认我会直接上 `std::string`：自己记长度（O(1) 的 `size()`）、自己管内存、拼接比较的重载一应俱全，没理由不用。`std::string_view`（C++17）更狠一层：只存"指针 + 长度"，不拷数据，切子串是 O(1)——`big.substr(2, 5)` 要实打实拷贝，`view.substr(2, 5)` 只是挪一下起点。

代价也直白：string_view **不拥有数据**，它的命全拴在底层字符串的生命周期上：

```cpp
// 需要 -std=c++17
#include <iostream>
#include <string>
#include <string_view>

std::string_view pick() {
    std::string local = "hello";
    return local;                    // undefined behavior：local 销毁，view 空悬
}

int main() {
    std::string big = "hello, string view";
    std::string_view v = big;        // 不拷贝，只记位置和长度
    v.remove_prefix(7);
    std::cout << v << '\n';          // O(1) 切片

    // std::cout << pick() << '\n'; // UB：读到已销毁的栈内存
    return 0;
}
```

```bash
g++ -std=c++17 -O2 -Wall -Wextra sv_dangle.cpp -o sv_dangle && ./sv_dangle
```

```text
string view
```

> **坑：** string_view 有三种最典型的空悬：底层是个临时 `std::string`（`std::string_view v = get_name();`，get_name 返回那一刻它就没了）；函数返回局部字符串的 view；底层容器后面扩容搬了家。我给自己定的原则：string_view 只当**函数参数**用（借用，调用期间有效），别存成成员或长期变量——除非你能拍胸脯保证底层活得比它久。
{: .sec-pit}

## 9.5 数组初始化
{: .sec-know}

数组初始化的规则看着整齐，其实藏着几处反直觉的地方，一条条过：

- **部分初始化，其余补零**。`int a[5] = {1, 2};` 得到 `{1, 2, 0, 0, 0}`。这条规则只认"有初始化列表"——没写初始化列表的局部数组，元素是垃圾值。
- **空列表全零**。`int b[5] = {};` 五个 0，这是最稳的清零写法。
- **维度可以让初始化列表推**。`int c[] = {1, 2, 3};` 维度是 3，写错数字都不用改两处。
- **字符串字面量初始化带 `'\0'`**。`char d[] = "hi";` 是 3 字节——想装下它，维度至少 3；写 `char e[2] = "hi";` 在 C++ 里是编译错误（C 语言从 C99 起允许，代价是悄悄丢掉 `'\0'`，这是个历史包袱）。
- **静态存储期免初始化全零**。全局数组、`static` 数组不写初始化，标准保证全 0；栈上的没这待遇。
- **数组不能整体拷贝赋值**。`int h[3] = {...}; int i[3] = h;` 与 `i = h;` 都是编译错误——数组名在表达式里退化成指针，"赋值整个数组"这个语义在类型系统里没有位置。要拷贝，`std::copy`、`memcpy`，或者干脆用 `std::array`（它是个 struct，赋值语义完好）。

```cpp
#include <iostream>

int main() {
    int a[5] = {1, 2};          // 补零：{1, 2, 0, 0, 0}
    int b[5] = {};              // 全 0
    int c[]  = {1, 2, 3};       // 维度由列表推出：3

    char d[]  = "hi";           // 3 字节：'h' 'i' '\0'
    // char e[2] = "hi";        // 错误：装不下结尾的 '\0'

    static int f[5];            // 静态存储期：保证全 0
    // int g[5];                // 栈上未初始化：读元素是 UB

    std::cout << a[4] << ' ' << b[0] << ' ' << sizeof(d) << ' '
              << sizeof(c) / sizeof(c[0]) << ' ' << f[3] << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra arr_init.cpp -o arr_init && ./arr_init
```

```text
0 0 3 3 0
```

> **坑：** "数组不能拷贝"这一条，最疼的地方在返回：你没法按值返回一个 C 数组。要么把它包进结构体，要么返回指针（当心空悬），要么用 `std::array` 按值返回。我会优先选最后这个——`std::array<int, 3> f() { return {1, 2, 3}; }`，拷贝会被优化掉，零成本。
{: .sec-pit}

## 9.6 指针和数组
{: .sec-iv}

指针和数组的关系，一句话：**数组是数组，指针是指针，但数组名在绝大多数表达式里会退化成指针**。下标运算符就是这场联姻生出来的——`p[i]` 的定义就是 `*(p + i)`，加法又能交换顺序，`*(i + p)` 自然也成立，于是 `i[p]` 居然也合法：

```cpp
#include <iostream>

int main() {
    int arr[4] = {10, 20, 30, 40};
    int* p = arr;                 // 退化：arr 当作 &arr[0]

    std::cout << p[1] << ' ' << *(p + 1) << ' ' << *(1 + p) << ' ' << 1[p] << '\n';

    int (*pa)[4] = &arr;          // &arr 是 int(*)[4]，不是 int**
    std::cout << (*pa)[2] << '\n';
    std::cout << sizeof(arr) << ' ' << sizeof(p) << ' ' << sizeof(*pa) << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra ptr_array.cpp -o ptr_array && ./ptr_array
```

```text
20 20 20 20
30
16 8 16
```

`1[p]` 能过编译，纯粹是 `p[i]` 被定义成 `*(p+i)` 之后数学上对称，写这种代码的同事大概会被请去喝茶。但它捅破了一件事：下标不是数组的专利，它是指针的运算。数组名自己参与下标时，是先退化成指针再算——这也解释了为什么 `sizeof(arr)` 是 16 而 `sizeof(p)` 是 8：退化不是"数组真的变成了指针"，而是"表达式里的数组名被按指针解释"。

`&arr` 和 `&arr[0]` 数值一样、类型却不同：前者是 `int(*)[4]`（步长 16 字节），后者是 `int*`（步长 4 字节）。这个区别正是第 8 章"退化三证据"的用武之地。

### 现代替代：std::span 与 std::mdspan
{: .sec-ext}

数组传参退化那堆老毛病——大小信息丢了、函数里 `sizeof` 是个陷阱——C++20 的 `std::span` 一把全解决了：它就是"指针 + 长度"的轻量视图，C 数组、`std::array`、`std::vector` 都能隐式转进去。

```cpp
// 需要 -std=c++20
#include <array>
#include <iostream>
#include <span>
#include <vector>

void print(std::span<const int> s) {     // 只读接口就用 span<const int>
    for (int x : s) std::cout << x << ' ';
    std::cout << '\n';
}

int main() {
    int arr[] = {1, 2, 3, 4, 5};
    std::array<int, 3> a{7, 8, 9};
    std::vector<int> v{100, 200};

    print(arr);      // 数组自动转 span，大小随身携带
    print(a);
    print(v);
    return 0;
}
```



多维的世界交给 `std::mdspan`（C++23）：在一段连续内存上叠一层"行列"视图，还能用 C++23 的多维下标语法 `m[i, j]`。

```cpp
// 需要 -std=c++23 且 GCC 14 及以上
#include <iostream>
#include <mdspan>
#include <vector>

int main() {
    std::vector<int> data(6, 0);
    std::mdspan m{data.data(), std::extents<std::size_t, 2, 3>{}};
    m[1, 2] = 9;                    // 多维下标是 C++23 新语法
    std::cout << data[5] << '\n';   // 行主序：1 * 3 + 2 = 5
    return 0;
}
```



`m[1, 2]` 落到 `data[5]`，又一次印证了行主序公式。mdspan 跟 span 一样不拥有数据，只是个视图——所有权还在 vector 手里。

## 9.7 使用数组
{: .sec-prac}

选型其实就三句话，我常贴墙记着：**大小编译期就定、想要值语义、还要 constexpr——上 `std::array`；大小运行期才变——上 `std::vector`；只有对接 C 接口或内存布局特别敏感时——才去碰裸数组**。

`std::array` 本质就是把裸数组包进 struct 的零开销容器：不退化（传参不会丢大小）、能拷贝赋值、能按值返回，还白送 `size()`/`front()`/`back()` 和迭代器，全程对 constexpr 友好。

```cpp
// 需要 -std=c++20
#include <algorithm>
#include <array>
#include <iostream>

int main() {
    std::array<int, 5> a{3, 1, 4, 1, 5};

    std::cout << "大小: " << a.size() << '\n';
    std::sort(a.begin(), a.end());
    for (int x : a) std::cout << x << ' ';
    std::cout << '\n';

    std::cout << a.front() << ' ' << a.back() << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra std_array.cpp -o std_array && ./std_array
```

```text
大小: 5
1 1 3 4 5
1 5
```

> **注意：** `std::array` 跟裸数组一样不做越界检查，`a[10]` 照样 UB；要检查就换成 `a.at(10)`，越界会抛 `std::out_of_range`。经验上：性能热路径用 `[]` 图快，边界拿不准的地方老老实实用 `at()`。
{: .sec-note}

## 9.8 枚举
{: .sec-know}

枚举干的事，就是给"一组相关的整数常量"安上名字和类型。C++ 里其实有两套枚举，行为天差地别，坑也基本都埋在这儿。

老式的**不限定作用域枚举**（unscoped enum）有三宗罪，我刚学的时候全中过：

- **名字污染外层作用域**。`enum Color { RED, GREEN, BLUE };` 之后，`RED` 撒在全局，再定义一个 `enum Traffic { RED, YELLOW };` 直接重定义冲突。
- **隐式转整数**。`RED + 1`、`int x = GREEN;` 随便混，枚举的类型名存实亡。
- **底层类型不确定**。没指定底层类型时由实现挑一个"装得下"的，可移植代码不能假设它的大小。

C++11 的 **`enum class`**（限定作用域枚举）把这几宗罪逐一堵上了：枚举名收进自己的作用域（必须写 `Fruit::APPLE`）；不隐式转整数，跨类型得显式 `static_cast`；默认底层类型钉死成 `int`，还能用 `: unsigned char` 这种语法显式指定，把大小捏得准准的。

```cpp
// 需要 -std=c++11
#include <iostream>

enum Color { RED, GREEN, BLUE };              // 不限定作用域：RED 撒进外层
enum class Fruit { APPLE, BANANA };           // C++11：强类型枚举

enum class Level : unsigned char { LOW = 1, MID, HIGH };   // 指定底层类型

int main() {
    int score = RED + 1;                      // 不限定枚举和 int 随便混——坑就在这
    std::cout << score << '\n';

    Fruit f = Fruit::APPLE;
    // int bad = f;                           // 错误：enum class 不给隐式转换
    std::cout << static_cast<int>(f) << '\n';
    std::cout << static_cast<int>(Level::MID) << '\n';
    std::cout << sizeof(Level) << '\n';       // 1：底层类型生效
    return 0;
}
```

```bash
g++ -std=c++11 -O2 -Wall -Wextra enum_class.cpp -o enum_class && ./enum_class
```

```text
1
0
2
1
```

### using enum 与 switch 穷尽性
{: .sec-ext}

`enum class` 严格了，但也带来了 `EnumName::Value` 的前缀疲劳。C++20 的 `using enum` 把枚举成员引入当前作用域，前缀想省就省：

```cpp
// 需要 -std=c++20
#include <iostream>

enum class Op { ADD, SUB, MUL };

struct Calc {
    using enum Op;          // C++20：枚举成员进入 Calc 的作用域
};

int main() {
    Calc::Op o = Calc::ADD;                 // 不用写 Calc::Op::ADD
    switch (o) {
        case Op::ADD: std::cout << "add\n"; break;
        case Op::SUB: std::cout << "sub\n"; break;
        case Op::MUL: std::cout << "mul\n"; break;
        // 故意不写 default，见下文
    }
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra enum_using.cpp -o enum_using && ./enum_using
```

```text
add
```

switch 和枚举是天生一对，穷尽性检查是个隐藏福利：当 switch 的条件是枚举类型、且覆盖了全部枚举值、**还不写 default** 时，将来你给枚举加个新值，编译器的 `-Wswitch`（`-Wall` 自带）会挨个给漏掉的 case 报警。反过来写了 default，这道保险就关了——新值悄无声息落进 default，bug 藏得毫无痕迹。所以我跟自己约好：**枚举的 switch 不写 default，靠警告把未来的坑兜住**。

## 9.9 结构体
{: .sec-know}

struct 把不同类型的成员捆成一个整体，是 C++ 自定义类型的起点。先清一笔旧账：**struct 和 class 唯一的差别就在默认访问级别和默认继承方式**——struct 默认 public，class 默认 private。成员函数、构造函数、继承、模板参数，它俩通吃。选哪个纯粹是风格问题：纯数据聚合用 struct，封装了不变量、带行为逻辑的用 class。

### 聚合类型与聚合初始化
{: .sec-know}

聚合初始化（`Point p{1, 2};`）是 C++ 里最省事的一种构造，但它有明确门槛，不是谁都能用。**C++20 的规则**：一个类想要是聚合类型，得同时满足：

- 没有用户声明或继承的构造函数；
- 没有私有或保护的非静态数据成员；
- 没有虚函数和虚基类；
- （基类方面）基类必须是 public 且非虚——C++17 起聚合允许有公开基类。

满足上面这些，就能用 `{}` 按成员声明顺序逐个填，没写到的成员走默认规则（有默认成员初始化器就照它来，否则值初始化成 0）。C++14 之后聚合还能带默认成员初始化器，"字段默认值"这种写法才算合法。

C++20 的指派初始化器（designated initializers）又往前推了一步：初始化时可以直接点名成员，跳着写、漏着写都行——但点名的顺序必须跟声明顺序对上。

```cpp
// 需要 -std=c++20
#include <iostream>

struct Point { int x; int y; };            // 聚合：无构造函数、无私有成员、无虚函数

struct Conf {
    int timeout = 30;                      // C++14 起聚合可带默认成员初始化器
    int retries  = 3;
    bool trace   = false;
};

int main() {
    Point p1{1, 2};
    Point p2{.x = 3, .y = 4};              // C++20 指派初始化器
    Point p3{.x = 7};                      // 未点名的 y 按默认规则补 0

    Conf c{.retries = 5};                  // 合法：没点名的成员用默认值
    std::cout << p1.x << ' ' << p2.y << ' ' << p3.y << '\n';
    std::cout << c.timeout << ' ' << c.retries << ' ' << c.trace << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra agg_init.cpp -o agg_init && ./agg_init
```

```text
1 4 0
30 5 0
```

`{.y = 2, .x = 1}` 这种乱序写法直接编译不过——指派必须按声明顺序来，这是 C++ 跟 C99 指派初始化的关键差异（C 里顺序随便）。这条限制换来的，是初始化顺序永远可预测。

### 成员按声明顺序初始化
{: .sec-ts}

构造函数初始化列表的书写顺序是个障眼法：**成员永远按声明顺序初始化**，列表里怎么写说了不算。多数时候无所谓，可一旦初始化表达式引用了别的成员，这个先后就性命攸关：

```cpp
// 需要 -std=c++20
#include <iostream>

struct Order {
    int a;
    int b;
    Order(int x) : b(x), a(x + 1) {}   // -Wall 会警告：实际初始化顺序是 a 先 b 后
};

int main() {
    Order o{10};
    std::cout << o.a << ' ' << o.b << '\n';   // 这里碰巧没事：a、b 互不依赖
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra init_order.cpp -o init_order && ./init_order
```

```text
11 10
```

gcc 的 `-Wreorder`（`-Wall` 自带）专门抓"列表顺序跟声明顺序不一致"。这次在警告下没出事，是因为 `a` 不依赖 `b`；要是把初始化写成 `Order(int x) : b(x), a(b) {}`，`a` 拿到的就是还没初始化的 `b`——直接 UB。我给自己定的规矩：**初始化列表的书写顺序照抄声明顺序**，让这个警告永远别响。

### 位域
{: .sec-know}

位域（bit-field）让成员按"位"来分：`unsigned code : 6` 就是占 6 位。打包协议头、塞硬件寄存器里的标志位，是它最对口的活儿。代价也明摆着：**位域取不了地址**（它压根不是按字节对齐的对象），具体的打包方式由实现决定，跨平台的二进制兼容就别指望它了。

```cpp
#include <iostream>

struct Flags {
    unsigned ready : 1;
    unsigned err   : 1;
    unsigned code  : 6;      // 三个位域共 8 位，正好一个字节的信息量
};

int main() {
    Flags f{1, 0, 42};
    std::cout << f.ready << f.err << ' ' << f.code << '\n';
    std::cout << sizeof(Flags) << '\n';   // GCC 下为 4：分配单元是 unsigned
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra bitfield.cpp -o bitfield && ./bitfield
```

```text
10 42
4
```

`sizeof(Flags)` 是 4 而不是 1：GCC 以 `unsigned` 为分配单元，哪怕只用了 8 位。标准压根不规定位域怎么打包，所以写跨平台序列化时，位域只配当"内存里省点空间"用，别让它直接出现在线缆格式上。

### 对齐与 padding：一次完整的推算
{: .sec-ver}

每个类型都有对齐要求（`alignof`）：`int` 通常得 4 字节对齐。为了让成员对得上自己的对齐，编译器会在成员之间、以及结构体末尾塞进填充字节（padding）。推算就两条：**成员放在它对齐要求的整数倍偏移上；结构体的总大小是它对齐要求的整数倍**（这样数组里相邻元素才个个对齐）。

拿 `struct A { char c; int i; char d; };` 推一遍：`c` 占偏移 0；`i` 要 4 字节对齐，偏移 1~3 得填空，`i` 占 4~7；`d` 占偏移 8；总大小再凑成 4 的倍数，偏移 9~11 又填一笔——12 字节。把成员顺序调一下（大的往前放）就能省下来：

```cpp
#include <cstddef>
#include <iostream>

struct A { char c; int i; char d; };   // 1 + (3 填充) + 4 + 1 + (3 填充) = 12
struct B { int i; char c; char d; };   // 4 + 1 + 1 + (2 填充) = 8

int main() {
    std::cout << "A: size=" << sizeof(A) << " align=" << alignof(A) << '\n';
    std::cout << "c 偏移 " << offsetof(A, c) << "，i 偏移 " << offsetof(A, i)
              << "，d 偏移 " << offsetof(A, d) << '\n';
    std::cout << "B: size=" << sizeof(B) << " align=" << alignof(B) << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra padding.cpp -o padding && ./padding
```

```text
A: size=12 align=4
c 偏移 0，i 偏移 4，d 偏移 8
B: size=8 align=4
```

同样的字段，换个顺序就从 12 字节瘦到 8 字节。把成员按对齐要求从大到小排，是省内存的老手艺了；大数组场景里这一手能真省出不少缓存。

### 空类、EBO 与 no_unique_address
{: .sec-ext}

空类 `struct Empty {};` 的 `sizeof` 至少是 1——标准要求不同对象得有不同地址，所以空对象也得占一个字节的地皮。这个"至少 1"会传染：空类一旦当成员或基类，就白白占着地方。有两条正经逃生通道：

- **空基类优化（EBO）**：空类作为基类时，允许与子类的其他成员共址、不占空间。几乎所有编译器都执行。
- **`[[no_unique_address]]`**（C++20）：标注在成员上，允许该成员与其他成员共址。GCC/Clang 执行，MSVC 目前忽略它（视为空标注）。

```cpp
// 需要 -std=c++20
#include <iostream>

struct Empty {};                        // sizeof 至少 1

struct Naive {                          // 两个空成员 + int
    Empty a;
    Empty b;
    int i;
};

struct Compact : private Empty {        // EBO：空基类不占空间
    int i;
};

struct Opt {
    [[no_unique_address]] Empty a;      // C++20：允许空成员共址
    int i;
};

int main() {
    std::cout << sizeof(Empty) << ' ' << sizeof(Naive) << ' '
              << sizeof(Compact) << ' ' << sizeof(Opt) << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra ebo.cpp -o ebo && ./ebo
```

```text
1 8 4 4
```

这套手艺最对口的，是泛型代码：自定义分配器、比较器常常是那种无状态的空类，塞进容器（`std::vector` 的 allocator、`std::map` 的比较器）时，靠 EBO 把开销吃掉。我自己写容器模板时，会把"可有可无的策略对象"设计成基类或 `[[no_unique_address]]` 成员——这跟标准库是同一个思路。

### 三路比较与结构化绑定
{: .sec-ext}

给结构体把六个比较运算符（`==`、`!=`、`<`、`<=`、`>`、`>=`）补全，是纯体力活，C++20 让你只写一行就搞定：

```cpp
// 需要 -std=c++20
#include <compare>
#include <iostream>

struct Ver {
    int major;
    int minor;
    auto operator<=>(const Ver&) const = default;   // 一行拿到全部六个比较
};

int main() {
    Ver a{1, 4}, b{1, 10};
    std::cout << (a < b) << ' ' << (a == b) << ' ' << (b >= a) << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra spaceship.cpp -o spaceship && ./spaceship
```

```text
1 0 1
```

default 出来的 `<=>` 会按成员声明顺序逐个比，而且顺手把 `operator==` 也 default 出来（前提是类里没自己声明 `==`）——所以 `a == b` 也能直接用，不用再补第二行。

结构化绑定（C++17）是"拆对象"的一把利器：聚合、数组、tuple-like 类型（`std::pair`/`std::tuple`/`std::map` 的元素）都能一次性拆开。

```cpp
// 需要 -std=c++17
#include <iostream>
#include <map>
#include <string>
#include <tuple>

struct Price { int yuan; int fen; };

Price split(int cents) { return {cents / 100, cents % 100}; }

int main() {
    auto [yuan, fen] = split(1299);       // 拆聚合类型
    std::cout << yuan << " 元 " << fen << " 分\n";

    Price p{2, 50};
    auto& [a, b] = p;                     // 绑定引用还能写回去
    a = 3;
    std::cout << p.yuan << '\n';

    std::map<std::string, int> m{{"apple", 3}};
    for (const auto& [name, count] : m)
        std::cout << name << " x " << count << '\n';

    std::tuple<int, std::string, double> t{1, "one", 1.5};
    auto [i, s, d] = t;
    std::cout << i << ' ' << s << ' ' << d << '\n';
    return 0;
}
```

```bash
g++ -std=c++17 -O2 -Wall -Wextra struct_bind.cpp -o struct_bind && ./struct_bind
```

```text
12 元 99 分
3
apple x 3
1 one 1.5
```

遍历 map 再也不用写 `it->first`/`it->second`，`pair` 也不用去记 first 到底是啥——名字本身就是文档。用好它只要记住一条：`auto [a, b]` 是拷贝，`auto& [a, b]` 才能改回原对象。

## 9.10 联合
{: .sec-warn}

union 让多个成员**共享同一段内存**，大小就是最大那个成员。省内存的代价是一条铁律：**同一时刻只有一个成员是"活跃"的**（就是最后被写进去的那个），读非活跃成员是 undefined behavior。

> **警告：** 像 `union Raw { std::uint32_t u; float f; };` 这样，写完 `r.u = 0x3F800000;` 再去读 `r.f`，在 C++ 标准里就是 UB——哪怕它在绝大多数机器上"恰好"能跑出对的数。这是 C++ 跟 C 的重要差异点，带着 C 的思维跨过来的人最容易栽在这儿。
{: .sec-warn}

有两条例外，值得记一下：

- **公共初始序列**：若干标准布局（standard-layout）结构体共享开头的成员序列时，读公共部分有定义。这是 C 遗产，实践中已经很少依赖。
- **逐字节搬运不算"读成员"**：`std::memcpy` 把 union 的字节拷出来再按别的类型解读，行为有定义——这是 type punning 的正规通道（第 08 章 strict aliasing 一节同款结论）。

```cpp
#include <cstdint>
#include <cstring>
#include <iostream>

union Raw {
    std::uint32_t u;
    float f;
};

int main() {
    static_assert(sizeof(float) == sizeof(std::uint32_t));

    Raw r;
    r.u = 0x3F800000;                     // 活跃成员是 u

    float v = 0;
    std::memcpy(&v, &r, sizeof v);        // memcpy 搬字节：行为有定义
    std::cout << v << '\n';               // 得到 1.0

    // float bad = r.f;                   // 直接读非活跃成员：undefined behavior
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra union_raw.cpp -o union_raw && ./union_raw
```

```text
1
```

### 放非平凡类型进 union 的坑
{: .sec-ts}

union 不会替你管成员的生命周期。一旦把 `std::string` 这种带构造析构的成员放进去，编译器会直接把 union 那几个隐式的构造/析构/赋值函数删掉（它根本不知道该毁哪个），一切只能手动来：激活用 placement new，销毁手动调析构函数。

```cpp
// 需要 -std=c++20
#include <iostream>
#include <new>
#include <string>

union Tagged {
    int i;
    std::string s;
    Tagged() {}
    ~Tagged() {}          // 编译器不知道 s 是否活跃，析构只能交给你
};

int main() {
    Tagged t;
    t.i = 42;
    std::cout << t.i << '\n';

    // 活跃成员换成 string：必须手动 placement new
    new (&t.s) std::string("hello");
    std::cout << t.s << '\n';

    t.s.~basic_string();  // 用完手动析构，漏掉就泄漏
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra union_tagged.cpp -o union_tagged && ./union_tagged
```

```text
42
hello
```

还得自己记着"当前活跃的是谁"——忘了记、记岔了，就是 UB。这套手工活只在内核、嵌入式、协议解析这种"每 bit 都是钱"的场景才值得，而且通常外面还得再包一层带 tag 的结构体。

### 现代替代：std::variant
{: .sec-ext}

`std::variant`（C++17）就是"会自己管生命周期的类型安全 union"：它记着当前活跃的是哪种类型，构造析构自动跟上，取错类型要么抛异常（`std::get`）要么返回空指针（`std::get_if`），访问用 `std::visit` 来分派。默认构造出来是第一个类型的值——要是第一个类型没有默认构造，塞一个 `std::monostate` 占个位就行。

```cpp
// 需要 -std=c++17
#include <iostream>
#include <string>
#include <type_traits>
#include <variant>

using Cell = std::variant<std::monostate, int, std::string>;

int main() {
    Cell c;                              // 默认构造第一个类型：monostate
    std::cout << c.index() << '\n';      // 0

    c = 42;
    std::cout << std::get<int>(c) << '\n';

    c = std::string("hi");
    std::cout << std::get<std::string>(c) << '\n';

    c = std::monostate{};                // 回到"空"状态

    auto show = [](auto&& v) {           // visit 一次处理所有可能
        using T = std::decay_t<decltype(v)>;
        if constexpr (std::is_same_v<T, std::monostate>)
            std::cout << "(空)\n";
        else
            std::cout << v << '\n';
    };
    std::visit(show, c);
    c = 7;
    std::visit(show, c);
    return 0;
}
```

```bash
g++ -std=c++17 -O2 -Wall -Wextra variant_demo.cpp -o variant_demo && ./variant_demo
```

```text
0
42
hi
(空)
7
```

`std::visit` 配上泛型 lambda 和 `if constexpr`，能把"按当前类型分派"压成一行，漏处理哪个类型直接编译报错——比 union 那套手工 tag 强出一个量级。选型我一般这么分：需要精确控制内存布局、对接二进制协议，才用 union；其余一切"多选一"的值，统统 `std::variant`。

## 9.11 自定义类型
{: .sec-know}

`typedef` 和 `using` 都能给类型起别名，功能重叠但气质完全不同。`typedef` 语法老派，一碰到函数指针就开始套括号；`using` 是"左名字右类型"，结构清爽，而且**别名模板（带参数的别名）只有 `using` 能写**——`typedef` 压根没有对应语法。

```cpp
// 需要 -std=c++20
#include <iostream>
#include <map>
#include <string>
#include <tuple>
#include <vector>

typedef unsigned long ulong_t;              // 老写法，还能用
using uint_v = std::vector<unsigned>;       // 新写法

using Handler = void (*)(int);              // 函数指针别名：using 完胜
// typedef void (*Handler)(int);            // 同样的东西，括号套括号

template <class T>
using StrMap = std::map<std::string, T>;    // 别名模板：只能用 using

void on_event(int code) { std::cout << "事件码 " << code << '\n'; }

int main() {
    uint_v v{1, 2, 3};
    std::cout << v.size() << '\n';

    Handler h = on_event;
    h(7);

    StrMap<double> price{{"apple", 5.5}};
    std::cout << price.at("apple") << '\n';

    std::pair<std::string, int> p{"banana", 6};
    std::tuple<int, std::string, double> t{1, "one", 1.5};
    std::cout << p.first << ' ' << p.second << '\n';
    std::cout << std::get<1>(t) << ' ' << std::get<2>(t) << '\n';
    return 0;
}
```

```bash
g++ -std=c++20 -O2 -Wall -Wextra alias.cpp -o alias && ./alias
```

```text
3
事件码 7
5.5
banana 6
one 1.5
```

新代码我一律写 `using`，理由就三条：从左到右读不绕弯；能写别名模板；模板里 `using X = typename Y::type` 这种场景没替代。`typedef` 留在老代码里别动它，就当历史遗迹。

`std::pair` 和 `std::tuple` 是"临时捆俩/捆几个值"的轻量工具：`std::get<N>` 按位置取，配合结构化绑定拆开用，`std::make_pair`/`std::make_tuple` 还能省掉模板参数。它们适合函数返回多值、map 遍历这种即用即弃的场合；但只要数据成员有名有义，老老实实写 struct——`p.first` 跟 `p.price` 的可读性，差着得有一代人。

## 9.12 技术解惑
{: .sec-ts}

### 数组和指针是一回事吗

不是，这是 C++ 里最顽固的一个误解。数组是完整的对象类型（`int[10]`，sizeof 40）；指针只是个存地址的标量（sizeof 8）。它俩在三个场景里看着一样（元素访问、退化传参、指针算术），在另外三个场景里又分得清清楚楚——`sizeof`、取地址 `&`、能不能赋值。第 8 章那"退化三证据"正是分界线：数组名只有在表达式里才被当指针解释，类型系统里 `int[10]` 和 `int*` 从不等于。

### `char s[2] = "hi"` 为什么 C 合法 C++ 非法

C 语言从 C99 起就允许初始化列表比数组短（甚至允许把字符串字面量的 `'\0'` 截断扔掉），这是给老代码留的口子；C++ 觉得造一个"没有结尾符的字符数组"纯属坑——它连合法的 C 字符串都不是，传给任何 C 字符串函数都是越界读——所以直接判非法。两门语言在"容忍历史"和"消灭坑"之间取舍不同，这一局 C++ 赢了。

### union 还是 variant

我一般问自己三个问题：内存布局要不要精确控制（二进制协议、硬件寄存器）？成员类型是不是运行期才组合出来？代码跑在不抛异常的环境里吗？布局敏感或无异常环境，选 union（记得配上手工 tag）；其余统统 `std::variant`——类型安全、生命周期自动、还能靠 `visit` 在编译期查漏。真到了要手写 union 的那天，把"活跃成员是谁"的 tag 结构体一并写了，别裸奔上阵。

### 常见 UB 清单
{: .sec-warn}

复合类型这一章的 UB 高发区，自己对一遍：

- 数组越界读写（`a[n]`、负下标、多维数组行列写反）。
- VLA 依赖编译器扩展，或用 `alloca` 把栈撑爆。
- 字符数组没有 `'\0'` 就交给 `strlen`/`strcpy`/`cout`。
- string_view 的底层对象先死了（临时 string、容器扩容、返回局部值）。
- `new[]` 配 `delete`（或反过来），以及重复释放。
- union 读非活跃成员、非平凡成员不手动析构。
- 位域跨平台二进制布局假设。
- 结构体初始化列表顺序与声明顺序不一致导致的未初始化依赖。

## 动手练
{: .sec-ex}

1. **span 接口**：写 `void print(std::span<const int> s)`，在 `main` 里分别传入 `int[6]`、`std::array<int, 4>`、`std::vector<int>` 各调用一次；再试着传一个 `std::string`，观察编译错误，想想为什么。
2. **状态机**：用 `enum class State : unsigned char { IDLE, RUN, PAUSE, DONE };` 写一个随输入迁移的 switch 状态机，故意不写 default，然后给枚举加一个新值 `ERROR`，用 `-Wall` 重新编译看警告。
3. **布局侦探**：对 `struct S { char a; double b; int c; };` 先在纸上推算 `sizeof` 和各成员 `offsetof`，再写程序验证。把成员按对齐从大到小重排，比较两种写法的大小。
4. **variant 计算器**：用 `std::variant<int, double, std::string>` 存"表达式结果"，写一个 `std::visit` 打印器，对 string 输出带引号、对浮点保留两位小数（`std::fixed` 与 `<iomanip>`）。
5. **找茬**：手写一段包含下列问题的代码——`char s[3] = {'a','b','c'};` 后接 `strlen(s)`、`std::string_view v = std::string("tmp");`、`new char[10]` 配 `delete`——逐一修复，并用 `-Wall -Wextra` 加 AddressSanitizer（`-fsanitize=address`）复核。

## 变式追问
{: .sec-think}

1. **为什么数组不能整体赋值，struct 却可以？** 数组的"退化"语义是根因：C 设计之初就规定数组名在表达式里当指针用，`a = b` 里 a 已经退化成 `int*`（右值，不可赋值），"整体赋值"在语法层面就没了落脚点。struct 没有退化语义，它是一个完整的标量式对象，赋值按成员逐个拷贝，语义干净。这是 1970 年代"指针即数组"的遗产，C++ 出于兼容一直背着。想要赋值语义，把数组包进 struct（或者用 `std::array`，它干的就是这件事）。
2. **行主序为什么成为 C/C++ 的选择，Fortran 却是列主序？** C 的多维数组定义为"数组的数组"——`a[i][j]` 是先取第 i 个 `int[N]` 再取它的第 j 个元素，这个递归定义天然推出行主序：最后一维变化最快。Fortran 的数组是"整体对象"，数学上按列向量习惯，选了列主序。谁对谁错没有答案，但边界要认清：把 C 的二维数组指针传给按列主序写的 BLAS 例程时，要么转置，要么交换行列参数——历史上多少数值 bug 是主序弄反造成的。
3. **`i[p]` 既然合法，为什么没人这么写？** 它只是 `*(i + p)` 的换序，标准保证与 `p[i]` 等价。没人写，因为下标的语义是"从容器里取第 i 个"，`i[p]` 颠倒了主语和索引，可读性归零。它的存在价值是揭示了语言的实现真相——下标是指针运算的语法糖，不是容器的特权；也正因如此，写自定义迭代器时只需实现 `operator+`，下标就自动可用。偶尔在老式宏或炫技代码里见到它，那不是学习对象，是阅读障碍。
4. **`[[no_unique_address]]` 在 MSVC 上不生效怎么办？** 接受现实：它是"允许优化"的标注，不是"必须生效"的指令，MSVC 目前忽略它，大小不变。可移植的设计不能把正确性押在它身上——省内存是收益，不省是常态。真正需要跨平台压缩空对象时，用 EBO（空基类优化），三大编译器都执行；或者把策略对象改成模板参数配合 `std::conditional_t` 直接剔除。测大小的断言（`static_assert(sizeof(Opt) == sizeof(int))`）也别写——它在 MSVC 上会真实地失败。
