## 文档中的代码/命令信息

命令、参数、终端输出建议使用等宽字体并单独成块，与正文区分开，避免被自动排版（自动编号、首字母大写、引号替换）破坏。

## 第二部分：Vim 文本编辑器使用技巧

### Vim 简介

- **vi**：Unix 系统上最经典的文本编辑器，从 ed 演化而来，几乎所有的类 Unix 系统都自带 vi。
- **vim**（Vi IMproved）：vi 的增强版，在 vi 基础上增加了语法高亮、多级撤销、分屏、标签页、代码折叠、插件等大量特性，是目前 Linux 服务器上最常用的编辑器。
- **vim 与 vi 的关系**：vim 兼容 vi 的所有命令。CentOS 系统中执行 `vi` 命令实际调用的是精简版的 vim（vim-minimal 软件包），安装完整 `vim` 软件包后体验更完整（语法高亮等）。
- **vim 与 sed 的关系**：vim 是**交互式全屏编辑器**，人在里面一边看一边改；sed 是**非交互式流编辑器**，按行处理、不需要人参与，适合写在脚本里批量处理。说白了，一个给人用，一个给脚本用。vim 内部还可以通过 `:!sed` 等方式调用 sed，两者互补。

为什么运维几乎都在用 vim 而不是 nano？最小化安装的 Linux 只有 vi/vim，nano 反而要另装；各发行版、各 Unix 的服务器上都找得到 vim，应急环境也能用。习惯了 vim，到哪台机器都不慌。

打开与保存文件：

```bash
vim file.txt          # 打开或新建文件
vim +10 file.txt      # 打开并跳到第 10 行
vim -R file.txt       # 以只读方式打开
```

超大日志文件别直接 vim 打开——整文件加载进内存，动辄卡死终端。看大文件用 less、grep，必须改时用 `sed -i` 或先截取片段。对比两个文件用 `vim -d a b`（即 vimdiff），差异行高亮两侧对照，比肉眼舒服得多。

### 四种模式及切换

Vim 的核心设计是**多模式**：同样的按键，在不同模式下含义完全不同。新手容易栽在这——以为自己在输入，其实普通模式下按下的每个键都是命令，改乱了还退不出去。

1. **普通模式（Normal）**：打开文件后的默认模式，此时按下的每个键都被解释为命令（移动、删除、复制等），而不是输入文本。
2. **插入模式（Insert）**：只有在这个模式下敲键才是输入文本。屏幕左下角显示 `-- INSERT --`。
3. **可视模式（Visual）**：先选中一片文本，再对其执行操作（删除、复制、缩进等）。
4. **命令行模式（Command-line，又称末行模式）**：屏幕底部输入 `:`、`/` 或 `?` 开头的命令，回车后执行，执行完回到普通模式。

模式切换的文字流程图：

```text
普通模式 --按 i/a/o/I/A/O--> 插入模式 --按 Esc--> 普通模式
普通模式 --按 v/V/Ctrl+v--> 可视模式 --按 Esc--> 普通模式
普通模式 --按 : 或 / 或 ?--> 命令行模式 --按 Enter--> 普通模式
普通模式 --按 R--> 替换模式（输入即覆盖） --按 Esc--> 普通模式
```

记忆口诀：**Esc 是家**——不管在哪个模式，按 `Esc` 都能回到普通模式；`:wq` 是门——从普通模式进入命令行模式保存退出。

| `o` | 普通 → 插入 | 在光标**下方**新建一行并插入 |
| `O` | 普通 → 插入 | 在光标**上方**新建一行并插入 |
| `R` | 普通 → 替换 | 进入替换模式，输入内容逐字覆盖原有字符 |

### 常用移动命令表

| 命令 | 移动目标 |

| `h` / `j` / `k` / `l` | 左 / 下 / 上 / 右（可配合数字前缀，如 `5j` 向下 5 行） |
| `w` / `W` | 跳到下一个单词 / 下一个大单词（跳过标点） |
| `b` / `B` | 跳到上一个单词 / 上一个大单词 |
| `e` | 跳到当前单词末尾 |
| `0` / `^` / `$` | 行首 / 行首第一个非空字符 / 行尾 |
| `gg` / `G` | 文件头 / 文件尾（`10G` 跳到第 10 行，`:10` 等价） |
| `Ctrl + d` / `Ctrl + u` | 向下 / 向上翻半屏 |
| `Ctrl + f` / `Ctrl + b` | 向下 / 向上翻一屏 |
| `f{字符}` / `F{字符}` | 行内向后 / 向前查找指定字符并跳过去 |
| `%` | 在配对的括号（`()`、`{}`、`[]`）之间跳转 |
| `H` / `M` / `L` | 跳到屏幕的顶部（High）、中部（Middle）、底部（Low） |

### 删除命令表

删除命令的基本结构是"删除范围 = 次数 + 删除符 + 移动目标"，例如 `d2w` 表示删除两个单词——这个组合规律实际敲一遍就明白，不用死记表格：

| 命令 | 删除范围 |
| --- | --- |
| `x` / `nx` | 删除光标处字符 / 删除光标处起 n 个字符 |
| `X` | 删除光标**前**一个字符 |
| `dw` | 删除一个单词（含后面空格） |
| `dd` | 删除光标所在行 |
| `ndd` | 删除光标所在行起共 n 行 |
| `d$` 或 `D` | 删除光标到行尾的内容 |
| `d0` | 删除光标到行首的内容 |
| `dG` | 删除光标到文件末尾的所有行 |
| `dgg` | 删除光标到文件开头的所有行 |
| `dj` / `dk` | 删除当前行与下一行 / 上一行 |
| `diw` | 删除光标所在单词（i = inner，vim 文本对象） |

> **注意：** 所有被删除的内容都进入了寄存器，可以用 `p` 粘贴回来——`dd` 删除一行再 `p` 粘贴，效果就是"剪切 + 移动"。

### 复制与粘贴命令表

复制（yank，y 开头）与删除结构相同：

| 命令 | 复制范围 |
| --- | --- |
| `yy` 或 `Y` | 复制光标所在行 |
| `nyy` | 复制光标所在行起共 n 行 |
| `yw` | 复制一个单词 |
| `y$` | 复制光标到行尾 |
| `yG` / `ygg` | 复制光标到文件尾 / 文件头的内容 |
| `v` + 移动 + `y` | 先选中再复制（可视模式通用做法） |
| `p` | 粘贴到光标**后**（复制整行时粘贴到**下一行**） |
| `P` | 粘贴到光标**前**（复制整行时粘贴到**上一行**） |
| `np` | 粘贴 n 次 |
| `"ayy` / `"ap` | 复制到命名寄存器 a / 从寄存器 a 粘贴（26 个字母寄存器可同时保存多份内容） |

粘贴前先瞄一眼寄存器里有什么：`:registers` 一次列出全部内容，避免粘错块。

vim 还有 0~9 号数字寄存器：最近一次删除或复制的完整行进 `"0`，更早的依次往后挤到 `"1`~`"9`。`dd` 删了一大片想找回？`"1p` 就能捞回来，比 `u` 撤销更精准——撤销会连带后续操作一起回退，寄存器粘贴只取你要的那一块。

### 查找命令表

| 命令 | 功能 |
| --- | --- |
| `/pattern` | 向下查找匹配 pattern 的内容 |
| `?pattern` | 向上查找匹配 pattern 的内容 |
| `n` | 跳到下一个匹配项 |
| `N` | 跳到上一个匹配项 |
| `*` | 快速查找光标所在单词，向下 |
| `#` | 快速查找光标所在单词，向上 |
| `:nohlsearch`（简写 `:noh`） | 临时取消搜索高亮 |
| `:set hlsearch` / `:set nohlsearch` | 开启 / 关闭搜索结果高亮 |
| `:set incsearch` | 开启输入即匹配的增量搜索 |

> **注意：** 搜索内容支持正则表达式，如 `/^error` 查找行首是 error 的行，与《基础正则表达式》一章的知识完全通用。

### 替换命令表

替换在命令行模式下执行，基本格式为 `:[范围]s/旧内容/新内容/[标志]`：

| 命令 | 功能 |
| --- | --- |
| `:s/old/new/` | 替换当前行第一个匹配项 |
| `:s/old/new/g` | 替换当前行所有匹配项 |
| `:%s/old/new/g` | 替换全文所有匹配项（`%` 表示所有行） |
| `:10,20s/old/new/g` | 只替换第 10 到 20 行 |
| `:%s/old/new/gc` | 全文替换但每处都要求确认（c = confirm） |

`c` 确认模式里的按键：`y` 换、`n` 跳过、`a` 剩下全换、`q` 停止——记住 `a` 和 `q`，大规模替换少敲一半键。
| `:%s/old/new/gi` | 全文替换并忽略大小写（i = ignorecase） |
| `:%s/old/new/ge` | 忽略"未找到"的报错（e） |
| `:g/pattern/d` | 删除所有匹配 pattern 的行 |
| `:r` / `R` | 普通模式下替换单个字符 / 进入替换模式连续覆盖输入 |
| `cw` | 删除光标处单词并进入插入模式（change word，改词神器） |

> **注意：** 替换内容中出现 `/` 需要转义，也可以用 `#` 作分隔符避免转义，如 `:%s#/usr/local#/opt#g`。

### 行号设置

| 命令 | 功能 |
| --- | --- |
| `:set number`（`:set nu`） | 显示绝对行号 |
| `:set nonumber`（`:set nonu`） | 关闭行号 |
| `:set relativenumber`（`:set rnu`） | 显示相对行号（当前行显示绝对行号，其余显示与光标的距离） |
| `:set number relativenumber` | 绝对 + 相对行号同时显示，配合 `5j`、`dd` 等带数字的命令极高效 |

相对行号的妙处在组合：`:set rnu` 后 `d5j`、`y3j` 这类"数字 + 移动"不再需要心算绝对行号，删除复制的速度快一倍。

行号只在当前会话有效，写入 `.vimrc` 可永久生效（见下文）。

编辑 Makefile 时有个例外要记住：Makefile 的命令行必须是真实 tab 字符，`expandtab` 会坏事——编辑前临时 `:set noexpandtab`。

### 撤销与重做

| 命令 | 功能 |
| --- | --- |
| `u` | 撤销上一步操作（可连续撤销多步） |
| `Ctrl + r` | 重做被撤销的操作（redo） |
| `U` | 撤销对当前行做的全部修改 |
| `:undolist` | 查看撤销历史分支 |
| `.` | 重复执行上一次的修改操作（如删了一行后，移到别处按 `.` 再删一行） |

vim 支持**多级撤销**（vi 只能撤销一步），配合 `u` 与 `Ctrl + r` 可以在编辑历史中自由穿梭。

### 拓展：块可视模式与批量加注释

`Ctrl + v` 块可视模式配 `I` / `A`，能在选中的每一行行首/行尾同时插入内容。给几十行配置统一加 `#` 注释是经典用法：`Ctrl + v` 选中行 → 按 `I` 输入 `# ` → 按 `Esc`，所有行同时生效。删注释反向操作一遍即可。`gv` 重选上次的选区，圈错了不用重新圈；普通模式下 `Ctrl + o` / `Ctrl + i` 在跳转位置之间后退、前进，翻配置文件来回跳很顺手。

### vim 配置文件 .vimrc

`.vimrc` 是 vim 的用户级配置文件，位于用户家目录（`~/.vimrc`），每次启动 vim 时自动读取，把临时设置固化为永久配置。常用配置项如下（`"` 开头为注释）：

```ini
" 显示行号：绝对 + 相对
set number
set relativenumber
" 开启语法高亮
syntax on
" 缩进设置：制表符宽度 4，自动缩进 4，用空格代替制表符
set tabstop=4
set shiftwidth=4
set expandtab
set autoindent
" 高亮当前行
set cursorline
" 搜索：忽略大小写（有一个大写字母时自动区分）、增量搜索、高亮
set ignorecase
set smartcase
set incsearch
set hlsearch
" 光标遇到括号时短暂闪现匹配
set showmatch
" 文件编码
set encoding=utf-8
" 总是显示状态栏
set laststatus=2
" 长行不折行显示
set nowrap
```

改完 `.vimrc` 后重新打开 vim 即生效，或在 vim 内执行 `:source ~/.vimrc` 立即加载。

自定义快捷键也写在这里：`:map <F2> :w<CR>` 让 F2 等于保存。重复性的编辑动作可以录宏——`q` + 寄存器名开始录制，再按 `q` 结束，`@寄存器名` 回放，配合数字能重复 n 次，批量改格式时省一半时间。录宏前先让光标回到行首（按 `0`），否则第二轮回放位置错位——宏翻车多半栽在这。

### 拓展：为什么我的 vim 没有语法高亮

三个常见原因依次排查：装的是 vim-minimal 精简版，`yum install -y vim` 换完整版；`TERM` 变量不对，远程工具里设成 xterm-256color；`.vimrc` 里没写 `syntax on`。`vim --version | grep clipboard` 还能看是否支持系统剪贴板——不支持的话，`"+y` 复制到系统剪贴板的功能用不了，跨程序粘贴文本得靠终端自身的复制。

### 异常恢复：swap 文件处理

vim 编辑时会为打开的文件生成一个隐藏的交换文件（如 `.file.txt.swp`），用于崩溃后恢复未保存的修改。异常退出（断电、强制关闭终端）后，交换文件会残留，下次打开文件就会报错：

```console
E325: ATTENTION
found a swap file by the name ".file.txt.swp"
...
Swap file ".file.txt.swp" already exists!
[O]pen Read-Only, (E)dit anyway, (R)ecover, (D)elete it, (Q)uit, (A)bort:
```

处理方式：

| 选项 | 含义 | 适用场景 |
| --- | --- | --- |
| `O` | 以只读方式打开 | 只想查看内容，不做修改 |
| `E` | 直接编辑，忽略交换文件 | 确认没有其他 vim 进程在编辑该文件 |
| `R` | 恢复（使用交换文件中的内容） | 上次异常退出，想找回未保存的修改 |
| `D` | 删除交换文件后正常打开 | 确认不需要恢复 |
| `Q` / `A` | 退出 / 放弃操作 | — |

> **注意：** 出现该提示时，先用 `ls -la .file.txt.swp` 确认没有另一个用户或终端正在编辑同一文件（生产服务器上可能是他人误操作），再选择 `R` 恢复或 `D` 删除；也可以直接 `rm` 掉该交换文件。平时正常用 `:wq` 退出，交换文件会自动清除，不会出现该提示。

其他异常场景的处理：

| 场景 | 命令 |
| --- | --- |
| 改乱了想放弃所有修改重新加载 | `:e!` |
| 从崩溃中恢复未保存内容 | `:recover` |
| 缓冲区被修改过不让退出 | 确认不需要保存，用 `:q!` 强制退出 |

### vim 与 sed、vi 的关系

| 维度 | vi | vim | sed |
| --- | --- | --- | --- |
| 交互性 | 交互式全屏编辑 | 交互式全屏编辑 | 非交互式，按行流式处理 |
| 撤销能力 | 仅一级撤销 | 多级撤销 + 恢复 | 无撤销概念 |
| 使用方式 | 手工逐字修改 | 手工修改 + 脚本化能力 | 写进脚本批量处理文件 |
| 典型场景 | 老系统应急 | 日常修改配置文件、写代码 | 批量替换、提取字段等自动化任务 |

三者的渊源：vi 的底层是 ex 行编辑器（`:1,$s/a/b/` 这样的命令原本就是 ex 的命令），sed 正是"stream editor"，把 ex 的行编辑思想非交互化。所以 vim 的命令行模式命令与 sed 命令长得像，不是巧合。

vim 还可在编辑过程中直接调用外部命令，与 sed 等工具协作：

```bash
" 在 vim 内执行外部命令
:!ls -l
" 把当前文件内容通过 sort 排序后写回（% 表示全文，! 表示过滤）
:%!sort
" 把 df -h 的输出插入到光标处
:r!df -h
```

vim 也可以非交互地执行命令，但脚本场景优先用 sed/awk：

```bash
vim -c '%s/old/new/g' -c 'wq' file.txt
```

## 原理解析：vim 为什么设计成多模式

1. **终端时代的遗产**：早期终端只有字符能力，没有鼠标和菜单栏，vim 用模式区分"操作"和"输入"——普通模式下几十个键全是快捷命令，省去鼠标和功能键，双手不离主键区。
2. **动词 + 宾语的语言化设计**：`d`（删除）是动词，`w`（词）、`$`（行尾）、`G`（文件尾）是宾语，`3dd` 的 `3` 是量词——命令像自然语言一样组合，比"选中再点删除"更快。
3. **寄存器机制**：删除即剪切、复制进寄存器，配合 `p` 粘贴，移动文本不需要"选中 → 复制 → 定位 → 粘贴"四步。

跨文件搬运也是寄存器的强项：`:sp 文件2` 开两个窗口，这边 `yy` 那边 `p` 就完成复制——不需要退出重进。同一个会话里所有缓冲区共享寄存器，多个文件来回搬内容很顺。

## 常见错误与排错

| 现象 | 可能原因 | 排查命令 | 解决方式 |
| --- | --- | --- | --- |
| 打开文件提示 `E325: found a swap file` | 上次异常退出残留 `.swp` 交换文件，或有其他进程正在编辑 | `ls -la .file.txt.swp` | 确认无其他编辑者后选 `R` 恢复未保存修改，或选 `D` 删除交换文件 |
| 从别处粘贴的代码缩进全部错乱 | autoindent 自动缩进与粘贴内容原有的缩进叠加 | `:set list` 查看不可见字符 | 粘贴前执行 `:set paste`，粘贴后 `:set nopaste`；或 `:set noai` 关闭自动缩进 |
| 保存时报 `E45: 'readonly' option is set` | 当前用户对文件没有写权限 | `ls -l 文件名` | 切换到有权限的账号；或用 `:w !sudo tee %` 借 sudo 保存 |
| 按方向键出现 ABCD 字符 | 使用的是精简版 vi 或终端类型不兼容 | `vim --version`、`echo $TERM` | 用 `hjkl` 代替方向键；安装完整版 `vim` 软件包 |
| 搜索后满屏高亮影响阅读 | 默认开启 hlsearch | `:set hlsearch?` | 执行 `:noh` 临时取消，或 `:set nohlsearch` 永久关闭 |
| 不知道自己在哪个模式，改错后无法退出 | 模式概念不清，误触按键 | 观察左下角是否显示 `-- INSERT --` | 先按 `Esc` 回普通模式，再 `:q!` 不保存退出重新来 |

> **补充：** 表里那条 `:w !sudo tee %` 值得拆开看原理：`:w !命令` 表示把缓冲区内容通过管道喂给外部命令，`tee %` 里的 `%` 会被展开为当前文件名——等于用 root 权限把内容重写了一遍，所以只读文件也能存。

## 现代环境补充

1. **版本现状**：vim 8.x / 9.x 是当前主流版本，Linux 发行版仓库直接可装（`dnf install vim` 或 `apt install vim`）；vim 9 引入了 vim9script，脚本执行速度大幅提升。
2. **Neovim**：vim 的现代化分支，内置 LSP（语言服务器协议）、终端分屏、异步插件，配置使用 Lua。追求极致效率的开发者常选它，但传统 vim 仍是服务器运维的基本盘。
3. **远程开发场景**：VS Code 等 IDE 都有 Vim 模式插件（如 vim-mode），本地用图形 IDE、服务器上用 vim，是当下常见的混合工作流。
4. **分工原则**：人工精细编辑用 vim，脚本化批量处理用 sed/awk，不要用 vim 做本该由脚本完成的事（比如在 vim 里逐行 `dd` 删除，不如一条 `sed` 或 `grep -v`）。
5. **容器与云环境**：容器镜像为瘦身常不带编辑器，应急时可用 `sed -i` 临时顶替，但生产容器里建议至少装上 vim-minimal。

## 自测题

1. vim 中从插入模式返回普通模式按什么键？从普通模式保存退出用什么命令？
2. 删除光标所在行及其下方共 4 行，命令是什么？
3. 把文件中所有 `old` 替换为 `new`，且每处都要求确认，命令是什么？
4. 打开文件提示 "found a swap file" 是什么原因？如何处理？
5. vim 与 sed 的核心区别是什么？

> **答案：** 1. 按 `Esc`（或 `Ctrl + `）返回普通模式；保存退出用 `:wq`（或 `ZZ`）。2. `4dd`（次数 + 删除符的组合用法）。3. `:%s/old/new/gc`，其中 `%` 表示全文，`g` 表示行内所有匹配，`c` 表示逐条确认。4. 上次异常退出残留了交换文件 `.swp`（或该文件正被其他 vim 进程编辑）；先用 `ls -la` 确认无其他编辑者，再选 `R` 恢复未保存内容或 `D` 删除交换文件。5. vim 是交互式全屏编辑器，需要人实时操作；sed 是非交互式流编辑器，按行自动处理，适合写进脚本批量执行。

## 小结

1. 技术文档优先用"样式"建立标题层级，而不是手工调整字号。
2. 正文、标题、编号三者的样式要提前统一，后续修改只需改样式。

4. 对照型、速查型内容优先用表格承载。
5. 文档中的命令与代码要单独成块并使用等宽字体，防止被编辑器的自动排版改写。
6. vim 是 vi 的增强版，CentOS 中 `vi` 命令由 vim-minimal 提供；vim 交互式编辑，sed 非交互式流处理，二者互补。
7. vim 四种模式：普通、插入、可视、命令行；`Esc` 永远回到普通模式，`:wq` 保存退出，`:q!` 不保存退出。
8. 常用命令成体系记忆：移动 `hjkl/w/b/gg/G`，删除 `x/dd/dw/d$`，复制 `yy/yw/y$`，粘贴 `p/P`，撤销 `u`，重做 `Ctrl + r`。
