## 一、上节回顾

### 1.1 系统用户权限

- 利用 sudo 方式进行普通用户提权；
- 利用 Linux 系统特殊权限位配置普通用户权限：
  - **setuid（4XXX）**：将文件数据的属主权限，赋予其他所有的用户。setuid 权限一般赋予二进制的命令文件或者一些可执行的脚本文件；
  - **setgid（2XXX）**：将文件数据的属组权限，赋予其他所有的用户；
  - **粘滞位**：创建一个共享目录，共享数据只能互相查看，不能互相随意修改。

补充：脚本如何执行

```bash
01. 借助解释器命令执行脚本
    sh /server/scripts/xxx.sh
    python /server/scripts/xxx.py
02. 直接执行脚本（当成命令执行）
    将脚本文件赋予执行权限
    /server/scripts/xxx.sh
    /server/scripts/xxx.sh --> PATH
    xxx
```

### 1.2 系统中重要数据信息如何加锁

```bash
chattr  +i  文件信息
chattr  -i  文件信息
lsattr  文件信息
```

### 1.3 定时任务实现方式

1. 系统自带定时任务（4 个特殊的目录）；
2. 用户自己设定定时任务（一个命令 `crontab`，三个文件：日志文件、配置文件、黑名单文件）。

### 1.4 定时任务配置方法与注意事项

```bash
crontab -e
* * * * *     命令信息
定时时间信息
```

时间的表示方法：

```bash
直接用数值表示：00 02 * * *
可以用符号表示：*  */n  n,m  n-m
```

> **注意：** 星期信息不要和日期信息同时设置。

编写注意事项：

1. 定时任务编写时需要加注释信息；
2. 文件的路径尽量采用绝对路径；
3. 命令信息最好也要用绝对路径；
4. 编写定时任务尽量在后面加上重定向黑洞 `&>/dev/null`：
   - 如果开启邮件服务 postfix：输出的信息 >> `/var/spool/mail/root`（block 空间不足）；
   - 如果关闭邮件服务 postfix：输出的信息 >> `/var/spool/postfix/maildrop/` 小文件（inode 空间不足）；
5. 尽可能让命令不要产生正确或错误的输出信息，如 `tar zcvf` 改为 `tar zcf`；
6. 多个定时任务命令，最好使用脚本实现；
7. 定时任务中无法识别任务中的一些特殊符号，两种解决方式：

```bash
# 解决方式一：利用转义符号
* * * * *  /bin/date "+\%F \%T" >/tmp/time.txt

# 解决方式二：利用脚本编写任务
vim /server/scripts/date.sh
/bin/date "+%F %T"

* * * * *  /bin/sh /server/scripts/date.sh &>/dev/null
```

| 02 | 磁盘阵列说明（raid0 / raid1 / raid5 / raid10 / raid01）；磁盘阵列如何配置；配置 LVM（L 逻辑、V 卷组、M 管理，逻辑卷管理，实现可以随意调整磁盘分区大小） |

## 三、磁盘物理结构

### 3.1 外部结构：看得见摸得到的结构

| 组成 | 说明 |
| --- | --- |
| 磁盘主轴 | 决定磁盘转速（rpm - round per minute）；家用磁盘 7200 rpm / 5400 rpm，企业磁盘 15k rpm / 10k rpm |
| 磁盘盘片 | 用于存储数据 |
| 磁盘磁头 | 用于读取数据 |
| 磁盘接口 | 用于连接主板、连接阵列卡 |

常见接口类型对照：

| 接口 | 理论速率 | 常见场景 | 现状 |
| --- | --- | --- | --- |
| IDE（PATA） | 133 MB/s | 早年家用机、老服务器 | 已淘汰 |
| SATA | 6 Gb/s（实际约 550 MB/s） | 家用台式机、入门服务器 | 主流廉价接口 |
| SCSI | 320 MB/s | 老企业服务器 | 已被 SAS 取代 |
| SAS | 6 Gb/s / 12 Gb/s | 企业级机械硬盘、阵列 | 当前企业主流 |
| USB | 480 Mb/s（2.0）到 10 Gb/s（3.1） | 移动硬盘 | 外置场景 |
| FC（光纤通道） | 8 / 16 Gb/s | 存储区域网络（SAN） | 高端存储 |
| NVMe（PCIe / M.2 / U.2） | PCIe 3.0 x4 约 3.5 GB/s | 固态硬盘、数据库加速 | 当前高性能主流 |

> **注意：** 接口速率是总线能力，机械硬盘的瓶颈在内部机械结构（寻道），所以 15k rpm 的 SAS 盘随机读写也只有每秒一两百 IOPS，随机 I/O 密集场景应直接选 NVMe 固态。

选购一句话：系统盘与低负载业务 SATA 够用，数据库、虚拟化这类 I/O 密集业务直接上 NVMe，容量型存储用大容量 SATA 组阵列。

### 3.2 内部结构：看不见的结构信息

| 组成 | 作用与特点 |
| --- | --- |
| 磁盘（Disk） | — |
| 磁头（Head） | 用来写入和读取数据；盘面数量等于磁头数量；采用径向运动读写数据 |
| 磁道（Track） | 用来存储用户数据；由多个同心圆组成；最外面同心圆为 0 磁道；磁盘默认按照磁道寻找数据。**磁头径向运动为机械运动（寻道），性能小于固态硬盘（芯片），机械运动较慢** |
| 扇区（Sector） | 用来存储用户数据；磁盘存储最小单位；默认从 1 扇区开始，扇区大小为 512 字节（系统存储最小单位是 block） |
| 柱面（Cylinder） | 用来存储用户数据；由不同盘面上相同的磁道组成（圆柱体）；磁盘默认按照柱面进行读写。**磁头之间的切换为电子切换，电子切换较快** |
| 单元块（Units） | 用来存储用户数据；表示单个柱面大小 |

> **注意：** 磁盘读写的耗时主要来自磁头的机械寻道，这也是机械盘远慢于固态盘的根本原因；而多盘面之间的切换是电子切换，速度很快。

补充说明：现代大容量硬盘普遍采用 4Kn（4096 字节扇区）的高级格式，性能与容量效率更好；分区工具的默认对齐值（1 MiB）就是为配合大扇区设计的，对齐不当会显著降低写入性能。

机械盘一次 I/O 的耗时由三段组成：寻道时间（磁头移到目标磁道）、旋转延迟（盘片把目标扇区转到磁头下）、数据传输时间。前两项是纯机械开销，占响应时间的大头——转速越高随机 IOPS 越高，同一块盘顺序读写远快于随机读写，根源都在这里。

## 四、磁盘阵列 RAID

阵列的作用：

1. 提高磁盘存储效率；
2. 提高磁盘存储安全；
3. 提高磁盘存储容量。

三条作用对应三种手段：性能靠条带化，安全靠镜像或校验，容量靠多盘聚合。没有一种 RAID 能三者全占，选型就是在做取舍。

常见阵列级别：

| 级别 | 特点 |
| --- | --- |
| raid 0 | 存储数据效率高，存储安全性低 |
| raid 1 | 存储数据效率低，存储安全性高 |
| raid 5 | 存储数据效率较高，存储安全性较高 |

> **注意：** raid 5 至少需要 3 块磁盘，阵列中最多只能坏一块磁盘，并损耗一块磁盘的容量，例如 300G + 300G + 300G 做 raid 5 后可用容量约 600G。

扩展两个企业常见的组合级别：

| 级别 | 最少磁盘 | 特点 |
| --- | --- | --- |
| raid 10（1+0） | 4 | 先镜像再条带，安全与性能兼顾，可用容量为总容量的一半 |
| raid 01（0+1） | 4 | 先条带再镜像，可靠性不如 raid 10，已少用 |

### 辨析：RAID5 与 RAID10 {: .sec-bianxi}

两者都兼顾安全与性能，差别在容量效率与写入方式：

- **容量效率**：raid 5 只损耗一块盘的容量（4 块 1T 可用约 3T），raid 10 直接减半（可用 2T）；
- **随机写性能**：raid 5 每次写入都要计算校验并落盘，小数据量随机写有明显的写惩罚；raid 10 写两份镜像即可，没有校验计算；
- **重建窗口**：raid 5 重建要读全组数据重算校验，盘越大耗时越久，期间再坏一块就全丢；raid 10 重建只是整盘复制，快得多。

数据库、虚拟化这类随机 I/O 重的负载普遍选 raid 10——花一半容量，换稳定的写性能与更短的重建窗口；日志、备份这类顺序写为主的场景，raid 5 的容量优势才划算。raid 01 先条带再镜像，一块盘故障会让整个条带组失去保护，所以企业里基本只见到 raid 10。

还有一个角色叫 **hot spare（热备盘）**：平时挂在阵列里不承载业务，组内任何一块盘故障后自动顶上开始重建，把"等人换盘"的时间从小时级压到分钟级，是生产阵列的标准配置。

说白了：要容量选 raid 5，要稳要快选 raid 10。

### 辨析：RAID 与 LVM {: .sec-bianxi}

初学者常把两者混为一谈，其实分工不同：

- **RAID 解决"盘坏了数据别丢、性能别崩"**：靠镜像或校验做冗余，作用在多块物理盘之间，由 RAID 卡或 `mdadm` 实现；
- **LVM 解决"分区大小要能随业务改"**：把 PV 聚合成存储池再切 LV，本身不做冗余，作用在分区与文件系统之间。

生产环境两者是叠加关系：底层先用 RAID 保证可靠性，再在 RAID 卷上做 PV/VG/LVM 提供弹性。只在 LVM 里做"镜像 LV"而不做 RAID 能实现但不推荐，排错和维护成本都高。查阵列状态：硬 RAID 用 RAID 卡工具（如 `MegaCli`、`storcli`），软 RAID 看 `/proc/mdstat`。一句话：RAID 管的是"物理上稳不稳"，LVM 管的是"逻辑上灵不灵"。

LVM 负责分区的弹性缩容和扩容。

> **注意：** RAID 可以由硬件 RAID 卡实现（推荐，带电池 / 闪存缓存），也可以用 Linux 的 `mdadm` 做软 RAID（不占硬件成本，但消耗 CPU）。两种方式对上层都表现为一块普通磁盘，分区与格式化步骤完全相同。

## 五、磁盘分区方法

### 5.1 预备知识一：系统启动引导记录

```bash
MBR 引导记录   用于引导磁盘空间小于 2T
GPT 引导记录   用于引导磁盘空间大于 2T
```

MBR 与 GPT 的详细对比：

| 对比项 | MBR | GPT |
| --- | --- | --- |
| 所在位置 | 磁盘第一扇区（LBA 0） | 第二扇区（LBA 1）起，磁盘末尾有备份 |
| 分区数量 | 最多 4 个主分区（或 3 主 + 1 扩展） | 默认最多 128 个分区 |
| 单分区容量 | 最大 2TB（2^32 × 512 字节） | 理论可达 ZB 级，实际受文件系统限制 |
| 引导方式 | 传统 BIOS + MBR | UEFI + GPT（传统 BIOS 也可引导 GPT） |
| 数据结构 | 512 字节内嵌分区表（64 字节，每项 16 字节） | 独立分区表区 + CRC32 校验，可自愈 |
| 分区工具 | `fdisk`、`parted` | `gdisk`、`parted`、新版 `fdisk` |

选择原则很简单：容量小于 2T 用 MBR（`fdisk`），大于 2T 必须用 GPT（`parted`）；新硬件的 UEFI 安装也要求 GPT。MBR 的引导记录与分区表在一起，一旦第一扇区损坏整个分区表丢失，所以重要数据建议定期备份分区表（`sfdisk -d /dev/sda > sda.pt`）。GPT 还会在磁盘末尾存一份分区表备份，主分区表损坏时可用 `gdisk` 恢复，这是它比 MBR 抗造的重要原因。

### 5.2 预备知识二：分区方式

**情况一：划分 4 个主分区**

```bash
/dev/sda  /dev/sda1 .. sda4   mount /dev/sda1  /mnt
```

**情况二：划分 3 个主分区 + 1 个扩展分区**

```bash
可以划分 3 个主分区    /dev/sda  /dev/sda1 .. sda3
可以划分 1 个扩展分区   扩展分区无法直接使用
需要在扩展分区基础上划分逻辑分区：/dev/sda5 /dev/sda6 ...
```

三种分区的定位：

| 分区类型 | 编号 | 能否直接使用 | 说明 |
| --- | --- | --- | --- |
| 主分区 | sda1 - sda4 | 能 | 最多 4 个，可直接格式化挂载 |
| 扩展分区 | sda1 - sda4 中占一个 | 不能 | 只是一个"容器"，自身不能格式化 |
| 逻辑分区 | 从 sda5 开始 | 能 | 建在扩展分区内部，编号从 5 起 |

分区类型 ID 速查（`fdisk` 交互模式下用 `t` 修改）：`83` Linux（普通数据分区）、`82` Linux swap、`8e` Linux LVM、`fd` Linux RAID 自动、`5` 扩展分区、`ee` GPT。

生产环境的常见做法：系统盘单独一块，数据盘整盘只建一个分区交给 LVM 管理，后续扩容加盘加 PV 即可，不用纠结主分区数量限制。MBR 的 4 主分区上限主要影响老机器与小容量盘。

设备命名规律也值得记一下：SATA/SAS/SCSI 盘按发现顺序命名为 `/dev/sda`、`/dev/sdb`，字母顺序不保证与物理插槽一一对应，热插拔后可能漂移——这正是 fstab 推荐写 UUID 的原因；需要稳定命名可用 `/dev/disk/by-id/`。NVMe 盘则是 `/dev/nvme0n1`（第 0 块盘的第 1 命名空间），分区追加 `p1`，如 `nvme0n1p1`。

## 六、文件系统类型与格式化命令

### 6.1 常见文件系统对比

| 文件系统 | 日志 | 单卷最大 | 特点 | 适用场景 |
| --- | --- | --- | --- | --- |
| ext2 | 无 | 16 TB | 无日志，结构简单，掉电后修复慢 | 已少用，小容量 / 引导分区偶见 |
| ext3 | 有 | 16 TB | 在 ext2 上加日志，兼容性好 | 老系统存量，新部署不建议 |
| ext4 | 有 | 1 EB | extent 管理减少碎片、延迟分配、在线 resize（增长） | RHEL 6 默认，通用场景 |
| xfs | 有 | 8 EB | 分配组并行、大文件与高并发友好、在线增长，**不能缩减** | RHEL 7+ 默认，数据库 / 大文件 |
| btrfs | 有 | 16 EB | 写时复制快照、校验和、压缩、子卷 | openSUSE / Synology 常见；RHEL 8 起已移除 |

> **注意：** "单卷最大"是理论上限，实际选型更多看场景：RHEL/CentOS 7 及以后默认 xfs，格式化与存储效率更高，特别适合数据库与备份服务器；需要灵活快照等高级特性且不在 RHEL 8+ 环境时再考虑 btrfs。

### 6.2 创建文件系统：mkfs

创建文件系统，就是决定磁盘分区存储数据的方式，敲一遍就明白：

```bash
ext3/4  centos6
xfs     centos7  格式效率较高，数据存储效率提升（数据库服务器）
```

```bash
mkfs.xfs  /dev/sdb1          # 创建 xfs 文件系统
mkfs -t xfs /dev/sdb2        # 等价写法
mkfs.ext4 /dev/sdb3          # 创建 ext4 文件系统
mkfs -t ext3 /dev/sdb4       # 创建 ext3 文件系统
mkfs.vfat /dev/sdb5          # 创建 FAT 文件系统（U 盘、跨系统交换分区）
```

```bash
[root@linux-node1 /]# mkfs.xfs /dev/sdb2
meta-data=/dev/sdb2              isize=512    agcount=4, agsize=65536 blks
         =                       sectsz=512   attr=2, projid32bit=1
         =                       crc=1        finobt=0, sparse=0
data     =                       bsize=4096   blocks=262144, imaxpct=25
         =                       sunit=0      swidth=0 blks
naming   =version 2              bsize=4096   ascii-ci=0 ftype=1
log      =internal log           bsize=4096   blocks=2560, version=2
         =                       sectsz=512   sunit=0 blks, lazy-count=1
realtime =none                   extsz=4096   blocks=0, rtextents=0
```

xfs 工具链常用命令：

| 命令 | 作用 |
| --- | --- |
| `xfs_info /挂载点` | 查看文件系统详细信息（块大小、分配组、日志） |
| `xfs_growfs /挂载点` | 在线扩大已挂载的 xfs 文件系统（配合 LVM 扩容） |
| `xfs_repair /dev/sdb1` | 修复损坏的 xfs 文件系统（需先卸载） |
| `xfs_admin -L 卷标 /dev/sdb1` | 设置 / 查看卷标 |
| `xfs_freeze` | 冻结 / 解冻文件系统 I/O，配合快照备份保证一致性 |

ext 系列对应工具：`e2fsck -f /dev/sdb1`（修复）、`resize2fs /dev/sdb1`（在线调整大小，ext4 支持增长）、`dumpe2fs -h /dev/sdb1`（查看超级块信息）、`tune2fs -L 卷标 /dev/sdb1`（设卷标）。

## 七、挂载与开机自动挂载

```bash
mount /dev/sdb1 /mount01
mount /dev/sdb2 /mount02
```

检查确认：

```bash
[root@linux-node1 /]# df -h
/dev/sdb1      1014M   33M  982M   4% /mount01
/dev/sdb2      1014M   33M  982M   4% /mount02
```

挂载点选空目录。挂载生效后，原目录里的内容会被遮住（不是删除），卸载后恢复可见；往挂载点写数据前先确认挂载真的生效了，否则数据会落进底层目录，卸载时就像"消失了"。

mount 常用参数：

| 参数 | 作用 |
| --- | --- |
| `-t 类型` | 指定文件系统类型，不指定则自动识别 |
| `-o ro` / `-o rw` | 只读 / 读写挂载 |
| `-o remount,rw` | 不卸载直接重新以读写挂载（修复只读挂载） |
| `-a` | 按 `/etc/fstab` 挂载所有未挂载项 |
| `-o bind` | 绑定挂载，把一个目录映射到另一个位置 |
| `-L 卷标` / `-U UUID` | 按卷标 / UUID 挂载，比设备名稳 |

卸载用 `umount`，`umount -l`（lazy，强制断开，处理"设备忙"的最后手段）、`umount -f`（NFS 强制）。卸载报 `target is busy` 时别急着 kill 进程，先查是谁在占用：`lsof +D /mount01` 或 `fuser -mv /mount01`。这里有个坑：占用者常常是另一个 SSH 窗口 `cd` 进了挂载点，最隐蔽也最常见。

查看挂载状态的两个来源：

| 来源 | 说明 |
| --- | --- |
| `/proc/mounts` | 内核当前挂载表的实时快照，最权威 |
| `/etc/mtab` | 历史文件，现代系统是指向 `/proc/mounts` 的软链接 |
| `findmnt` | 友好查询工具，`findmnt /dev/sdb1` 按设备查，`findmnt -T /路径` 按路径查 |

排错时以 `/proc/mounts` 为准——它直接来自内核，不会说谎；`df`、`findmnt` 看到的信息最终都源于它。

```bash
findmnt /dev/sdb1            # 查看某设备的挂载点与参数
findmnt -T /home/ops         # 查看某路径所在文件系统
findmnt --fstab              # 只看 fstab 里配置的挂载项
```

### 7.1 方法一：将挂载命令放入 /etc/rc.local

```bash
[root@linux-node1 /]# tail -2 /etc/rc.local
mount /dev/sdb1 /mount01
mount /dev/sdb2 /mount02
```

系统开机加载 `rc.local` 的流程：

```bash
加载 /etc/rc.local --> /etc/rc.d/rc.local --> 以绝对路径方式执行
/etc/rc.d/rc.local
chmod +x /etc/rc.d/rc.local
```

> **注意：** CentOS 7 中 `/etc/rc.local` 是软链接，真正的文件 `/etc/rc.d/rc.local` 默认没有执行权限，必须 `chmod +x /etc/rc.d/rc.local` 才会生效。另外，rc.local 属于 systemd 的 `rc-local.service`，**不是推荐的挂载方式**：它执行晚、失败不重试、没有依赖管理。生产环境一律用 `/etc/fstab`，rc.local 只留给一次性初始化脚本。

### 7.2 方法二：在 /etc/fstab 文件中进行设置

```bash
UUID=e2fc8646-2b36-47cc-a35a-8c13208f4d0b /          xfs                 defaults            0             0
UUID=34fc45ba-c38c-42bc-a120-90f9d5dd2382 /boot      xfs                 defaults            0             0
UUID=62100743-6f8a-4f83-a37d-e2088c4830e2 swap       swap                defaults            0             0
挂载磁盘文件(存储设备)                   挂载点     指定文件系统类型   挂载的参数    是否备份磁盘  是否检查磁盘
```

```bash
mount 挂载的磁盘文件 挂载点
[root@linux-node1 ~]# tail -2 /etc/fstab
/dev/sdb1                                 /mount01                xfs     defaults        0 0
UUID=144738ff-0da3-4162-b574-40af379cbe9e /mount02                xfs     defaults        0 0
```

| 列 | 含义 |
| --- | --- |
| 第 1 列 | 挂载的磁盘文件（存储设备），可以用设备名或 UUID |
| 第 2 列 | 挂载点 |
| 第 3 列 | 指定文件系统类型 |
| 第 4 列 | 挂载的参数（defaults） |
| 第 5 列 | 是否备份磁盘 |
| 第 6 列 | 是否检查磁盘 |

最要小心的是设备名漂移。三个易错点：

1. **第一列优先用 UUID**：设备名（`/dev/sdb1`）会随磁盘顺序变化，UUID 是文件系统的唯一身份证，用 `blkid /dev/sdb1` 查看；
2. **第五列 dump 基本已废弃**，统一写 0；第六列 fsck 顺序：根分区写 1，其他写 2，swap、光盘、网络文件系统写 0（不检查）；
3. **第四列常用选项**：`defaults`（rw、suid、dev、exec、auto、nouser、async 的组合）、`noatime`（不更新访问时间，提升读性能）、`nofail`（设备不存在时开机不卡住，非系统盘推荐）、`_netdev`（网络文件系统专用，等网络就绪再挂载）。

## 八、容量查看：df 与 du

两个命令分工明确：df 看**文件系统**的剩余空间，du 看**目录 / 文件**占用了多少。

| 命令 | 作用 | 常用参数 |
| --- | --- | --- |
| `df -h` | 以人类可读单位查看各文件系统容量与使用率 | `-i` 查看 inode 使用率，`-T` 显示文件系统类型 |
| `du -sh 目录` | 统计目录总占用大小 | `-h` 可读单位，`-s` 只汇总 |
| `du -sh --max-depth=1 目录` | 按一级子目录分别统计，定位大目录 | `-a` 含隐藏文件，`-c` 加总计 |
| `du -sh 目录/* | sort -rh | head` | 找出目录内最占空间的项 | 组合排序技巧 |

```bash
# 磁盘报错 No space left on device 时的标准动作
df -h                      # 哪个文件系统满了（block 视角）
df -i                      # 是不是 inode 满了（大量小文件）
du -sh --max-depth=1 /var  # 一层层往下定位大目录
```

给 `du` 加 `-x` 可限制在同一文件系统内统计，`/proc`、NFS 这类跨挂载点不会被算进来，排查根分区时很实用。统计目录先 `du -sh` 总览、再 `--max-depth=1` 下钻，比一上来就全盘扫快得多。

df 与 du 的结果对不上，说白了是口径不同：df 统计的是文件系统已用块，du 统计的是文件可见大小；已删除但仍被进程占用的文件，df 算它、du 找不到它。这个场景的排查见《磁盘管理进阶》。

> **注意：** inode 耗尽时 df -h 可能显示还有大量剩余空间，但任何写文件都报 `No space left on device`——因为文件创建除了要 block 还要 inode，所以"磁盘满"必须同时看 `df -h` 与 `df -i`。

## 常见错误与排错

| 现象 | 可能原因 | 排查命令 | 解决方式 |
| --- | --- | --- | --- |
| 新硬盘在系统里看不到 | 未重新加载分区表，或虚拟化平台未添加磁盘 | `lsblk`；`partprobe /dev/sdb` | `partprobe` 重载；检查虚拟机硬件配置 |
| 分区后 `/dev/sdb1` 不存在 | 分区表未写入，或用了 `q` 退出未保存 | `fdisk -l /dev/sdb` | 重新分区并用 `w` 保存，再 `partprobe` |
| 挂载报 `wrong fs type` | 忘了格式化，或文件系统类型写错 | `blkid /dev/sdb1`；`file -s /dev/sdb1` | 先 `mkfs` 创建文件系统，fstab 类型写对 |
| 挂载报 `special device does not exist` | fstab 里设备名写错或盘序变化 | `blkid`；`ls /dev/disk/by-uuid/` | fstab 改用 UUID |
| 开机卡在 `A start job is running for /mount01` | fstab 配置错误，设备不存在且未加 `nofail` | `journalctl -b | grep mount` | 加 `nofail`；进救援模式修正 fstab |
| `No space left on device` 但 df 显示有空间 | inode 耗尽，或文件被删仍被进程占用 | `df -i`；`lsof | grep deleted` | 删小文件 / 重启或释放占用进程 |
| 卸载报 `target is busy` | 有进程在该目录工作或 shell  cd 在里面 | `lsof +D /mount01`；`fuser -mv /mount01` | 退出进程或目录，最后手段 `umount -l` |
| 分区超过 2T 报错 | 用 MBR 分区表分了大分区 | `parted -l` 看分区表类型 | 改用 GPT（`mklabel gpt`）后重新分区 |

## 现代环境补充

CentOS 7 已于 2024 年 6 月 EOL，新系统（Rocky Linux / AlmaLinux / CentOS Stream）磁盘领域的新旧对照：

| 旧做法 | 现代做法 | 说明 |
| --- | --- | --- |
| 只认 `/dev/sdX` | NVMe 固态为 `/dev/nvme0n1`，分区 `nvme0n1p1` | `lsblk` 一屏看全所有块设备 |
| `fdisk -l` 看盘 | `lsblk` + `lsblk -f`（看 UUID 与文件系统） | 更直观，树形展示 |
| `mount | grep xxx` 查挂载 | `findmnt` | 结构化输出，支持按路径 / 设备查 |
| `/etc/mtab` 当权威 | `/proc/mounts`（mtab 只是软链） | mtab 已被 procfs 取代 |

| `dd` 测盘性能 | `fio` 压测工具 | fio 能模拟真实 I/O 模型，结论更可靠 |

## 自测题

1. MBR 与 GPT 分区表的核心差异有哪些？2T 以上磁盘该用哪种？

> **答案：** MBR 位于第一扇区，最多 4 个主分区，单分区上限 2 TB，仅支持传统 BIOS 引导；GPT 分区表独立存放且末尾有备份，默认支持 128 个分区，单分区可达 ZB 级，配合 UEFI 引导并有 CRC 校验。2 TB 以上磁盘必须用 GPT。

2. 一块磁盘最多几个主分区？想要 6 个分区怎么规划？逻辑分区从几号开始？

> **答案：** MBR 下一块盘最多 4 个主分区。规划为 3 个主分区 + 1 个扩展分区，在扩展分区内部再建 3 个逻辑分区，逻辑分区编号从 5 开始（sda5、sda6……）。

3. ext4 与 xfs 各有什么典型特点？RHEL 7 及以后默认用哪个？

> **答案：** ext4 有日志、extent 管理减少碎片、支持在线增长（`resize2fs`），通用场景都适用；xfs 采用分配组并行处理，大文件与高并发写入性能更好，也支持在线增长（`xfs_growfs`）但不支持缩减。RHEL 7 及以后默认 xfs。

4. `/etc/fstab` 六列分别是什么？第一列为什么推荐用 UUID？

> **答案：** 依次是：设备（或 UUID）、挂载点、文件系统类型、挂载参数、是否 dump 备份、是否 fsck 检查。推荐 UUID 是因为设备名会随磁盘插拔顺序变化（sdb 可能变 sdc），UUID 是文件系统唯一标识，稳定可靠，用 `blkid` 查询。

5. `df -h` 显示还有很多空间，写文件却报 `No space left on device`，可能是什么原因？

> **答案：** 两种可能：① inode 耗尽——文件太多，`df -i` 会显示 inode 使用率 100%，需删除大量小文件；② 文件已被删除但仍被进程占用（df 统计已用块、du 找不到该文件），需 `lsof | grep deleted` 找到进程并释放或重启。

6. 数据库服务器的阵列选 raid 5 还是 raid 10？hot spare 起什么作用？

> **答案：** 优先 raid 10。数据库是随机 I/O 密集型负载，raid 5 每次写入都要计算并落盘校验，随机写性能差；重建时还要全组读盘、耗时长，期间再坏一块就丢数据。raid 10 写入只是双份镜像，性能稳定、重建快，代价是容量减半。hot spare（热备盘）平时不承载业务，组内任何一块盘故障后自动顶替重建，把故障恢复从"等人换盘"压缩到分钟级，是生产阵列的标准配置。

## 小结

1. 磁盘知识分 5 层：物理结构 → 阵列 / LVM → 分区 → 格式化（创建文件系统） → 挂载使用，排查磁盘问题也按这个顺序自上而下定位。
2. 内部结构记住四个概念：**磁道**（同心圆，最外是 0 磁道）、**扇区**（最小存储单位，512 字节）、**柱面**（不同盘面相同磁道组成）、**单元块**（单个柱面大小）。
3. 磁头径向运动寻道是机械运动（慢），磁头间切换是电子切换（快），这是机械盘的性能瓶颈所在。
4. RAID 用冗余换安全或用条带换性能：raid 0 快但不安全，raid 1 安全但容量减半，raid 5 折中（至少 3 块盘、最多坏 1 块、损耗 1 块盘容量）。
5. 分区前先确认容量：小于 2T 用 MBR + `fdisk`，大于 2T 用 GPT + `parted`。
6. 一块磁盘最多 4 个主分区；想要更多分区就要用"3 主分区 + 1 扩展分区"，再在扩展分区里划分逻辑分区（编号从 `sda5` 开始）。
7. 文件系统按场景选：ext4 通用，xfs 适合大文件与高并发（RHEL 7+ 默认），ext3/ext2 逐步淘汰，btrfs 在 RHEL 8 中已移除。
8. 挂载两步走：临时用 `mount`，永久写 `/etc/fstab`（六列，设备列推荐 UUID，非系统盘加 `nofail`）；rc.local 方式已不推荐。
9. `df` 看文件系统、`du` 看目录；"磁盘满"必须同时检查 block（`df -h`）与 inode（`df -i`）。
10. 查看挂载用 `findmnt` 与 `/proc/mounts`，卸载报 busy 用 `lsof +D` / `fuser -mv` 找占用进程。
11. 阵列选型是容量、安全、性能的取舍：raid 5 省容量但随机写有校验惩罚，raid 10 容量减半换来稳定写性能与快速重建，数据库类负载选 raid 10；热备盘（hot spare）自动顶替故障盘，生产标配。
