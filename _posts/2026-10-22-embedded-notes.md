嵌入式入门最容易卡在「裸机 → 实时操作系统」的跨越，这里整理一条相对平滑的学习路径，并把每个关键概念先给一句话定义，再展开。

## 裸机阶段

> **一句话定义**：裸机（Bare-metal）指不跑操作系统、代码从 `main` 开始顺序 / 前后台循环执行的开发方式，所有硬件资源由开发者直接管理。

- **时钟树**：MCU 用多路分频 / 倍频把单一高速晶振分配成各外设所需时钟的树状结构，是功耗与性能调配的总闸。
- **GPIO**：通用输入输出引脚，软件可配置为输入 / 输出 / 复用 / 模拟，是所有外设最底层的「手和脚」。
- **中断**：CPU 对异步事件的异步响应机制，暂停当前执行流转去执行 ISR（中断服务程序），处理完再返回。
- **定时器**：按设定周期产生溢出 / 比较事件的硬件计数器，用于延时、PWM、输入捕获、系统时基。

**实际示例**（寄存器翻转 LED，直观看到「手和脚」）：

```c
// STM32：直接操作 ODR 第 5 位（假设 LED 在 PA5）
GPIOA->ODR ^= (1u << 5);   // 取反一次 = 翻转一次电平
```

💡 原理：裸机常采用「前台-后台」模型——`main` 循环是后台，ISR 是前台；ISR 只置标志位，真正的处理放在后台循环里做，避免长时间关中断。

⚠️ 坑位：在中断里做 `printf`、长延时、复杂运算会拖垮实时性，甚至造成主循环「饿死」。

## 引入 RTOS

> **一句话定义**：RTOS（实时操作系统）是在确定时延内响应事件的抢占式多任务内核，把「轮询」变成「事件驱动」，让多个任务看似并行。

- **任务**：RTOS 中独立调度的最小执行单元，拥有自己的栈与优先级。
- **调度**：按优先级 / 时间片决定哪个任务获得 CPU 的算法；抢占式意味着高优先级任务就绪即夺走 CPU。
- **队列**：任务间 / 中断与任务间传递结构化数据的线程安全 FIFO。
- **信号量**：用于资源互斥与同步的计数器 / 令牌。

**实际示例**（FreeRTOS 用队列解耦生产者与消费者）：

```c
QueueHandle_t q = xQueueCreate(10, sizeof(int));
// 中断 / 任务里发送
xQueueSend(q, &val, 0);
// 任务里接收（阻塞等待，不占用 CPU 忙等）
xQueueReceive(q, &val, portMAX_DELAY);
```

🔍 辨析：`轮询`是「不断问你忙不忙」，`事件驱动`是「你忙完了叫我」——后者在等待期间 CPU 可以去干别的，效率和响应都更好。

✏️ 注意：每个任务要给足栈空间，并用 `uxTaskGetStackHighWaterMark()` 检查高水位线，防止栈溢出悄悄破坏邻居数据。

## 常见坑

- 在中断里做耗时操作 → 系统卡死
- 共享变量不加保护（关中断 / 互斥量）→ 偶发数据错乱
- `printf` 进中断 → 拖垮实时性

⚠️ 坑位：裸机里「全局变量被主循环和 ISR 同时改」是头号疑难杂症；RTOS 里则要用临界区或队列把数据交接串行化。

> 嵌入式不是「写 C」，而是「在资源受限下做确定性的事」。

## 新技术延伸

- **Zephyr RTOS**：模块化、设备树驱动、类 Linux 的 Kconfig/CMake 构建系统，一套代码适配多厂商 MCU，适合复杂 IoT 与需要长期维护的产品。
- **Rust + Embassy**：基于 `async/await` 的嵌入式异步框架，无标准库依赖、编译期内存安全、无数据竞争，适合高可靠固件与对安全性要求高的场景。
- **RISC-V MCU**：GD32V、ESP32-C6/H2、CH32 等开源指令集芯片快速成熟，降低授权成本，工具链（如 `riscv-gcc`、`probe-rs`）生态完善中。
- **边缘 AI / TinyML**：CMSIS-NN、TensorFlow Lite for Microcontrollers 让 Cortex-M 跑轻量推理（关键词唤醒、振动异常检测、视觉分类），把「感知」直接下沉到端侧。
- **Matter / Thread**：基于 IPv6 Thread 的跨生态智能家居互联协议，解决多品牌设备互通，正成为物联网固件的新标配能力。
