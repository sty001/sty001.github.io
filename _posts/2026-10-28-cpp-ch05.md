## 优先级与结合律：记三档就够
{: .sec-know}

先把完整表摊开，再讲怎么记才不累。同一档里默认从左到右结合，标了"从右到左"的我也单独点出来了：

| 级别 | 运算符 | 结合律 |
| --- | --- | --- |
| 1 | `::` | 无 |
| 2 | `a++` `a--` `f()` `a[]` `.` `->` `typeid` `const_cast` `dynamic_cast` `reinterpret_cast` `static_cast` | 从左到右 |
| 3 | `++a` `--a` `+a` `-a` `!` `~` `(T)e` `*p` `&x` `sizeof` `alignof` `new` `delete` `co_await` | 从右到左 |
| 4 | `.*` `->*` | 从左到右 |
| 5 | `*` `/` `%` | 从左到右 |
| 6 | `+` `-` | 从左到右 |
| 7 | `<<` `>>` | 从左到右 |
| 8 | `<=>` | 从左到右 |
| 9 | `<` `<=` `>` `>=` | 从左到右 |
| 10 | `==` `!=` | 从左到右 |
| 11 | `&` | 从左到右 |
| 12 | `^` | 从左到右 |
| 13 | `\|` | 从左到右 |
| 14 | `&&` | 从左到右 |
| 15 | `\|\|` | 从左到右 |
| 16 | `?:` `=` `+=` `-=` `*=` `/=` `%=` `<<=` `>>=` `&=` `^=` `\|=` `throw` `co_yield` | 从右到左 |
| 17 | `,` | 从左到右 |

十七档背不下来，也没必要背。我自己就按三档记：

- **最高档（1~4）**：作用域、各种后缀、各种一元前缀。共性就一条——它们都"贴着"操作数，优先级天然最高。
- **中间档（5~15）**：按"算术 → 移位 → 关系 → 相等 → 位 → 逻辑"顺下来就行。
- **最低档（16~17）**：条件、赋值、逗号，憋到最后才算。

中间档真正容易记反的只有两处，记牢这俩，剩下的括号兜底：

1. **移位比关系运算符高**。`a << 1 < b` 是 `(a << 1) < b`，不是 `a << (1 < b)`。
2. **`&` `^` `\|` 比 `==` 低**。`a & 1 == 0` 是 `a & (1 == 0)`，几乎肯定不是你想要的。这正是位运算判断标志位必须加括号的原因：`(flags & MASK) != 0`。

再说三条我自己常用的经验：

- 拿不准就加括号——它不花运行时代价，只多一个字符的可读性。
- `&&` 比 `\|\|` 优先级高，`a \|\| b && c` 实际是 `a \|\| (b && c)`——但这种写法本身就该在 review 时被拦下来。
- 一元运算符和 `*` 的组合最容易看走眼：`*p++` 是 `*(p++)`（后置 `++` 级别更高），`*++p` 是 `*(++p)`。

> **坑：** `a[i] = i++` 这种写法，在 C++17 之前是未定义行为。C++17 给赋值补了"右操作数先于左操作数"的顺序保证，于是它有定义了——但结果全看顺序规则，读代码的人根本算不出来。细节见 5.5.3。
{: .sec-pit}

## 5.1 赋值运算符
{: .sec-expl}

### 5.1.1 赋值是表达式，不是语句
{: .sec-know}

在 C 系语言里 `a = b` 是个**表达式**，自带值（赋值后左操作数的左值引用）。这就引出两个你能直接用的后果：链式 `a = b = c`，以及把赋值塞进别处，比如 `while ((c = getchar()) != EOF)`。

```cpp
// assign_expr.cpp —— 需要 -std=c++20
#include <iostream>

int main() {
    int a, b, c;
    a = b = c = 7;                 // 右结合：等价于 a = (b = (c = 7))
    std::cout << a << " " << b << " " << c << "\n";

    int x = 1;
    std::cout << (x = 5) << "\n";  // 赋值表达式的值是 5，类型是 int 左值
    (x = 5) = 9;                   // 合法但别写：赋值表达式是左值，可以再被赋值
    std::cout << x << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra assign_expr.cpp -o ae && ./ae
```

```text
7 7 7
5
9
```

### 5.1.2 复合赋值：不只是少打几个字
{: .sec-know}

别把 `a += b` 简单看成 `a = a + b` 的缩写——它俩有实打实的差别：

- **左操作数只求值一次**。`*p++ += 1` 与 `*p++ = *p++ + 1` 完全不同（后者有 UB）。
- **类型不需要显式转换**。`char c = 'a'; c += 1;` 合法，因为复合赋值内部做了隐式转换回左操作数类型。
- **内建类型上，结果先按左操作数类型做转换**。`int i = 5; i *= 0.5;` 结果是 `int`（2），不是 double。
- 对自定义类型，`operator+=` 通常比 `operator+` 高效（不用构造临时对象）。

```cpp
// compound_assign.cpp —— 需要 -std=c++20
#include <iostream>

int main() {
    char c = 'a';
    c += 1;                        // OK：不需要写 c = static_cast<char>(c + 1)
    std::cout << c << "\n";

    int i = 5;
    i *= 0.5;                      // 结果是 2（int），不是 2.5
    std::cout << i << "\n";

    unsigned char u = 200;
    u += 100;                      // 无符号回绕：300 - 256 = 44
    std::cout << static_cast<int>(u) << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra compound_assign.cpp -o ca && ./ca
```

```text
b
2
44
```

### 5.1.3 赋值运算符该返回什么
{: .sec-prac}

自己写 `operator=` 的惯例是返回**左值引用** `T&`。原因很实际：链式 `a = b = c` 才跑得通，而且语义跟内建类型对得上。

```cpp
// operator_assign.cpp —— 需要 -std=c++20
#include <iostream>
#include <string>
#include <utility>

class Name {
public:
    Name() = default;
    explicit Name(std::string s) : value_(std::move(s)) {}

    Name& operator=(const Name& other) {
        if (this != &other) {          // 自赋值检查
            value_ = other.value_;
        }
        return *this;                  // 返回左值引用，支持链式
    }

    const std::string& get() const { return value_; }
private:
    std::string value_{"none"};
};

int main() {
    Name a{"Alice"}, b{"Bob"}, c{"Carol"};
    a = b = c;                         // 靠的就是返回 Name&
    std::cout << a.get() << " " << b.get() << "\n";

    Name d;
    d = d;                             // 自赋值：检查生效，不会出错
    std::cout << d.get() << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra operator_assign.cpp -o oa && ./oa
```

```text
Carol Carol
none
```

为什么是 `T&` 而不是 `const T&` 或 `T`？三点：链式赋值时左操作数还得能接着被赋值；按值返回 `T` 白多一次拷贝；`const T&` 会挡掉 `(a = b) = c`（虽然没人这么写，但内建类型允许）。

> **坑：** 顺带一句：按值返回的函数加 `const`（`const std::string getName();`）纯属噪音。C++11 之后它会挡住调用方把返回值 move 走，收益却是零。这条在 4.4.10 也提过，这里再拎出来一次。
{: .sec-pit}

#### 辨析：初始化 与 赋值的运算符巧合
{: .sec-iv}

`T x = a;` 里的 `=` 根本不调 `operator=`，调的是**构造函数**（拷贝或转换构造）——因为这一刻 `x` 还没诞生。只有 `x = a;`（x 已经存在）才走 `operator=`。这也解释了为什么 `explicit` 构造能拦住 `T x = a;`，却拦不住 `T x(a);`。

## 5.2 算术运算符
{: .sec-expl}

### 5.2.1 五种运算与它们的类型规则
{: .sec-know}

`+` `-` `*` `/` `%` 里，`%` 只认整型，其余四种算术类型都能用。结果类型交给**整型提升 + 寻常算术转换**去定（细节在 6.2.2、6.2.3），这里先只记结论：

- 比 `int` 窄的类型（`char`、`short`、`bool`）参与运算时先提升为 `int`；
- 两边类型不同时，往"更能装"的那边转；
- 一边无符号一边有符号且 rank 相同时，有符号那边被转成无符号。

### 5.2.2 整数溢出：有符号 UB，无符号取模
{: .sec-warn}

C/C++ 里最反直觉的分界线就在这里：

- **有符号整数溢出是未定义行为**（UB）。编译器可以假设它永不发生，于是做出各种"优化"——包括把上面的边界检查直接删掉。
- **无符号整数溢出是定义良好的**：结果按 2^N 取模（N 为位宽）。

```cpp
// overflow.cpp —— 需要 -std=c++20
#include <climits>
#include <iostream>

int main() {
    unsigned int u = 0;
    std::cout << "0u - 1       = " << (u - 1) << "\n";        // 定义良好：回绕
    std::cout << "UINT_MAX + 1 = " << (UINT_MAX + 1u) << "\n"; // 定义良好：0

    int i = INT_MAX;
    std::cout << "INT_MAX      = " << i << "\n";
    // std::cout << (i + 1) << "\n";   // 未定义行为：有符号溢出，不要打开这一行
}
```

```bash
g++ -std=c++20 -Wall -Wextra overflow.cpp -o ov && ./ov
```

```text
# 前提：32 位 unsigned int（现实中几乎所有平台都是）
0u - 1       = 4294967295
UINT_MAX + 1 = 0
INT_MAX      = 2147483647
```

把最后一行注释去掉，用 UBSan 跑，会看到类似这样的运行期报错：

```bash
g++ -std=c++20 -O0 -fsanitize=undefined overflow.cpp -o ov_san && ./ov_san
```

```text
overflow.cpp:12:22: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
```

（UBSan 的措辞随版本略有差异，行号列号按你的文件算。）

三种检测手段：

| 手段 | 作用 | 代价 |
| --- | --- | --- |
| `-fsanitize=undefined`（含 `signed-integer-overflow`） | 运行期精确报出溢出点 | 约 2 倍 slowdown，别上生产 |
| `-ftrapv` | 溢出时直接 `SIGABRT` | 只支持有符号，会插入大量检查 |
| `-fwrapv` | 把有符号溢出**定义**为回绕 | 把 UB 变合法，代价是可移植性依赖编译器开关 |

实际怎么用：把 `-fsanitize=undefined` 塞进 CI 的 Debug 构建，生产环境别开；`-fwrapv` 只在搬那些依赖回绕行为的老代码时临时顶一下。

> **坑：** 溢出 UB 最阴的地方在于"优化会把检查删了"。写 `if (i + 1 > i)` 时，编译器完全能推出它恒真（没 UB 即没溢出），于是整段判断被消掉。所以"先加再判断"永远是错的，正确姿势是 `if (i < INT_MAX) { ++i; }`。
{: .sec-pit}

### 5.2.3 有符号与无符号混算的灾难
{: .sec-warn}

混算时规则会把有符号那边转成无符号，负数一下变成天文数字。写倒序死循环的人，多半就栽在这条上：

```cpp
// sign_mix.cpp —— 需要 -std=c++20
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v;                 // 空容器
    std::cout << std::boolalpha;

    auto n = v.size();                  // std::size_t，无符号
    std::cout << "v.size()       = " << n << "\n";
    std::cout << "v.size() - 1   = " << (n - 1) << "\n";   // 0 - 1 → SIZE_MAX

    std::cout << "(-1 < 1u)      = " << (-1 < 1u) << "\n";  // false！-1 变成 UINT_MAX
    std::cout << "(-1 > 1u)      = " << (-1 > 1u) << "\n";  // true
}
```

```bash
g++ -std=c++20 -Wall -Wextra -Wsign-compare sign_mix.cpp -o sm && ./sm
```

```text
# 前提：64 位 size_t
v.size()       = 0
v.size() - 1   = 18446744073709551615
(-1 < 1u)      = false
(-1 > 1u)      = true
```

经典的"倒序死循环"就这么来的：

```cpp
// 死循环（v 为空时 i 从 SIZE_MAX 开始，永远 >= 0）
for (std::size_t i = v.size() - 1; i >= 0; --i) { /* ... */ }
```

三种正确写法：

```cpp
for (std::size_t i = v.size(); i-- > 0;) { /* i 从 size()-1 递减到 0 */ }
for (auto it = v.rbegin(); it != v.rend(); ++it) { /* 反向迭代器，最省心 */ }
for (std::ptrdiff_t i = std::ssize(v) - 1; i >= 0; --i) { /* C++20 ssize，有符号 */ }
```

`std::ssize`（C++20，头文件 `<iterator>`）返回有符号的 `std::ptrdiff_t`，就是专为这种"要做减法"的下标场景准备的。

### 5.2.4 除零、余数符号与 `INT_MIN / -1`
{: .sec-know}

```cpp
// div_mod.cpp —— 需要 -std=c++20
#include <climits>
#include <iostream>

int main() {
    std::cout << "7/2   -7/2   7/-2   -7/-2  = "
              << 7 / 2 << " " << -7 / 2 << " " << 7 / -2 << " " << -7 / -2 << "\n";
    std::cout << "7%2   -7%2   7%-2   -7%-2  = "
              << 7 % 2 << " " << -7 % 2 << " " << 7 % -2 << " " << -7 % -2 << "\n";

    // int z = 0; std::cout << 1 / z;   // 未定义行为：整型除零，通常是 SIGFPE
    // std::cout << INT_MIN / -1;       // 未定义行为：结果无法用 int 表示
}
```

```bash
g++ -std=c++20 -Wall -Wextra div_mod.cpp -o dm && ./dm
```

```text
7/2   -7/2   7/-2   -7/-2  = 3 -3 -3 3
7%2   -7%2   7%-2   -7%-2  = 1 -1 1 -1
```

规则：

- **整数除法向零取整**（C++11 起明确规定；C++03 时对负数是实现定义的）。`-7 / 2 == -3`，不是 -4。
- **余数的符号跟被除数**（同样由 C++11 的 truncate-toward-zero 推出，`(a/b)*b + a%b == a`）。
- **整型除零是 UB**（实际表现通常是 SIGFPE 崩溃）。
- **`INT_MIN / -1` 是 UB**，因为 2147483648 装不进 `int`；`INT_MIN % -1` 同理。这是唯一一个"操作数都合法但结果溢出"的除法。
- 浮点除以 0.0 **不是** UB：IEEE 754 下得到 ±inf 或 NaN（除非开了 trap）。

### 5.2.5 浮点为什么不能 `==`
{: .sec-know}

两个层面的原因：二进制本身就不精确实（`0.1` 没法用有限二进制表示），再加上运算过程中舍入误差会累积。

```cpp
// float_cmp.cpp —— 需要 -std=c++20
#include <cmath>
#include <iostream>

bool almost_equal(double a, double b, double rel = 1e-9) {
    double diff = std::fabs(a - b);
    if (diff <= rel) { return true; }                     // 接近 0 时用绝对阈值兜底
    return diff <= rel * std::fmax(std::fabs(a), std::fabs(b));
}

int main() {
    std::cout << std::boolalpha;
    double x = 0.1 + 0.2;
    std::cout << "x == 0.3            : " << (x == 0.3) << "\n";
    std::cout << "almost_equal        : " << almost_equal(x, 0.3) << "\n";
    std::cout << "1e16 + 1 == 1e16    : " << ((1e16 + 1.0) == 1e16) << "\n";
    std::cout << "NaN == NaN          : " << (std::nan("") == std::nan("")) << "\n";
    std::cout << "almost_equal(NaN)   : " << almost_equal(std::nan(""), std::nan("")) << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra float_cmp.cpp -o fc && ./fc
```

```text
x == 0.3            : false
almost_equal        : true
1e16 + 1 == 1e16    : true
NaN == NaN          : false
almost_equal(NaN)   : false
```

epsilon 比较的三个局限，得心里有数：

1. **固定阈值在大数量级下失效**。`1e16 + 1 == 1e16` 是 true，因为 double 在这个量级上连 1 的间隔都表示不了——任何小于 ULP 的误差都不可见。所以阈值必须**相对**（乘上量级）。
2. **接近 0 时相对阈值失效**，所以上面那段代码留了一条绝对阈值的分支。
3. **NaN 无解**。NaN 的任何比较都是 false，包括自己和自己；`almost_equal` 也救不了。做数值算法时先 `std::isfinite` 过滤。

要更准就上 **ULP 比较**（比按位表示差了几个可表示数）。想从根上避开，就改设计：金额用整数的最小单位（分），比例用定点数。

### 5.2.6 求值顺序：`f(g(), h())` 到底先算谁
{: .sec-warn}

先交代点历史：C++11 把"序列点"（sequence point）这个概念废了，换成三套关系来描述顺序——**sequenced-before**（有先后）、**indeterminately sequenced**（有先后但谁先 unspecified，且不交错）、**unsequenced**（完全没保证）。

判定 UB 只看一条硬规则：**同一个标量对象上若有两个未排序的写，或一个写和一个未排序的读，就是未定义行为。** 我记这条就靠一句话——"同一对象上两写未排序就是 UB"——当初记混过、掉过坑才刻进脑子。

C++17 补了几条保证，把一批经典 UB 扶正成了"有定义"：

| 表达式 | C++17 起的新保证 |
| --- | --- |
| `E1 = E2`、`E1 @= E2` | E2 的值计算与副作用**全部先于** E1 |
| `E1 << E2`、`E1 >> E2` | E1 先于 E2 |
| `E1[E2]` | E1 先于 E2 |
| `E1 ->* E2`、`E1 .* E2` | E1 先于 E2 |
| `f(a, b, c)` | 函数后置表达式先于各实参；实参之间**indeterminately sequenced**（不交错，但顺序 unspecified） |
| `new T(a, b)` | 分配函数的调用先于实参求值 |

注意最后一行：`f(g(), h())` 里 `g()` 和 `h()` 在 C++17 之后不再 UB（它们不交错），但**谁先跑没规定**。所以两个函数若有相互依赖的副作用，结果就不可预测——不是 UB，但你也算不出来。

```cpp
// order_demo.cpp —— 需要 -std=c++20
#include <iostream>

int g() { std::cout << "g "; return 1; }
int h() { std::cout << "h "; return 2; }
void f(int, int) {}

int main() {
    f(g(), h());                 // 顺序 unspecified：可能打印 "g h" 也可能 "h g"
    std::cout << "\n";

    int i = 0;
    int arr[4] = {0, 0, 0, 0};
    arr[i] = i + 1;              // C++17 起：i+1 先于 arr[i] 求值，有定义
    std::cout << "arr[0]=" << arr[0] << "\n";

    // int j = 0;
    // int bad = j++ + ++j;      // 未定义行为：两个写未排序
}
```

```bash
g++ -std=c++20 -Wall -Wextra order_demo.cpp -o od && ./od
```

```text
g h
arr[0]=1
```

第一行那个顺序别去依赖——换个编译器或优化级别，很可能就反过来了。

## 5.3 比较运算符
{: .sec-expl}

### 5.3.1 六个比较运算符与它们的坑
{: .sec-know}

`<` `<=` `>` `>=` `==` `!=` 返回 `bool`。坑主要是三个：

```cpp
// compare_pit.cpp —— 需要 -std=c++20
#include <iostream>

int main() {
    std::cout << std::boolalpha;
    int a = 1, b = 2, c = 3;

    // 坑一：链式比较。数学里的 a < b < c 在 C++ 里是 (a < b) < c
    std::cout << "a < b < c       = " << (a < b < c) << "\n";   // (1 < 2)=true → true < 3 → 1 < 3 → true
    int x = 5, y = 1, z = 0;
    std::cout << "5 < 1 < 0 直觉? = " << (x < y < z) << "\n";   // (5<1)=false → false < 0 → 0 < 0 → false
    std::cout << "正确写法        = " << (a < b && b < c) << "\n";

    // 坑二：混符号
    std::cout << "-1 < 1u         = " << (-1 < 1u) << "\n";     // false

    // 坑三：浮点 ==（见 5.2.5）
    std::cout << "(0.1+0.2) == 0.3= " << ((0.1 + 0.2) == 0.3) << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra compare_pit.cpp -o cpt && ./cpt
```

```text
a < b < c       = true
5 < 1 < 0 直觉? = false
正确写法        = true
-1 < 1u         = false
(0.1+0.2) == 0.3= false
```

`a < b < c` 最坑的地方是它经常"碰巧算对"。`1 < 2 < 3` 正好是 true，于是写的人以为 C++ 支持链式比较，直到某天数据变成 `5 < 1 < 0` 才露馅。

### 5.3.2 三路比较 `<=>`：C++20 的一次性解决方案
{: .sec-ext}

C++20 的"飞船运算符" `<=>` 一次比较就返回**三态结果**，六个关系运算符由编译器从它合成。

三种返回类别，区别只在于"相等"的强弱：

| 类别 | 含义 | 典型来源 |
| --- | --- | --- |
| `std::strong_ordering` | 相等意味着**可替换**（所有可观察属性都一样） | 整数、指针、`std::string` 的字典序 |
| `std::weak_ordering` | 相等只意味着**等价**，不一定可替换 | 大小写不敏感的字符串比较 |
| `std::partial_ordering` | 还多一个 `unordered` 状态 | 浮点（NaN 与任何东西都无序） |

```cpp
// spaceship.cpp —— 需要 -std=c++20
#include <compare>
#include <iostream>
#include <limits>
#include <type_traits>

struct Version {
    int major;
    int minor;
    auto operator<=>(const Version&) const = default;   // 逐成员字典序
};

int main() {
    std::cout << std::boolalpha;
    Version a{1, 2}, b{1, 3};
    std::cout << "a < b  = " << (a < b) << "\n";        // 由 <=> 合成
    std::cout << "a == b = " << (a == b) << "\n";       // 默认 <=> 会隐式生成 ==
    std::cout << "(a<=>b) < 0 = " << ((a <=> b) < 0) << "\n";

    auto cmp = 1.0 <=> 2.0;
    static_assert(std::is_same_v<decltype(cmp), std::partial_ordering>);
    std::cout << "1.0<=>2.0 is_lt = " << std::is_lt(cmp) << "\n";

    double nan = std::numeric_limits<double>::quiet_NaN();
    auto nc = 0.0 <=> nan;
    std::cout << "与 NaN 比较无序 = " << (nc == std::partial_ordering::unordered) << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra spaceship.cpp -o sp && ./sp
```

```text
a < b  = true
a == b = false
(a<=>b) < 0 = true
1.0<=>2.0 is_lt = true
与 NaN 比较无序 = true
```

几个容易忽略的细节：

- `= default` 的三路比较会**逐成员**比较，按成员声明顺序，用的是每个成员自己的 `<=>`。
- 默认 `<=>` 会**隐式声明一个 defaulted `==`**，`!=` 再从 `==` 合成。所以上面只写了 `<=>`，`==` 就白送了。
- 想手写就手写：`auto operator<=>(const T&) const { return field1 <=> other.field1; }`，返回类型可以让 `auto` 推导。
- `std::is_lt` / `is_eq` / `is_gt` 这些命名比较函数在 `<compare>` 里，比直接和 `0` 比较可读。
- 老代码里的 `operator<` + `std::tie` 那套写法可以退休了。

## 5.4 逻辑运算符
{: .sec-expl}

### 5.4.1 短路求值：可以放心依赖
{: .sec-know}

内建的 `&&` 和 `||` 保证**从左到右**求值，且结果一确定就停。这不是编译器优化，是语言硬规则——所以你才敢把它当安全护栏用。

```cpp
// short_circuit.cpp —— 需要 -std=c++20
#include <iostream>

bool probe(const char* name, bool v) {
    std::cout << name << " ";
    return v;
}

int main() {
    std::cout << "&&: ";
    if (probe("L", false) && probe("R", true)) {}     // 只打印 L
    std::cout << "\n||: ";
    if (probe("L", true) || probe("R", false)) {}     // 只打印 L
    std::cout << "\n&&: ";
    if (probe("L", true) && probe("R", false)) {}     // 打印 L R
    std::cout << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra short_circuit.cpp -o sc && ./sc
```

```text
&&: L 
||: L 
&&: L R
```

三种日常惯用法全靠它：

```cpp
if (p != nullptr && p->is_valid()) { /* 指针判空后直接用 */ }
if (idx < v.size() && v[idx] == target) { /* 越界检查后访问 */ }
if (f1() || f2() || f3()) { /* 第一个成功就不再试后面的 */ }
```

`!` 就是个一元取反，谈不上短路。条件运算符 `?:` 也只算被选中的那个分支。

### 5.4.2 别重载 `&&` 和 `||`
{: .sec-warn}

一旦给自己的类型重载了 `&&` / `\|\|`，丢掉的——也是唯一丢掉的——就是**短路求值**。两个操作数一定都被求值，因为它们只是这次函数调用的两个实参，调用发生前就得算完。于是 `if (p && p->ok())` 这种"靠前面拦住后面"的写法直接报废。

求值顺序反而保得住。C++17 起标准说得很清楚：**只要用运算符记法（而非 `a.operator&&(b)` 这种显式调用）去调重载运算符，它就沿用被重载内建运算符的顺序规则**——所以重载版 `&&` 左操作数依旧先于右操作数。要是没有这条，两个实参谁先谁后不定，带副作用的表达式就滑向 UB 边缘了。

```cpp
struct Boolish {
    bool value;
    // 千万别这么写：
    // Boolish operator&&(const Boolish& r) const { return {value && r.value}; }
};
```

需要"自定义类型的布尔语义"，正确做法是提供 `explicit operator bool()`（见 6.2.5），让内建的 `&&` 继续工作，短路和顺序都保住。

> **坑：** 逗号运算符、赋值运算符、`[]`、`<<` 同理：**C++17 起只要用运算符记法写，顺序规则就跟着内建版本走**；一旦写成显式的函数调用形式（`operator&&(a, b)`、`a.operator=(b)`），就退化成普通函数调用规则——多个实参之间只是 indeterminately sequenced，先后顺序 unspecified。C++ 里有一小撮运算符的"特殊求值规则"是内建版本独有的，重载就丢一半（短路全丢）：`&&`、`\|\|`、`,`、`?:`（这个根本不能重载）。
{: .sec-pit}

### 5.4.3 布尔转换与 `!!` 惯用法
{: .sec-know}

`if`、`while`、`&&`、`||`、`!`、`?:` 的首操作数，外加 `static_assert`，都会触发**语境转换到 bool**（contextual conversion to bool）。它比普通隐式转换松一点：`explicit operator bool()` 在这儿能工作，在 `bool b = obj;` 里却不行。

`!!x` 这个惯用法的作用是把任意值规范成 `bool`：

```cpp
int flags = 0x100;
bool has_flag = !!(flags & 0x100);   // 等价于 (flags & 0x100) != 0
```

写 `!!` 好处是意图清楚（"我就是要一个 bool"），坏处是新手犯懵。团队里定一个就别混。更现代的替代是 `static_cast<bool>(...)`。

## 5.5 `++` 与 `--`
{: .sec-expl}

### 5.5.1 前置与后置：返回值类别不同
{: .sec-know}

- **前置** `++i`：先加，返回**加之后的左值**（`int&`）。
- **后置** `i++`：先加，返回**加之前的值**（prvalue 临时量）。

```cpp
// inc_dec.cpp —— 需要 -std=c++20
#include <iostream>

int main() {
    int i = 0;
    ++i = 10;                    // 合法：++i 是左值，可以继续被赋值
    std::cout << i << "\n";
    // i++ = 20;                 // 错误：i++ 是 prvalue，不能赋值

    int j = 5;
    std::cout << "j++ = " << j++ << " → j = " << j << "\n";
    std::cout << "++j = " << ++j << " → j = " << j << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra inc_dec.cpp -o id && ./id
```

```text
10
j++ = 5 → j = 6
++j = 7 → j = 7
```

### 5.5.2 `++i` 真的比 `i++` 快吗
{: .sec-iv}

答案很直接：**内建类型开优化后完全没差别；迭代器这类自定义类型，有差别。**

原因也简单。内建类型上，编译器发现旧值被丢了，就生成一模一样的指令——不是"优化多厉害"，而是后置版本在"用不上旧值"时本来就白赚，不需要额外干活。

自定义类型上，后置版本必须**先拷贝一份旧值**才能返回：

```cpp
// 典型的迭代器实现（简化）
Iter& operator++() { ++ptr_; return *this; }        // 前置：原地改，返回引用
Iter  operator++(int) { Iter tmp = *this; ++ptr_; return tmp; }  // 后置：多一次拷贝
```

所以规则是：

- 内建类型（`int`、指针）：怎么写都行，别纠结。
- 迭代器、自定义类型：**默认写 `++it`**。这不是性能迷信，是后置版本多构造一个对象的真实成本，而且这个习惯在模板代码里更重要——你不知道 `T` 是什么。

```cpp
// prefix_postfix.cpp —— 需要 -std=c++20
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3};
    for (auto it = v.begin(); it != v.end(); ++it) {   // 习惯用前置
        std::cout << *it;
    }
    std::cout << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra prefix_postfix.cpp -o pp && ./pp
```

```text
123
```

### 5.5.3 什么时候变成 UB：判定规则与实例
{: .sec-warn}

回到 5.2.6 那条硬规则：**同一标量对象上两个未排序的写，或一个写与一个未排序的读 → UB。** 拿它卡一遍：

```cpp
// inc_ub.cpp —— 需要 -std=c++20
#include <iostream>

int main() {
    int i = 1;
    // int a = i++ + ++i;     // 未定义行为：两个写（i++ 和 ++i）彼此未排序
    // i = i++;               // C++17 前 UB；C++17 起赋值右操作数先于左操作数，有定义
    // int arr[4]{}; int k = 0;
    // arr[k] = k++;          // C++17 前 UB；C++17 起同上，有定义

    int b = i++ + 1;          // 安全：只有一个写
    std::cout << b << " " << i << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra inc_ub.cpp -o iu && ./iu
```

```text
2 2
```

整理成一张表，这是最常被问的一组：

| 表达式 | C++11/14 | C++17 起 |
| --- | --- | --- |
| `i++ + ++i` | UB | **仍是 UB**（两个写未排序） |
| `i = i++ + i` | UB | **仍是 UB**（`i++` 与 `i` 的读未排序） |
| `i = i++` | UB | 有定义（E2 先于 E1） |
| `arr[i] = i++` | UB | 有定义（E2 先于 E1） |
| `std::cout << i << i++` | UB | 有定义（`<<` 的 E1 先于 E2） |
| `f(++i, ++i)` | UB | 不再是 UB，但**实参顺序 unspecified**，两个实参的值不确定 |

最后一行单独拎出来说：C++17 之后 `f(++i, ++i)` 里两个自增是 indeterminately sequenced（一个完整跑完再跑另一个，不交错），所以不是 UB。但 `i` 被加了两次、两个实参各拿到什么值，没人规定。这属于"不崩但结果不可预测"，比 UB 好一点，也仅仅好一点。

落到实践只有一条：**一个表达式里别对同一个对象改两次**。拆成两句，代码多一行，可维护性翻几倍。

## 5.6 位运算符
{: .sec-expl}

### 5.6.1 六个位运算符与掩码操作
{: .sec-know}

`&`（与）`\|`（或）`^`（异或）`~`（取反）`<<`（左移）`>>`（右移）。前四个只吃整型，`<<`/`>>` 同样只对整型有效。

位运算的主场是**标志位（flags）**：

| 操作 | 写法 | 说明 |
| --- | --- | --- |
| 测试某位 | `(flags & MASK) != 0` | 括号必须加，`&` 优先级低于 `!=` |
| 置位 | `flags \|= MASK` | 把指定位设为 1 |
| 清位 | `flags &= ~MASK` | 把指定位设为 0 |
| 翻转 | `flags ^= MASK` | 指定位取反 |
| 取最低位的值 | `flags & -flags` | 只在最低的那个 1 处为 1 |

```cpp
// bitflags.cpp —— 需要 -std=c++20
#include <bitset>
#include <cstdint>
#include <iostream>

int main() {
    std::uint8_t flags = 0b0000'0101;          // C++14 起支持二进制字面量与分隔符
    auto show = [](std::uint8_t v) { std::cout << std::bitset<8>(v) << "\n"; };

    show(flags);                               // 00000101
    flags |= 0b0000'0010;   show(flags);       // 置位    → 00000111
    flags &= ~0b0000'0100;  show(flags);       // 清位    → 00000011
    flags ^= 0b0000'0001;   show(flags);       // 翻转    → 00000010

    std::cout << std::boolalpha;
    std::cout << "bit2 置位了吗: " << ((flags & 0b0000'0100) != 0) << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra bitflags.cpp -o bf && ./bf
```

00000010

### 5.6.2 `n & (n-1)`：消去最低位的那个 1
{: .sec-ts}

这个式子的效果是**把 `n` 二进制里最低的那个 1 清零**。从它又能变出三个高频用法：

```cpp
// bit_tricks.cpp —— 需要 -std=c++20
#include <bit>
#include <cstdint>
#include <iostream>

bool is_power_of_two(std::uint32_t n) {
    return n != 0 && (n & (n - 1)) == 0;       // 只有一位是 1
}

int count_set_bits_naive(std::uint32_t n) {
    int c = 0;
    while (n) { n &= n - 1; ++c; }             // 每消一个 1 记一次
    return c;
}

int main() {
    std::cout << std::boolalpha;
    std::cout << "8 是 2 的幂吗   = " << is_power_of_two(8) << "\n";
    std::cout << "12 是 2 的幂吗  = " << is_power_of_two(12) << "\n";
    std::cout << "0 是 2 的幂吗   = " << is_power_of_two(0) << "\n";
    std::cout << "0b1011000 里有几个 1 = " << count_set_bits_naive(0b1011000) << "\n";
    std::cout << "C++20 has_single_bit = " << std::has_single_bit(8u) << "\n";
    std::cout << "C++20 popcount       = " << std::popcount(0b1011000u) << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra bit_tricks.cpp -o bt && ./bt
```

```text
8 是 2 的幂吗   = true
12 是 2 的幂吗  = false
0 是 2 的幂吗   = false
0b1011000 里有几个 1 = 3
C++20 has_single_bit = true
C++20 popcount       = 3
```

注意 `is_power_of_two` 里的 `n != 0`——`0 & (0-1)` 也等于 0，少了这层判断就会把 0 也当成 2 的幂。这是最容易漏写的一处。

### 5.6.3 异或交换是反模式
{: .sec-ts}

```cpp
int a = 3, b = 5;
a ^= b;  b ^= a;  a ^= b;    // 能交换，但别这么写
```

四个反对理由：

1. **可读性**：`std::swap(a, b)` 一眼看懂，这三行要停下来想。
2. **性能更差**：三条指令存在严格的数据依赖，无法并行；编译器对 `std::swap` 有完整的信息（通常就是三条 `mov`），比这快。
3. **别名时崩**：如果 `a` 和 `b` 是同一个对象（比如 `swap(x, x)` 或引用到同一变量），三步下来结果是 **0**——原值彻底丢失。
4. **一行写法是 UB**：`a ^= b ^= a ^= b;` 对 `a` 有多次未排序的写，未定义行为。

要交换就用 `std::swap`（C++11 起它对有移动语义的类型是 O(1) 且 `noexcept`）。

### 5.6.4 移位运算的三条 UB
{: .sec-warn}

- **移位数为负，或大于等于位宽 → UB**（所有版本都一样，没有任何例外）。`1 << 32` 在 32 位 `int` 上是 UB，不是 0。
- **左移负数**：C++20 之前对有符号类型是 UB；C++20（P0907 采纳二补数）之后定义为"乘以 2^n 后按位宽取模"。
- **右移负数**：C++20 之前是**实现定义**（算术右移还是逻辑右移由实现定）；C++20 起规定为算术右移（向下取整）。

结论就一句：只要你想做的是纯二进制位移，**一律用无符号类型**（`std::uint32_t` 之类），这样三条里只剩"移位数越界"需要留心，而那条你自己就能查。

一个真实的坑：

```cpp
std::uint32_t mask = 1u << 31;    // OK：1u 是 unsigned，31 < 32
// int bad = 1 << 31;             // UB：int 是 32 位有符号，1<<31 溢出
std::uint64_t big = 1ull << 40;   // OK：用 ull 后缀保证是 64 位无符号
```

### 5.6.5 `<bit>` 库（C++20）：把手写位技巧换成标准函数
{: .sec-ext}

C++20 的 `<bit>` 头里塞满了 `constexpr` 的位操作模板（针对无符号整型），编译器多半会直接把它们映射成 `popcnt`、`lzcnt`、`tzcnt` 这类指令。

```cpp
// bit_header.cpp —— 需要 -std=c++20
#include <bit>
#include <cstdint>
#include <iostream>

int main() {
    std::uint32_t x = 0b1011000;              // 88
    std::cout << "popcount      = " << std::popcount(x) << "\n";
    std::cout << "countr_zero   = " << std::countr_zero(x) << "\n";
    std::cout << "countl_zero   = " << std::countl_zero(x) << "\n";
    std::cout << "bit_width     = " << std::bit_width(x) << "\n";
    std::cout << "bit_floor     = " << std::bit_floor(x) << "\n";
    std::cout << "bit_ceil      = " << std::bit_ceil(x) << "\n";
    std::cout << std::boolalpha << "has_single_bit= " << std::has_single_bit(x) << "\n";
    std::cout << std::noboolalpha << "rotl(x,1)     = " << std::rotl(x, 1) << "\n";
    std::cout << "rotr(x,1)     = " << std::rotr(x, 1) << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra bit_header.cpp -o bh && ./bh
```

```text

countr_zero   = 3
countl_zero   = 25
bit_width     = 7
bit_floor     = 64
bit_ceil      = 128
has_single_bit= false
rotl(x,1)     = 176
rotr(x,1)     = 44
```

逐个说清（前提是 32 位 `unsigned int`，`x = 88 = 0b1011000`）：

| 函数 | 含义 | 88 的结果 |
| --- | --- | --- |
| `std::popcount(x)` | 1 的个数 | 3 |
| `std::countr_zero(x)` | 末尾连续 0 的个数 | 3 |
| `std::countl_zero(x)` | 开头连续 0 的个数 | 32 - 7 = 25 |
| `std::bit_width(x)` | 表示 x 需要的位数（x=0 时为 0） | 7 |
| `std::bit_floor(x)` | 不超过 x 的最大 2 的幂 | 64 |
| `std::bit_ceil(x)` | 不小于 x 的最小 2 的幂 | 128 |
| `std::has_single_bit(x)` | 是不是 2 的幂 | false |
| `std::rotl` / `std::rotr` | 循环左移/右移 | 176 / 44 |

验算一下 `rotl`：`88 << 1 = 176`，88 的最高位是 bit 6（值 64），在 32 位循环左移中它不会绕回（因为 176 < 2^32），结果 176。`rotr(88, 1)`：最低位是 0（88 有 3 个末尾 0），所以就是 `88 >> 1 = 44`。

`std::bit_ceil` 有个前提：结果得塞得进该类型，否则 UB（比如 `std::bit_ceil(std::uint32_t(0x80000001))`）。

字节序反转：C++23 加了 `std::byteswap`（`<bit>`）。在它可用之前，用这个可移植实现：

```cpp
// byteswap_portable.cpp —— 需要 -std=c++20
#include <cstddef>
#include <cstdint>
#include <iostream>
#include <type_traits>

template <class T>
constexpr T byteswap_fallback(T v) {
    static_assert(std::is_unsigned_v<T>, "只对无符号整型有意义");
    T r{};
    for (std::size_t i = 0; i < sizeof(T); ++i) {
        r |= static_cast<T>(((v >> (i * 8)) & 0xFF) << ((sizeof(T) - 1 - i) * 8));
    }
    return r;
}

int main() {
    std::uint32_t v = 0x12345678;
    std::cout << std::hex << byteswap_fallback(v) << "\n";
    // C++23：std::cout << std::hex << std::byteswap(v) << "\n";
    std::cout << std::dec;
}
```

```bash
g++ -std=c++20 -Wall -Wextra byteswap_portable.cpp -o bs && ./bs
```

```text
78563412
```

> **坑：** 位运算就用**无符号**类型。有符号类型的右移、取反、移位溢出，统统在 UB 或实现定义的边上晃；而且符号位一旦掺和进来，`~0` 是 -1 还是最大值，取决于你有没有假设二补数（C++20 才正式拍板二补数）。
{: .sec-pit}

## 5.7 求字节数：`sizeof` 与 `alignof`
{: .sec-expl}

### 5.7.1 `sizeof` 是运算符，不是函数
{: .sec-know}

它是编译期运算符，结果是 `std::size_t` 类型的**常量表达式**。三条推论：

- 它不对操作数求值；
- 它不需要运行期信息；
- `sizeof(expr)` 和 `sizeof(type)` 两种写法，`type` 那一种必须带括号（`sizeof int` 是语法错误）。

```cpp
// sizeof_demo.cpp —— 需要 -std=c++20
#include <iostream>

void takes_array(int arr[10]) {
    std::cout << "函数里 sizeof(arr) = " << sizeof(arr) << "\n";   // 指针！不是数组
}

int main() {
    int a[10];
    int* p = a;
    std::cout << "sizeof(a)          = " << sizeof(a) << "\n";
    std::cout << "sizeof(p)          = " << sizeof(p) << "\n";
    std::cout << "元素个数           = " << sizeof(a) / sizeof(a[0]) << "\n";
    takes_array(a);

    int i = 0;
    std::cout << "sizeof(i++)        = " << sizeof(i++) << "\n";
    std::cout << "i 之后             = " << i << "\n";   // 还是 0：sizeof 不求值
}
```

```bash
g++ -std=c++20 -Wall -Wextra sizeof_demo.cpp -o sd && ./sd
```

```text
# 前提：LP64（Linux/macOS 64 位）；Windows 上指针是 8 字节但 long 是 4 字节
sizeof(a)          = 40
sizeof(p)          = 8
元素个数           = 10
函数里 sizeof(arr) = 8
sizeof(i++)        = 4
i 之后             = 0
```

GCC 会在这里报 `-Wsizeof-array-argument`（这个开关**默认开**，连 `-Wall` 都不用加）——编译器在提醒你"形参早就退化成指针了"。

### 5.7.2 数组与指针退化：经典混淆
{: .sec-iv}

数组会在三种语境下**退化**（decay）成首元素指针：函数传参、`auto` 推导，以及大多数参与运算的场合。于是：

| 场景 | `sizeof` 的结果 |
| --- | --- |
| 数组实参声明处（`void f(int a[10])`） | 指针大小（8） |
| 数组名在定义它的作用域里 | 整个数组的字节数 |
| `sizeof(a) / sizeof(a[0])` | 元素个数（只在数组语境下对） |

要拿到元素个数，现代写法是 `std::size(a)`（C++17，`<iterator>`），它对数组和容器都成立，且不会退化：

```cpp
// size_ssize.cpp —— 需要 -std=c++20
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    int a[5]{};
    std::vector<int> v{1, 2, 3};

    std::cout << "std::size(a)  = " << std::size(a) << "\n";
    std::cout << "std::size(v)  = " << std::size(v) << "\n";
    std::cout << "std::ssize(v) = " << std::ssize(v) << "\n";

    std::cout << "倒序：";
    for (std::ptrdiff_t i = std::ssize(v) - 1; i >= 0; --i) {
        std::cout << v[static_cast<std::size_t>(i)];
    }
    std::cout << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra size_ssize.cpp -o ss && ./ss
```

```text
std::size(a)  = 5
std::size(v)  = 3
std::ssize(v) = 3
倒序：321
```

`std::ssize`（C++20）返回有符号的 `std::ptrdiff_t`，就是给"要做减法"的下标场景准备的（见 5.2.3）。

### 5.7.3 `alignof` 与对齐
{: .sec-know}

`alignof(T)` 返回类型 `T` 的对齐要求（`std::size_t`），C++11 起。它和 `sizeof` 是一对：

```cpp
// alignof_demo.cpp —— 需要 -std=c++20
#include <cstddef>
#include <iostream>

struct Plain { char c; int i; };
struct alignas(16) Aligned { float x, y, z, w; };

int main() {
    std::cout << "alignof(char)     = " << alignof(char) << "\n";
    std::cout << "alignof(int)      = " << alignof(int) << "\n";
    std::cout << "alignof(double)   = " << alignof(double) << "\n";
    std::cout << "alignof(Plain)    = " << alignof(Plain) << "  sizeof=" << sizeof(Plain) << "\n";
    std::cout << "alignof(Aligned)  = " << alignof(Aligned) << "  sizeof=" << sizeof(Aligned) << "\n";
    std::cout << "alignof(max_align_t) = " << alignof(std::max_align_t) << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra alignof_demo.cpp -o ad && ./ad
```

```text

alignof(int)      = 4
alignof(double)   = 8
alignof(Plain)    = 4  sizeof=8
alignof(Aligned)  = 16  sizeof=16
alignof(max_align_t) = 16
```

`Plain` 的 `sizeof` 是 8 而不是 5，就是对齐填充闹的：`char` 后面被塞了 3 字节 padding，才把 `int` 顶到 4 字节边界上。做二进制序列化、网络协议、内存映射文件时，这些 padding 字节是实打实的坑——它们的**内容是不确定的**。

### 5.7.4 `sizeof` 不能用在哪些东西上
{: .sec-know}

函数类型（`sizeof(f)` 不行，`sizeof(&f)` 行）、不完整类型（只声明没定义的 `struct S;`、还有 `void`）、以及位域本身。`sizeof` 引用类型拿到的是被引用类型的大小；`sizeof` 空类至少是 1（每个对象都得有唯一地址）。

## 5.8 条件运算符 `?:`
{: .sec-expl}

### 5.8.1 语法与求值
{: .sec-know}

`cond ? E2 : E3` 是 C++ 里唯一的三目运算符。两个特性：

- **只求值被选中的分支**，另一个分支完全不碰（这也是短路的一种）；
- 结果是**表达式**，可以出现在任何需要值的地方，包括 `constexpr` 上下文。

```cpp
// cond_op.cpp —— 需要 -std=c++20
#include <iostream>

const char* side(bool b) { std::cout << (b ? "left " : "right "); return b ? "L" : "R"; }

int main() {
    const char* r = true ? side(true) : side(false);   // 只调 side(true)
    std::cout << "\n结果 = " << r << "\n";

    constexpr int n = 10;
    constexpr int m = (n > 5) ? 1 : 2;                 // 编译期就能算
    static_assert(m == 1);
    std::cout << m << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra cond_op.cpp -o co && ./co
```

```text
left 
结果 = L
1
```

### 5.8.2 返回类型推导：两分支类型不同时怎么办
{: .sec-know}

规则按以下顺序判定：

1. 两分支类型相同 → 结果就是那个类型；
2. 两分支都是同类型的 glvalue（且 cv 限定一致）→ 结果是**同值类别的 glvalue**；
3. 其中一个是类类型时，尝试互相转换：只有一边能转 → 用那个；两边都能转或都不能转 → **编译错误（歧义）**；
4. 都不是类类型 → 走整型提升与寻常算术转换求公共类型。

```cpp
// cond_type.cpp —— 需要 -std=c++20
#include <iostream>
#include <string>
#include <type_traits>

int main() {
    int i = 1, j = 2;
    (true ? i : j) = 5;                    // 合法！两个分支都是 int 左值，结果是左值
    std::cout << "i=" << i << " j=" << j << "\n";

    auto a = true ? 1 : 2.0;               // 走 usual arithmetic conversions → double
    static_assert(std::is_same_v<decltype(a), double>);

    auto b = true ? "abc" : std::string("x");   // 只有 const char* → string 这条路走得通
    static_assert(std::is_same_v<decltype(b), std::string>);
    std::cout << a << " " << b << "\n";

    // auto c = true ? 1 : nullptr;        // 编译错误：int 与 nullptr_t 没有公共类型
}
```

```bash
g++ -std=c++20 -Wall -Wextra cond_type.cpp -o ct && ./ct
```

```text
i=5 j=2
1 x
```

`(true ? i : j) = 5;` 这一行是表里最反直觉的一条——条件运算符在"两分支同类型左值"时返回左值，于是它能被赋值。多数人头回见都得一愣。

反过来，如果两分支**不都是**同类型左值（比如一个是字面量），结果就是 prvalue，不能被赋值：

```cpp
int i = 1;
// (true ? i : 0) = 5;    // 错误：结果是 prvalue
```

### 5.8.3 `?:` 还是 `if-else`
{: .sec-best}

该选 `?:` 的场景：在初始化时从两个值里挑一个（`const int x = ok ? a : b;`）——换成 `if-else` 反而啰嗦，而且 `const` 根本没法初始化。

该选 `if-else` 的场景：分支带副作用、有多条语句、需要提前返回。把复杂逻辑硬塞进 `?:` 只会让代码难读，嵌套的 `?:` 更是 review 红灯。

## 5.9 逗号运算符
{: .sec-expl}

### 5.9.1 逗号运算符 vs 逗号分隔符
{: .sec-know}

这是两件完全不同的东西，用错了就出怪事：

- **逗号分隔符**：出现在声明、初始化列表、函数调用实参表、模板实参表里，只是语法标点，没有求值顺序保证。
- **逗号运算符**：出现在表达式里，`E1, E2` 先求 E1 丢弃结果，再求 E2，整个表达式的值和值类别都来自 E2。它保证 E1 的每个副作用在 E2 开始之前完成——这是 C++ 里最早的、也是最没有附加条件的一条从左到右保证（`&&`、`||`、`?:` 也有顺序保证，但附带短路；赋值、`[]`、`<<` 的顺序保证是 C++17 才补上的）。

```cpp
// comma_op.cpp —— 需要 -std=c++20
#include <iostream>

int main() {
    int i = 0, j = 10;
    int k = (i = 3, j = 4, i + j);      // 依次执行，结果是最后一个表达式
    std::cout << "k=" << k << " i=" << i << " j=" << j << "\n";

    // for 循环里同时推进两个变量：逗号运算符最正当的用途
    for (int a = 0, b = 5; a < b; ++a, --b) {
        std::cout << a << "/" << b << " ";   // 这里的 << 是运算符，不是逗号
    }
    std::cout << "\n";
}
```

```bash
g++ -std=c++20 -Wall -Wextra comma_op.cpp -o cm && ./cm
```

```text
k=7 i=3 j=4
0/5 1/4 2/3
```

`for (int a = 0, b = 5; ...)` 里的逗号是**分隔符**（声明语句），而 `++a, --b` 里的是**运算符**。同一个 `for` 头里两种逗号都冒出来了——这正是它让人犯晕的地方。

### 5.9.2 什么时候真的该用它
{: .sec-best}

三个正当场景：

1. **for 循环的多个推进表达式**：`for (int i = 0, j = n - 1; i < j; ++i, --j)`。
2. **while 里"取一个值再判断"**：`while (std::getline(is, line), !line.empty())`。
3. **宏里需要多条语句又不能用 `do-while` 的地方**：配合括号保证优先级。

除此之外基本都是误用。看到 `foo(), bar();` 这种写法，直接拆成两行——逗号运算符在这里唯一的作用就是让代码更难读。

> **坑：** C++20 起，下标表达式里的逗号（`a[i, j]`）被**弃用**（它其实是 `a[(i, j)]`，几乎肯定不是本意）。新代码里别这么写。
{: .sec-pit}

### 5.9.3 运算符重载的边界（预告）
{: .sec-ext}

C++ 里不能重载的：`::`、`.`、`.*`、`?:`、`sizeof`、`alignof`、`typeid`、四种命名 cast，还有 `#`、`##`。能重载的里面，`&&`、`\|\|`、`,` 这三个即便重载也保得住 C++17 的顺序保证（用运算符记法调用时），丢掉的只是短路——两个操作数照样都被求值。这大概是"重载会丢东西"这条经验里，最常被夸大的一半。

运算符重载的完整内容放到第 9 篇去讲。这一节我只留一个我自己的取舍标准：**重载完之后，读代码的人得觉得"它和内建版本行为一致"**。做不到的（比如 `operator+` 干减法、`operator<<` 打日志）就是给自己挖坑——我个人不推荐。

## 5.10 技术解惑
{: .sec-expl}

### 5.10.1 优先级记不住怎么办
{: .sec-know}

按开篇那三档记：后缀 > 一元 > 中间一长串 > 条件/赋值/逗号。中间那串只记两个"反常识"点：移位比关系高，`&`/`^`/`\|` 比 `==` 低。剩下的交给括号——GCC/Clang 开 `-Wparentheses` 会在 `a & b == c` 这种地方主动戳你一下。

### 5.10.2 `i++ + ++i` 到底等于几
{: .sec-know}

没有答案，因为它就是未定义行为。`+` 的两个操作数之间没有顺序保证，两次对 `i` 的写彼此未排序，标准从此不再规定任何行为。换个编译器或优化级别，结果就可能变。别猜了，拆成两句就完事（见 5.5.3）。

### 5.10.3 `1 << 31` 为什么有时是负数有时崩
{: .sec-know}

`1` 是 `int`（32 位有符号），`1 << 31` 的结果 2147483648 装不进 `int`。C++20 之前这是 UB（通常会出负数，因为位模式恰好是 `INT_MIN`）；C++20 起因二补数被正式采纳，结果就定义为负数。**不管哪个版本，它都不是"一个正数"**。要一个最高位的掩码，写 `1u << 31`（无符号）或 `1ull << 31`。

### 5.10.4 `sizeof` 后面到底要不要括号
{: .sec-know}

两种形式都合法：`sizeof(expr)` 和 `sizeof(type-id)`。作用于**表达式**时括号能省（`sizeof i` 合法，只是可读性差）；作用于**类型**时括号必写（`sizeof(int)` 行，`sizeof int` 是语法错误）。还有个老陷阱：`sizeof(a)` 在 `a` 是数组名时得数组大小，在 `a` 是指针时是指针大小——括号说了不算，上下文才算。

### 5.10.5 怎么判断一个整数是不是 2 的幂
{: .sec-know}

`n != 0 && (n & (n - 1)) == 0`。C++20 之后直接写 `std::has_single_bit(n)`（要求无符号类型）。别忘了 `n != 0` 那个判断——漏掉的话，`is_power_of_two(0)` 会返回 true。

### 5.10.6 位运算该用什么类型
{: .sec-know}

一律用**无符号**（`std::uint32_t`、`std::uint64_t` 这类定宽类型）。理由：有符号的右移、取反、左移溢出，统统踩在实现定义或 UB 的边沿；而且混算时符号位行为在 C++20 之前没统一规定。取反一个标志位掩码时，`~0u` 是清楚的"全 1"，`~0` 却依赖你对 `int` 的假设。

### 5.10.7 `x & 1 == 0` 为什么不对
{: .sec-know}

因为 `==` 优先级比 `&` 高，表达式被解析成 `x & (1 == 0)`，也就是 `x & false` → `x & 0` → 恒为 0。正确写法是 `(x & 1) == 0`。这个坑在判断标志位时实在太常见了，开 `-Wparentheses`（GCC 的 `-Wall` 里已包含）会跳出来提醒。

### 5.10.8 短路求值能用到什么程度
{: .sec-know}

内建的 `&&`、`\|\|`、`?:`、`,` 这四个的顺序保证是语言硬规则，可以无条件依赖——指针判空、越界检查、分步初始化全靠它们。四个里只有前两个能让程序**少算**右边表达式，这才是短路，也是重载之后唯一会丢掉的东西（`?:` 压根不能重载）。另要分清：短路保证的是"求值顺序"，不是"可见性"——多线程下 `if (p && p->ready)` 照样需要原子或锁。

### 5.10.9 `a = b = c` 的求值顺序是什么
{: .sec-know}

赋值是右结合的，所以解析成 `a = (b = c)`。求值顺序上，C++17 起保证"右操作数整体先于左操作数"：先算 `b = c`（含其副作用），再算 `a` 的身份，最后把值赋给 `a`。C++17 之前只有"操作数的**值计算**先于赋值本身"这一条，副作用顺序没保证——这正好是 5.5.3 那张表的来由。

### 5.10.10 为什么模板里要写 `vector<vector<int>>` 的空格
{: .sec-know}

C++11 之前，`>>` 会被词法分析器当成一个右移运算符，所以嵌套模板必须写成 `vector<vector<int> >`。C++11 专门修了这个（现在 `>>` 在模板实参结尾会被正确切开），所以 C++11 之后两种写法都对。老代码里看到那个空格，基本就能判断它的年代。

## 知识点速查
{: .sec-chk}

| 节点 | 要点 | 版本 |
| --- | --- | --- |
| 赋值 | 是表达式，右结合；返回左值引用 | C++98 起 |
| 复合赋值 | 左操作数只求值一次；内含隐式回转 | C++98 起 |
| 有符号溢出 | UB；`-fsanitize=undefined` 可查 | C++98 起 |
| 无符号溢出 | 定义良好，按 2^N 取模 | C++98 起 |
| 混算 | 有符号被转成无符号；`size()-1` 变 SIZE_MAX | C++98 起 |
| 整数除法 | 向零取整（C++11 明确规定）；除零 UB | C++11 |
| 取余 | 符号跟被除数；`INT_MIN % -1` 是 UB | C++11 |
| 浮点比较 | 不用 `==`；相对 epsilon + 近零兜底；NaN 无解 | — |
| 求值顺序 | C++17：赋值右先于左、`<<` 左先于右、实参不交错 | C++17 |
| 序列点 | C++11 废除，改用 sequenced-before | C++11 |
| 链式比较 | `a < b < c` 是 `(a<b)<c`，写 `a<b && b<c` | — |
| 三路比较 | `<=>` + strong/weak/partial_ordering；默认 `<=>` 送 `==` | C++20 |
| 短路 | `&&` `\|\|` `?:` 有短路；重载 `&&`/`\|\|` 后只剩顺序保证，短路消失 | C++98 起 |
| `++i` vs `i++` | 内建类型无差别；迭代器上后置多一次拷贝 | — |
| 位掩码 | 测试要加括号：`(f & M) != 0` | C++98 起 |
| `n & (n-1)` | 消去最低位的 1；判 2 的幂要加 `n != 0` | — |
| 异或交换 | 反模式；别名时清零；用 `std::swap` | — |
| 移位 UB | 移位数越界一律 UB；左移负数 C++20 起有定义 | C++20 |

## 动手练
{: .sec-ex}

1. **优先级验证**：写 10 个表达式（含 `a & 1 == 0`、`a << 1 < b`、`*p++`、`a || b && c`），先用三档记忆法写出你预期的结果，再编一个程序打印真实结果，逐个对照。把判断错的那几个记下来。
2. **溢出三连**：写 `int` 溢出、`unsigned` 回绕、混算 `size()-1` 三个小程序，分别用 `-O0`、`-O2`、`-O2 -fsanitize=undefined` 编译运行，记录三次的差异。特别留意"开优化后边界检查被消掉"那一个。
3. **`<bit>` 改造**：找一段手写位技巧的老代码（判 2 的幂、数 1 的个数、向上取整到 2 的幂、循环移位），全部换成 `<bit>` 里的标准函数，然后对比 `-O2` 下的汇编，看看是不是真的映射到了 `popcnt`/`lzcnt`。
4. **三路比较**：给一个有 3 个成员的结构体（比如 `struct Person { std::string name; int age; }`）写 `auto operator<=>(const Person&) const = default;`，验证 `<`、`<=`、`==`、`!=` 都能用。再改成手写版本，让比较只按 `age`、忽略 `name`，看看返回类型该是什么。
5. **`ssize` 反死循环**：把 5.2.3 里的死循环版本、倒序 `size_t` 版本、反向迭代器版本、`ssize` 版本各写一遍，确认只有第一个会死循环。然后给项目 CI 加上 `-Wsign-compare -Wsign-conversion`。

## 变式追问
{: .sec-think}

1. `f(++i, ++i)` 在 C++17 之后还是未定义行为吗？

   不是 UB，但也没有确定的结果。C++17 规定函数各实参的初始化彼此是 **indeterminately sequenced**——"一个完整地跑完再跑另一个，不交错，但哪个先 unspecified"。所以两次自增不会互相穿插（这点满足了"两个写不能未排序"的要求，因此不再是 UB），但 `i` 到底被加了几次后传给第一个参数、几次后传给第二个，没有规定。结论：这是个"能编过、不崩、但你算不出答案"的表达式，和 UB 一样不能写。

2. 为什么 `unsigned` 溢出被定义成取模，而 `signed` 溢出是 UB？

   这不是随意的，是给优化器留的空间。如果规定了有符号溢出回绕，编译器就不能做一大批依赖"没有溢出"的代数化简——比如 `i + 1 > i` 恒真、`(a * 10) / 10 == a`、`for (int i = 0; i <= n; ++i)` 不需要处理回绕。把有符号溢出定为 UB，等于允许编译器假设它永不发生，从而在这些地方生成更好的代码。无符号类型从来被当作"模运算 + 位模式"语义使用（位掩码、哈希、环形索引），它的溢出本来就是要的行为，所以标准直接定义了。这个取舍的代价是：有符号溢出的 bug 是静默的，必须靠 `-fsanitize=undefined` 去抓。

3. `sizeof(arr) / sizeof(arr[0])` 求元素个数，在什么情况下会给出错的答案？

   只要 `arr` 不是"真正的数组"就错。三种情形：数组作为函数形参（退化成指针，结果是指针大小除以元素大小，通常得 2 或 1）；`arr` 本身是指针（`int* p = new int[10]; sizeof(p)/sizeof(p[0])` 得 2）；数组是通过指针别名拿到的。C++17 起用 `std::size(arr)`：它在数组语境下给出元素个数，在传进函数后……也一样救不了你——因为形参已经是指针了，信息在函数入口就丢了。真正该做的要么传 `std::span`（C++20，同时带指针和长度），要么直接传容器。

4. `1e16 + 1 == 1e16` 是 true，那是不是说明"大数用 double 完全可以"？

   反过来读才对：这个 true 恰恰说明 double 在大数量级上**分辨不出 1 的差别**。double 有 53 位有效位，约 15~16 位十进制有效数字；到了 1e16 这个量级，相邻可表示数之间的间隔（ULP）已经是 2 左右，所以 +1 直接被舍掉。结论不是"可以用"，而是"要知道它什么时候不能用"：做累加计数的用整数（或至少有符号的 `std::int64_t`），做时间差/金额差时先估算 ULP 再决定精度，做比较时用相对 epsilon（5.2.5）。把 `double` 当计数器用是数值代码里最典型的慢性 bug。
