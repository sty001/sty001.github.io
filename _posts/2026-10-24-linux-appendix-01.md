## 七、帮助与命令定位

| 命令 / 参数 | 说明 |
| --- | --- |
| `man 查看的命令` | 查看命令手册信息 |
| `which 命令` | 显示命令文件所在路径位置 |
| `whereis` | 查看命令所在路径以及命令相关手册文件所在路径 |
| `locate` | 查看文件所在路径信息 |

`man` 手册的常见结构：

- `NAME`：命令作用说明，例如 `mkdir - make directories`
- `SYNOPSIS`：命令使用方法，例如 `mkdir [OPTION]... DIRECTORY...`
- `DESCRIPTION`：命令的参数解释，例如 `-p, --parents  no error if existing, make parent directories as needed`

## 十三、高级命令：四剑客

课程中把 `find`、`grep`、`sed`、`awk` 称为"四剑客"，按常用程度排序为：老大 `awk`、老二 `sed`、老三 `grep`、老四 `find`。

## 十七、Linux 运维经验语录

1. 一切从根开始。

2. 在 Linux 系统中一切皆文件：目录是特殊的文件，存储设备是特殊文件，命令也是命令文件。

3. Linux 系统中服务配置文件被修改之后，不会立即生效。需要重启服务（重新加载读取配置文件过程），才能使配置文件的修改生效。

4. 在系统中对配置进行永久修改时，都需要修改配置文件；在命令行的修改，大部分情况都是临时修改。

5. 学习好运维：听话、出活。

6. 在企业中运维主要干什么：

   | 能力阶段 | 说明 |
   | --- | --- |
   | 部署服务（命令） | 5000 - 6000 |
   | 排错能力 | 9000 |
   | 服务或系统优化能力 | 10000 以上 |
   | 数据的分析能力 | 15000 以上 |
   | 架构能力 | 20000 以上 |

7. 一种错误情况："你以为"。例如外网不通了，先 `ping 223.5.5.5` 排查；yum 源也要检查。

8. 安全和系统性能（管理系统效率）是成反比的：系统越安全，管理起来效率越低；系统越不安全，管理起来效率越高。

9. 在编写 Linux 配置文件信息时，能复制就不要手敲。

10. 企业工作中出现严重异常问题时，运维排错的大招：

    ```text
    a 服务重新安装
    b 重启系统 reboot
    c 重新安装系统
    ```

11. 系统中不是所有命令都可以对文件进行编辑修改，可用：`vim 文件`、`sed -i`、`cat >>`、`echo >>`、`>`。
