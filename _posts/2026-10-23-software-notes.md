记录一点关于软件工程方法论的梳理，偏重「可落地的工程实践」而非纯理论。

## 需求拆解

- 把模糊的需求拆成 **用户故事（User Story）**，每条都可验收
- 用 **MoSCoW** 区分 Must / Should / Could / Won't
- 接口契约先行：先定义 API / 数据结构，再写实现

## 代码组织

- 单一职责 + 依赖倒置，避免上帝类
- 用分层（controller / service / repository）隔离变化
- 提交信息遵循 Conventional Commits，方便自动生成 CHANGELOG

## 上线与可观测

- 灰度发布 + 特性开关（Feature Flag）
- 日志、指标、链路追踪三者缺一不可
- 出问题先回滚，再复盘

> 工程能力的差距，往往不在写代码，而在「让系统稳定地持续交付」。
