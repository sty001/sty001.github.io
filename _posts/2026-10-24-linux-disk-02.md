| 指令 | 说明 |
| --- | --- |
| `mklabel,mktable LABEL-TYPE` | create a new disklabel (partition table)，创建一个分区表（默认为 mbr） |
| `print [devices\|free\|list,all\|NUMBER]` | 显示分区信息、可用设备、剩余空间、所有分区或某个分区 |
| `mkpart PART-TYPE [FS-TYPE] START END` | 创建一个分区 |

| `rm NUMBER` | 删除编号为 NUMBER 的分区 |

修改磁盘分区类型并分区：

```bash
修改磁盘分区类型: mklabel gpt
分区方法: mkpart primary 0  2100G
```

**第三个里程：加载磁盘分区**

```bash
partprobe /dev/sdc
```

> **注意：** parted 与 fdisk 不同，命令立即生效、没有"保存退出"的概念；`mkpart primary 0 2100G` 的 START 从 0 开始即可（parted 内部会做 1MiB 对齐）。GPT 分区超过 2T 是常态，若要在同一块盘上分多个大于 2T 的分区，逐个 `mkpart` 即可。生产环境更常见的做法是：整块盘只建一个分区做 LVM 的 PV，后续弹性分配。

```bash
mkfs.xfs  /dev/sdb1
```

常用格式化命令速查：

| 命令 | 说明 |
| --- | --- |
| `mkfs.xfs /dev/sdb1` | 创建 xfs 文件系统 |
| `mkfs -t xfs /dev/sdb1` | 等价写法 |
| `mkfs.ext4 /dev/sdb1` | 创建 ext4 文件系统 |

| `resize2fs /dev/sdb1` | 在线调整 ext4 大小 |
| `e2fsck -f /dev/sdb1` | 检查修复 ext 系列 |
| `xfs_repair /dev/sdb1` | 检查修复 xfs（需先卸载） |

### 辨析：ext4 与 xfs

| 对比项 | ext4 | xfs |
| --- | --- | --- |
| 设计取向 | 通用，小文件与目录操作友好 | 大文件、高并发顺序 I/O 强 |
| 在线扩容 | 支持（`resize2fs`） | 支持（`xfs_growfs`） |
| 在线缩减 | 支持（需先卸载） | 不支持 |
| 崩溃修复速度 | 慢，全盘扫描 | 快，按分配组并行修复 |
| 代表发行版 | RHEL 6 | RHEL 7+ |

xfs 为什么只能扩大不能缩小？缩小的本质是把数据搬走、再归还空间，xfs 的空间按分配组（AG）管理，设计上没有实现"收缩搬移"这条路径，官方也明确不打算补。所以 xfs 盘一开始就要规划好容量，需要弹性收缩能力就选 ext4。反过来说，只增不减的场景（日志、备份、数据库）用 xfs 反而省心——不用担心缩错顺序丢数据。一句话选型：拿不准就 xfs（新系统默认），明确要在线缩减或大量小文件场景再上 ext4。

## 四、磁盘挂载应用

```bash
mount /dev/sdb1 /mount01
mount /dev/sdb2 /mount02
```

检查确认：

```bash
[root@linux-node1 /]# df -h
/dev/sdb1      1014M   33M  982M   4% /mount01
/dev/sdb2      1014M   33M  982M   4% /mount02
```

卸载报 `target is busy` 的处理：先找占用者——`lsof +D /mount01` 或 `fuser -mv /mount01`，结束对应进程或让它退出该目录，再正常 `umount`。这里有个坑：占用者常常就是另一个 SSH 窗口里 `cd` 进了挂载点的你自己的 shell，最隐蔽也最常见；实在找不到占用者再用 `umount -l` 懒卸载，设备条目会保留到占用结束。

### 4.1 方法一：将挂载命令放入 /etc/rc.local

```bash
[root@linux-node1 /]# tail -2 /etc/rc.local
mount /dev/sdb1 /mount01
mount /dev/sdb2 /mount02
```

系统开机加载 `rc.local` 的流程：

```bash
加载 /etc/rc.local --> /etc/rc.d/rc.local --> 以绝对路径方式执行
/etc/rc.d/rc.local
chmod +x /etc/rc.d/rc.local
```

> **注意：** CentOS 7 中 `/etc/rc.local` 是软链接，真正的文件 `/etc/rc.d/rc.local` 默认没有执行权限，必须 `chmod +x /etc/rc.d/rc.local` 才会生效。该方式属于 systemd 的 `rc-local.service`，执行晚、失败不重试、没有依赖管理，**生产环境的开机挂载请使用 `/etc/fstab`**，rc.local 只留给一次性初始化脚本。

### 4.2 方法二：在 /etc/fstab 文件中进行设置

```bash
UUID=e2fc8646-2b36-47cc-a35a-8c13208f4d0b /          xfs                 defaults            0             0
UUID=34fc45ba-c38c-42bc-a120-90f9d5dd2382 /boot      xfs                 defaults            0             0
UUID=62100743-6f8a-4f83-a37d-e2088c4830e2 swap       swap                defaults            0             0
挂载磁盘文件(存储设备)                   挂载点     指定文件系统类型   挂载的参数    是否备份磁盘  是否检查磁盘
```

```bash
mount 挂载的磁盘文件 挂载点
[root@linux-node1 ~]# tail -2 /etc/fstab
/dev/sdb1                                 /mount01                xfs     defaults        0 0
UUID=144738ff-0da3-4162-b574-40af379cbe9e /mount02                xfs     defaults        0 0
```

| 列 | 含义 |
| --- | --- |
| 第 1 列 | 挂载的磁盘文件（存储设备），可以用设备名或 UUID |
| 第 2 列 | 挂载点 |
| 第 3 列 | 指定文件系统类型 |
| 第 4 列 | 挂载的参数（defaults） |
| 第 5 列 | 是否备份磁盘 |
| 第 6 列 | 是否检查磁盘 |

易错点回顾：设备列优先用 UUID（`blkid` 查询）；dump 列统一 0；fsck 列根分区 1、其他 2、swap 与网络文件系统 0；非系统盘建议加 `nofail` 防止开机卡住，网络文件系统加 `_netdev`。

fstab 改坏是"开机起不来"的常见原因：改完先 `mount -a` 验证一遍，报错当场修，确认无报错再重启；远程改 fstab 前最好另开一个会话兜底。

临时挂载与永久挂载再对一遍：**mount 命令**立即生效，重启即失效，适合临时救急与验证；**/etc/fstab** 开机自动挂载，改完用 `mount -a` 验证——它按 fstab 顺序挂载其中未挂载的项，报错就是配置有误。推荐节奏：先手动 `mount` 挂好、业务验证正常，再写 fstab，下次重启自然接管。`mount -a` 不会重挂已挂载项，所以它验证的是"fstab 能不能挂上"，不保证"当前挂载与 fstab 写的一致"，两步都要核对。

## 五、LVM 逻辑卷管理

LVM（Logical Volume Manager，逻辑卷管理）在物理磁盘与文件系统之间加了一层抽象，把"改分区大小"这种需要重装 / 迁移数据的操作变成在线调整。

### 5.1 原理解析：LVM 的四层结构

LVM 由四个概念自底向上组成：

1. **PV（Physical Volume，物理卷）**：把普通分区 / 整盘标记为 LVM 可用，记录物理位置与 PE 信息，命令 `pvcreate`；
2. **VG（Volume Group，卷组）**：一块或多块 PV 组成的存储池，容量是各 PV 之和，命令 `vgcreate`；
3. **PE / LV（Physical Extent / Logical Volume，物理扩展 / 逻辑卷）**：VG 被切成固定大小的 PE（默认 4MiB，`vgcreate -s` 指定），若干个 PE 拼成 LV，LV 才是最终被格式化和挂载的设备；
4. **设备映射器（device-mapper）**：LV 到 PV 的映射由内核 dm 层实现，所以 LV 的物理位置可以不连续（跨盘、跨分区都行），也不要求连续。

这层抽象说白了就是接水：PV 是矿泉水（单瓶），VG 是把若干瓶倒进去的大水池，LV 是从水池接出来的水管——水池多大由瓶子决定，水管要多粗随时改，管子里流的水来自哪个瓶子并不重要。

这层抽象带来三个直接好处：容量弹性调整（`lvextend` / `lvreduce`）、逻辑跨物理盘（多块小盘拼一个大 LV）、快照（COW 机制，见 5.5）。

### 5.2 创建流程

```bash
# 第一步：准备分区（类型改为 LVM，id 8e；也可以整盘直接用）
fdisk /dev/sdb        # t 修改分区类型为 8e (Linux LVM)，w 保存
partprobe /dev/sdb

# 第二步：创建 PV（把分区纳入 LVM 管理）
pvcreate /dev/sdb1

# 第三步：创建 VG（把 PV 加入存储池，-s 指定 PE 大小，-n 指定 VG 名）
vgcreate vg0 /dev/sdb1

# 第四步：创建 LV（从 VG 中划分逻辑卷）
lvcreate -L 10G -n lv01 vg0          # 指定大小
lvcreate -l 100%FREE -n lv02 vg0     # 用尽 VG 剩余空间
lvcreate -L 5G -n lv03 -i 2 -I 64k vg0   # 条带化跨 2 块 PV，提升吞吐

# 第五步：格式化并挂载
mkfs.xfs /dev/vg0/lv01
mount /dev/vg0/lv01 /data01
echo '/dev/vg0/lv01 /data01 xfs defaults 0 0' >> /etc/fstab
```

> **注意：** LVM 设备路径是 `/dev/卷组名/逻辑卷名`（如 `/dev/vg0/lv01`），`/dev/mapper/vg0-lv01` 与 `/dev/vg0/lv01` 是同一个设备（后者是前者的软链接），fstab 里写哪个都可以。

想看某个 LV 的 PE 分布，`lvdisplay -m /dev/vg0/lv01` 会列出每一段映射到哪块 PV 的哪些 PE，跨盘排障时非常有用。

`-i 2 -I 64k` 的条带化值得单独说一下：把数据交叉写到多块 PV 上，顺序大文件的吞吐能近似翻倍，但前提是 VG 里确实有多块 PV，且任一块 PV 掉线整个 LV 数据就残了。普通业务用不上，数据库、备份盘这类追求吞吐的场景才考虑。

### 5.3 查看状态：pvs / vgs / lvs

```bash
pvs                 # 查看物理卷：PV 名、所属 VG、大小、剩余
vgs                 # 查看卷组：VG 名、PV 数、LV 数、总容量、空闲
lvs                 # 查看逻辑卷：LV 路径、所属 VG、大小、属性
lvdisplay /dev/vg0/lv01     # 查看单个 LV 详情（含 PE 映射）
vgdisplay vg0              # 查看 VG 详情（含 PE 大小与总数）
```

三条信息是排障的第一现场：`vgs` 的 `VFree` 还有没有空闲空间决定能否扩容，`lvs` 的 `Attr` 里出现 `s`（snapshot）或 `m`（mirror）说明这不是普通 LV，`pvs` 发现 PV 丢失说明磁盘掉了。

### 5.4 扩容与缩减

**扩容（在线进行，业务无感知）：**

```bash
# 场景一：VG 里还有空闲空间，直接扩 LV
lvextend -L +5G /dev/vg0/lv01
xfs_growfs /data01                  # xfs：按挂载点增长文件系统
# resize2fs /dev/vg0/lv01           # ext4：按设备增长文件系统

# 场景二：VG 空间不足，先加 PV 再扩
pvcreate /dev/sdc1
vgextend vg0 /dev/sdc1
lvextend -L +50G /dev/vg0/lv01
xfs_growfs /data01
```

**缩减（仅 ext4 支持，xfs 不支持缩减）：**

```bash
umount /data01                       # 必须卸载
e2fsck -f /dev/vg0/lv01              # 先检查文件系统
resize2fs /dev/vg0/lv01 8G           # 先把文件系统缩到 8G
lvreduce -L 8G /dev/vg0/lv01         # 再把 LV 缩到 8G
mount /dev/vg0/lv01 /data01
```

为什么顺序不能反：LV 只认块区间，文件系统若还占着即将被裁掉的区域，裁掉的就是有效数据；先把文件系统缩进目标大小以内，LV 裁掉的部分才是真正空闲的。

> **注意：** 缩减的顺序一定是"先缩文件系统、再缩 LV"，顺序颠倒会丢数据；xfs 逻辑卷只能增长不能缩减，这是 xfs 的机制限制，需要预留缩减能力的场景应选 ext4。`lvreduce` 默认会要求交互确认，`-y` 可跳过（确认无误再用）。

### 5.5 删除流程

```bash
umount /data01
vim /etc/fstab                      # 删掉对应挂载行
lvremove /dev/vg0/lv01              # 删除 LV
vgremove vg0                        # 删除 VG
pvremove /dev/sdb1                  # 移除 PV 标记
```

删除前用 `lvs` 确认没有业务在用；快照 LV（属性带 `s`）会随原 LV 一起删，如果只想删快照，直接 `lvremove 快照路径`。

### 5.6 LVM 快照

**原理：** 快照是同一 VG 内的一个特殊 LV，创建时与原 LV 共享全部数据块（几乎不占空间）；之后原 LV 有数据块要被修改时，先把旧内容复制到快照的预留空间（COW，写时复制），再覆盖原块。因此快照保存的是"创建那一刻"的数据视图，占用随原卷的变化量增长。

**用途：**

1. 备份一致性：对数据库 / 正在写入的目录做快照，再从快照备份，避免备份到"改了一半"的数据；
2. 快速回滚：误操作（`rm -rf`、错误脚本写入）后，可以把原 LV 回滚到快照状态；
3. 测试验证：给生产数据打快照挂到测试机验证变更，不影响生产。

```bash
# 创建快照（-s 指定快照，-L 指定预留空间，一般留原卷的 15%-30%）
lvcreate -s -L 2G -n lv01_snap /dev/vg0/lv01

# 查看快照
lvs /dev/vg0/lv01_snap

# 从快照备份
mount /dev/vg0/lv01_snap /mnt/snap
tar zcf /backup/data.tar.gz -C /mnt/snap .
umount /mnt/snap

# 回滚（谨慎：会丢弃快照创建后的所有修改）
lvconvert --merge /dev/vg0/lv01_snap

# 用完删除快照
lvremove /dev/vg0/lv01_snap
```

> **注意：** 快照空间耗尽后会**自动失效**（数据块改不动，原卷写入直接报错），所以快照是临时手段，备份完成后应立即删除；快照与源 LV 必须在同一个 VG 内。

可以对同一个源 LV 建多个快照，每个快照独立记录自己的变化量；快照之上再叠快照会形成快照链，读取要走链回溯，性能逐层下降，尽量保持单层快照、用完即删。

## 六、企业常见问题：磁盘满

`No space left on device` 有两种完全不同的原因。

### 6.1 block 存储空间不足：存储的数据过多了

模拟磁盘空间不足：

```bash
dd if=/dev/zero of=/tmp/test.txt  bs=10M count=100
```

解决方式：

```bash
a 删除没用的数据
b 找出大的没用的数据
  find / -type f -size +xxx
  du -sh /etc/sysconfig/network-scripts/*|sort -h
```

遇到文件名乱码删不掉的文件，用 inode 号处理：`ls -i 目录` 先查 inode 号，再 `find 目录 -inum 12345 -delete` 删除，绕开文件名直接定位。删除海量小文件也优先用 `find 目录 -type f -delete`，比 `rm -rf *` 稳——通配符展开的参数列表会被撑爆。

补充：按照数值排序命令

```bash
[root@linux-node1 mount01]# cat num.txt |sort -n
# 1
# 10
# 11
# 12
# 2
# 3
# 6
# 9
[root@linux-node1 mount01]# cat num.txt |sort -n -k2
# 1
# 2
# 3
# 6
# 9
# 10
# 11
# 12
```

> **注意：** 直接 `sort -n` 是按整行的字典序排的，看起来"1 10 11 12 2 ..."；用 `-k2` 指定按第 2 列排序才能得到"1 2 3 6 9 10 11 12"。

### 6.2 inode 存储空间不足：出现了大量小文件

查看方式：`df -i`；解决方式：删除大量没用的小文件。

### 6.3 疑难场景：删了文件空间不释放

生产环境更隐蔽的一类"磁盘满"：`du` 统计已经变小，但 `df` 显示空间没回来。原因是文件被删除后，只要有进程还打开着它的文件描述符，内核就不会释放其占用的 block。

```bash
# 1. 找出被删除但仍被占用的文件
lsof +L1                      # 直接列出链接数为 0（已删除）的打开文件
lsof | grep deleted           # 通用写法
ls -l /proc/<PID>/fd          # 看某进程持有的文件描述符

# 2. 三种处理方式
# a. 通知进程重新打开日志（如 nginx -USR1  reopen、logrotate）
# b. 直接清空被占用文件的内容（保留 fd，空间立即释放）
> /proc/<PID>/fd/<FD号>
# c. 重启服务（最后手段）
```

NFS 场景另有一类"删不掉"：`.nfsXXXX` 隐藏文件是客户端还在打开的文件，等客户端关闭后自动消失，不要反复 rm 较劲。

```bash
# 排查磁盘满的标准流程
df -h                                   # 哪个文件系统 block 满了
df -i                                   # 是否 inode 耗尽
du -sh --max-depth=1 /var/log 2>/dev/null   # 逐层定位大目录
lsof +L1                                # 是否有已删除文件未释放空间
```

### 辨析：inode 耗尽与 block 耗尽

两者报错一模一样（`No space left on device`），现象完全不同：

- **block 耗尽**：`df -h` 使用率逼近 100%，`df -i` 正常；文件数量不多但单个很大，`du` 能直接找到元凶；
- **inode 耗尽**：`df -i` 的 IUse% 逼近 100%，`df -h` 却显示大量剩余空间；文件数量极其庞大、单个很小，`du` 扫半天也找不出几个大文件。

说白了，block 是放数据的柜子，inode 是登记文件的户口本——柜子没满但户口本用完了，照样写不进任何新文件。典型肇事场景：邮件队列、session 文件目录、crontab 每分钟落盘的小文件（这正是定时任务要重定向到黑洞的原因）。

## 七、swap 分区管理

swap 是磁盘上划出的一块"内存扩展区"：物理内存吃紧时，内核把不活跃的页换出到 swap，避免直接 OOM（Out of Memory）杀进程。**第一个历程：将磁盘分出一部分空间给 swap 分区使用**

```bash
dd if=/dev/zero  of=/tmp/1G  bs=100M count=10
```

**第二个历程：将指定磁盘空间作为 swap 空间使用**

```bash
[root@linux-node1 tmp]# mkswap /tmp/1G
Setting up swapspace version 1, size = 1023996 KiB
no label, UUID=6dd70684-dec2-48cf-8fd9-f311548bbb4f
```

**第三个历程：加载使用 swap 空间**

```bash
[root@linux-node1 tmp]# swapon /tmp/1G
swapon: /tmp/1G: insecure permissions 0644, 0600 suggested.
[root@linux-node1 tmp]# free -h
              total        used        free      shared  buff/cache   available
Mem:           1.9G        225M        575M        9.6M        1.2G        1.5G
Swap:          2.0G          0B        2.0G
[root@linux-node1 tmp]# swapoff /tmp/1G
[root@linux-node1 tmp]# free -h
              total        used        free      shared  buff/cache   available
Mem:           1.9G        224M        576M        9.6M        1.2G        1.5G
Swap:          1.0G          0B        1.0G
[root@linux-node1 tmp]# rm /tmp/1G -f
```

> **注意：** `swapon` 提示权限不安全时，按提示把文件权限改为 0600（`chmod 600 /tmp/1G`）即可；`swapoff` 后可以安全删除该文件。

补充：用**独立分区**做 swap（更正规，性能略好）：

```bash
fdisk /dev/sdb          # 建分区后 t 修改类型为 82 (Linux swap)
mkswap /dev/sdb2
swapon /dev/sdb2        # 临时启用
free -h                 # 验证

# 永久生效写入 fstab
echo 'UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx swap swap defaults 0 0' >> /etc/fstab
swapon -a               # 按 fstab 启用全部 swap
```

swap 管理命令速查：

| 命令 | 作用 |
| --- | --- |
| `free -h` | 查看内存与 swap 使用概况 |
| `swapon -s` / `swapon --show` | 查看当前启用的 swap 设备与优先级 |
| `swapon -p 10 /dev/sdb2` | 启用并指定优先级（数值越大越优先） |
| `swapoff /dev/sdb2` | 停用 swap |
| `cat /proc/sys/vm/swappiness` | 查看 swap 倾向（0-100，默认 60） |
| `sysctl -w vm.swappiness=10` | 降低 swap 使用倾向（数据库服务器常用） |

> **注意：** swap 只是"缓冲"，不是"扩容"：进程页被换出到磁盘后，访问时要换入，必然伴随 I/O 抖动。数据库、Redis 等对延迟敏感的服务，应把 `vm.swappiness` 调到 10 甚至 1，靠物理内存与容量规划解决问题；服务器内存不足时的正确姿势是加内存，而不是把 swap 调大。

swappiness 白话：数值代表内核"愿意把内存页换出去"的相对程度，越高越积极换出。内存明明够用却频繁换页，就是在白白浪费 I/O，调低到 10 让内核尽量扛住物理内存。

内存特别紧张的机器还可以看 zram：把 swap 建在压缩内存里，速度远快于磁盘 swap，代价是占用少量 CPU 做压缩，Rocky/AlmaLinux 装上 `zram-generator` 即用。

## 八、磁盘配额 quota

多用户共用一台服务器 / 存储时，需要限制单个用户或组能占用多少空间，避免某个用户把盘写满影响所有人。这就是 quota：对用户 / 组设置 block 与 inode 上限，超限即禁止写入。

核心概念：

| 概念 | 含义 |
| --- | --- |
| 软限制（soft limit） | 达到时警告，但在宽限期内仍可继续写 |
| 硬限制（hard limit） | 绝对上限，达到立即禁止写入 |
| 宽限期（grace period） | 超过软限制后，允许超限使用的时长，默认 7 天 |

配置流程（以 ext4 为例）：

```bash
# 1. 挂载时开启配额支持
mount -o remount,usrquota,grpquota /data01
# 或在 fstab 的挂载参数中加 usrquota,grpquota 后 mount -a

# 2. 创建配额数据库文件并扫描
quotacheck -cugm /data01

# 3. 开启配额
quotaon /data01

# 4. 给用户设置限制（block 软 100M/硬 200M，inode 软 10000/硬 20000）
setquota -u ops 102400 204800 10000 20000 /data01
# 或交互式编辑：edquota -u ops

# 5. 查看
quota -u ops                  # 查看某用户的配额使用
repquota /data01              # 汇总报告所有用户配额

# 6. 关闭
quotaoff /data01
```

常用命令表：

| 命令 | 作用 |
| --- | --- |
| `quotacheck -cugm 挂载点` | 创建配额数据库（aquota.user / aquota.group） |
| `quotaon` / `quotaoff 挂载点` | 开启 / 关闭配额 |
| `edquota -u 用户名` | 交互式编辑用户配额 |
| `setquota -u 用户 块软 块硬 inode软 inode硬 挂载点` | 非交互设置 |
| `repquota -a` | 输出全部文件系统的配额使用报告 |
| `quota -u 用户名` | 用户自查自己的配额用量 |

> **注意：** xfs 的配额机制不同，不用 quotacheck 系列命令，而是用 `xfs_quota -x -c 'limit -u bsoft=100m bhard=200m ops' /data01` 管理，且 xfs 推荐在挂载参数用 `uquota` / `gquota`。给一批用户设置相同配额时，先用 `edquota -u 模板用户` 调好，再 `edquota -p 模板用户 用户1 用户2` 批量套用，效率最高。

配额之外的思路：给每个业务单独分一个文件系统（或 LVM 卷），物理上限直接锁死，还能避免一个业务写满影响全局——很多场景下这比配额更省心。

## 九、磁盘性能查看

磁盘满了会报错，磁盘慢了却"没脾气"，需要主动观测。三个层次的工具：

| 工具 | 视角 | 常用命令 |
| --- | --- | --- |
| `iostat` | 设备级 I/O 统计（sysstat 包） | `iostat -x 1` 每秒刷新全部磁盘明细 |
| `iotop` | 进程级 I/O 排序，看谁在写盘 | `iotop -oPa` 只看活跃进程与 I/O |
| `sar` | 历史性能数据回溯（sysstat 包） | `sar -d 1 10`；`sar -b 1`（I/O 传输速率） |

`iostat -x` 的关键指标解读：

| 指标 | 含义 | 危险信号 |
| --- | --- | --- |
| `%util` | 设备繁忙百分比 | 持续接近 100% 说明磁盘已饱和 |
| `await` | I/O 平均等待时间（毫秒） | 机械盘持续大于 20ms 需关注 |
| `r/s` / `w/s` | 每秒读 / 写请求数 | 与业务量对比判断是否异常 |
| `rkB/s` / `wkB/s` | 每秒读 / 写数据量 | 持续打满接口带宽 |
| `svctm` | 单次 I/O 服务时间（已废弃但仍有参考性） | — |

```bash
# 安装
dnf install -y sysstat iotop

# 实时观察（Ctrl+C 退出）
iostat -x 1
iotop -oPa

# 回溯昨天的历史数据（sar 默认保留 /var/log/sa/）
sar -d -f /var/log/sa/sa24
```

> **注意：** 判断"磁盘慢"不能只看 `%util`：机械盘随机小 I/O 场景下 `%util` 高但吞吐低，说明该上 SSD 或做 I/O 合并；`await` 高而 `%util` 低，先怀疑存储网络（NFS / iSCSI）或阵列缓存问题。性能数据要结合业务基线看，单点数值意义有限。

磁盘性能三个量互相牵制：IOPS、吞吐（MB/s）、延迟。机械盘 IOPS 上不去是寻道拖的，吃吞吐要靠顺序大块 I/O；SSD 吞吐充裕，瓶颈常在队列深度与驱动。压测时固定两个量、只动一个量，否则结论没有意义。

压测工具 `fio` 一例：`fio --name=t --filename=/data01/fio.tmp --size=1G --rw=randread --bs=4k --iodepth=32 --direct=1 --runtime=30 --time_based`，测 4K 随机读 IOPS。写压测会写出指定大小的文件，注意留空间、测完删临时文件；`--direct=1` 绕过缓存，结果才是真实盘速。压测要在业务低峰跑，避免影响在线业务。对比两块盘时用相同参数各跑一轮，关注 IOPS 与延迟分位数而非只看平均值。后台备份这类重 I/O 任务，用 `ionice -c3` 包起来以空闲优先级运行，避免挤占在线业务的 I/O。

## 十、dd 命令与坏块检测

### 10.1 dd 参数详解

`dd` 按块复制数据，是磁盘克隆、备份引导记录、制造测试文件的底层工具：

| 参数 | 英文 | 作用 |
| --- | --- | --- |
| `if=` | input file | 输入源（文件或设备） |
| `of=` | output file | 输出目标（文件或设备） |
| `bs=` | block size | 块大小，如 `bs=10M` |
| `count=` | count | 复制多少个块 |
| `skip=` | skip | 输入侧跳过多少块（从中间开始读） |
| `seek=` | seek | 输出侧跳过多少块（写入到指定位置） |
| `conv=fsync` | fsync | 结束时强制刷盘，测速必须加 |
| `conv=noerror` | noerror | 读错误不中断（配合 `sync` 补零） |
| `conv=notrunc` | notrunc | 不截断输出文件（保留原有内容） |
| `status=progress` | status | 实时显示进度 |
| `oflag=direct` | direct | 绕过缓存直写，测真实磁盘性能 |

典型用法：

```bash
# 1. 磁盘克隆：整盘对拷（目标盘容量必须不小于源盘）
dd if=/dev/sda of=/dev/sdb bs=64M conv=fsync status=progress

# 2. 备份与恢复 MBR（引导记录 + 分区表）
dd if=/dev/sda of=/tmp/mbr.bak bs=512 count=1
dd if=/tmp/mbr.bak of=/dev/sda bs=512 count=1

# 3. 备份分区表（仅分区表，不影响数据）
sfdisk -d /dev/sda > /tmp/sda.pt
sfdisk /dev/sda < /tmp/sda.pt

# 4. 制造测试文件 / 测磁盘写入速度
dd if=/dev/zero of=/tmp/testfile bs=1M count=1000 oflag=direct status=progress

# 5. 安全擦除磁盘（破坏性操作，执行前确认设备名）
dd if=/dev/zero of=/dev/sdb bs=10M status=progress

# 6. 测试读取性能
dd if=/dev/sdb1 of=/dev/null bs=1M count=1000 iflag=direct status=progress
```

> **注意：** `dd` 没有进度提示时极易误判为死机，养成加 `status=progress` 的习惯；`if` 与 `of` 写反（尤其目标是系统盘）会造成不可逆的数据灾难，执行前逐字核对设备名，生产环境操作前先 `lsblk` 确认。

测盘速也有讲究：`oflag=direct` 绕过页缓存测真实落盘，不加它测出来的是"假速度"（数据只进了内存就报完成）；先测写再测读，多次取平均；对比基线必须用相同参数，换参数就没有可比性了。

### 10.2 坏块检测 badblocks

磁盘使用年限增长后可能出现坏道，写入报错、文件莫名丢失都可能是前兆。`badblocks` 用于检测块设备的坏块：

```bash
# 1. 只读检测（安全，不影响数据）
badblocks -sv /dev/sdb1
# -s 显示进度，-v 详细输出

# 2. 读写检测（非破坏性，先备份数据再用）
badblocks -nsv /dev/sdb1
# -n 非破坏性读写模式

# 3. 写检测（破坏性，会抹掉数据，新盘验收用）
badblocks -wsv /dev/sdb1

# 4. 结果写入文件，供文件系统工具使用
badblocks -sv /dev/sdb1 > /tmp/badblocks.txt
e2fsck -l /tmp/badblocks.txt /dev/sdb1    # 让 ext 文件系统标记这些坏块
```

| 参数 | 作用 |
| --- | --- |
| `-s` | 显示检测进度 |
| `-v` | 详细模式 |
| `-n` | 非破坏性读写测试 |
| `-w` | 破坏性写测试（抹数据） |
| `-b 块大小` / `-c 簇大小` | 指定检测块大小 |
| `-o 输出文件` | 把坏块清单写入文件 |

> **注意：** 检测只读、写坏块报告用文件收。对于 RAID 阵列，坏块检测应交给 RAID 卡的管理工具（如 MegaCLI）处理，阵列会通过热备盘自动重建；普通单盘场景 badblocks 才有意义。发现坏块持续增多，应尽快迁移数据并更换磁盘，坏道扩散只是时间问题。

比坏块检测更该养成习惯的是看 SMART：`smartctl -H /dev/sdb` 一眼看健康结论；`smartctl -a /dev/sdb` 重点盯 `Reallocated_Sector_Ct`（已重映射扇区数）与 `Current_Pending_Sector`（待定扇区数），数值持续增长就是盘在退化的信号。用 cron 每周收集一次 SMART 输出，趋势比单次数值更有意义。新盘上架先跑一次 `smartctl -t long` 长测，通过再接业务。

## 常见错误与排错

| 现象 | 可能原因 | 排查命令 | 解决方式 |
| --- | --- | --- | --- |
| `lvextend` 后 `df` 看不到容量变化 | 忘了扩展文件系统 | `df -h`；`xfs_info /挂载点` | xfs 执行 `xfs_growfs 挂载点`，ext4 执行 `resize2fs 设备` |
| LVM 扩容报 `insufficient free space` | VG 没有空闲 PE | `vgs` 看 `VFree` | `vgextend` 加 PV 后再扩 |
| `lvreduce` 导致数据丢失 | 先缩 LV 再缩文件系统，顺序颠倒 | `dmesg | grep xfs` | 按"先文件系统后 LV"操作；xfs 不支持缩减 |
| LVM 快照满了，原盘写入报错 | 快照预留空间不足，COW 无处存放 | `lvs` 看快照 `Cpy%` 使用率 | 删除并重建更大快照；备份完成后立即清理快照 |
| 删了日志 `df` 不降 | 文件被进程占用未释放 | `lsof +L1`；`lsof | grep deleted` | `> /proc/PID/fd/FD` 清空或重启进程 |
| `df` 有空间但写文件报 `No space left` | inode 耗尽 | `df -i` | 定位并删除大量小文件 |
| swap 启用报 `insecure permissions` | swap 文件权限过松 | `ls -l swap文件` | `chmod 600 swap文件` 后重新 `swapon` |
| `badblocks` 检测极慢 | 整盘只读扫描，机械盘耗时以小时计 | 看进度输出 | 加 `-s` 观察进度；或先 `smartctl -a` 看重映射扇区数 |
| `dd` 克隆后目标盘无法启动 | 只克隆了数据区没克隆 MBR，或盘容量不一致 | `lsblk` 对比容量 | `dd` 整盘克隆并确认容量；引导问题用 `bs=512 count=1` 补 MBR |

## 自测题

1. LVM 的 PV、VG、LV、PE 分别是什么？它们之间的关系是怎样的？

> **答案：** PV 是被 LVM 标记过的物理分区或整盘；VG 是由一个或多个 PV 组成的存储池；PE 是 VG 内部固定大小的分配单元（默认 4MiB）；LV 由若干个 PE 拼成，是最终格式化与挂载的逻辑设备。关系是：PV 组成 VG，VG 切成 PE，PE 拼成 LV，由内核 device-mapper 实现映射，所以 LV 可以跨盘、物理位置不必连续。

2. 已经 `lvextend -L +5G /dev/vg0/lv01`，为什么 `df -h` 看不到容量变化？

> **答案：** `lvextend` 只扩大了逻辑卷本身，文件系统不知道自己变大了，必须再扩展文件系统：xfs 执行 `xfs_growfs /挂载点`，ext4 执行 `resize2fs /dev/vg0/lv01`。两步都做完成才算扩容结束。

3. `du` 显示删除了大文件，`df` 空间却没有释放，怎么排查和处理？

> **答案：** 文件被删除但仍有进程打开其文件描述符，内核不会释放 block。用 `lsof +L1` 或 `lsof | grep deleted` 找到占用进程，处理方式：① 通知进程重新打开文件（如 nginx 发送 USR1 信号、logrotate）；② 直接清空 `> /proc/PID/fd/FD号` 立即释放空间；③ 重启服务。

4. swap 的软限制和硬限制是什么意思？xfs 的配额命令与 ext4 有什么不同？

> **答案：** 题目应为配额概念：软限制是警告阈值，超过后在宽限期内仍可继续写入；硬限制是绝对上限，达到即禁止写入。xfs 不使用 quotacheck / quotaon 系列命令，而是用 `xfs_quota -x -c 'limit -u bsoft=... bhard=... 用户'` 管理，挂载参数用 `uquota` / `gquota`。

5. `dd if=/dev/sda of=/dev/sdb bs=64M` 这条命令在做什么？执行前最需要注意什么？

> **答案：** 把 /dev/sda 整盘按 64MiB 块大小克隆到 /dev/sdb。注意：① 目标盘容量必须不小于源盘；② if 与 of 绝对不能写反，写反会把备份盘的内容覆盖到系统盘，造成不可逆数据灾难；③ 建议加 `conv=fsync status=progress` 保证数据落盘并观察进度；执行前先用 `lsblk` 核对设备名。

6. 如何快速区分一次"磁盘满"是 block 耗尽还是 inode 耗尽？

> **答案：** 同时看 `df -h` 与 `df -i`：block 耗尽时 `df -h` 接近 100% 而 inode 正常，文件少而大，`du` 能定位大目录；inode 耗尽时 `df -i` 接近 100% 而 `df -h` 剩余充足，海量小文件堆积，典型如邮件队列、session 目录、定时任务未重定向输出的落盘文件。两者报错相同（`No space left on device`），处理方向完全不同。

7. /data01 要在线扩容，VG 里已经没有空闲空间了，完整步骤是什么？

> **答案：** ① 新分区或新盘做 PV：`pvcreate /dev/sdc1`；② 加入卷组：`vgextend vg0 /dev/sdc1`；③ 扩 LV：`lvextend -L +50G /dev/vg0/lv01`；④ 扩文件系统：xfs 用 `xfs_growfs /data01`，ext4 用 `resize2fs /dev/vg0/lv01`。全程在线，业务无感知。

## 小结

1. 分区工具按容量选：小于 2T 用 `fdisk`（`n` 新建、`p` 查看、`d` 删除、`t` 改类型、`w` 保存），大于 2T 用 `parted`（`mklabel gpt` + `mkpart`）。
2. 一块盘最多 4 个主分区；要更多分区就做成"3 主 + 1 扩展"，再在扩展分区里建逻辑分区，编号从 5 开始。分区后执行 `partprobe /dev/sdX` 让内核重新加载分区表。
3. 格式化即创建文件系统：CentOS 6 常用 ext3 / ext4，CentOS 7 推荐 xfs（格式化与存储效率更高）；命令是 `mkfs.xfs /dev/sdb1` 或 `mkfs -t xfs /dev/sdb1`。
4. 开机自动挂载两种方式：`/etc/rc.local`（要先给 `/etc/rc.d/rc.local` 加执行权限）和 `/etc/fstab`（六列：设备、挂载点、文件系统、参数、是否备份、是否检查）。生产环境推荐 fstab，rc.local 只做一次性初始化。
5. 报 `No space left on device` 时先区分是 block 满（`df -h`，删大文件，用 `find -size` / `du -sh` 定位）还是 inode 满（`df -i`，删大量小文件）；删了文件不释放空间用 `lsof +L1` 找占用进程。
6. 临时扩容 swap 三步：`dd` 造文件 → `mkswap` 格式化 → `swapon` 挂载（`swapoff` 卸载，用 `free -h` 验证），适合 Java 程序临时吃内存的场景；正规做法是独立分区（类型 82）并写入 fstab。
7. LVM 四层结构 PV → VG → LV（PE 为分配单元），优势是弹性容量、跨盘整合与快照；扩容顺序是 `lvextend` + `xfs_growfs` / `resize2fs`，缩减仅 ext4 支持且必须先缩文件系统。
8. LVM 快照基于写时复制（COW），创建时几乎不占空间，用于备份一致性与快速回滚；快照满会自动失效，用完立即删。
9. 磁盘配额 quota 通过软限制（警告 + 宽限期）与硬限制（绝对上限）约束用户用量，ext4 用 quotacheck / quotaon / edquota / setquota / repquota 系列，xfs 用 `xfs_quota`。
10. 性能观测用 `iostat -x`（设备级）、`iotop`（进程级）、`sar`（历史回溯）；`dd` 用于克隆、备份 MBR 与制造测试文件（执行前务必核对 if / of 设备名），坏块用 `badblocks` 检测并交文件系统标记。
11. ext4 通用、支持在线缩减；xfs 高并发强、只能扩不能缩（规划时留余量）。LVM 白话记法：PV 凑水池、LV 接水管；磁盘满先分清 block 满还是 inode 满，删了不释放找 `lsof +L1`。
